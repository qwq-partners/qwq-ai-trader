# Codex·Claude 공통 작업 배정 (2026-09-20)

사용자가 승인한 전역 정책 ID는 `ai-routing-v1-2026-09-20`이다. 이 문서는 프로젝트 적용 요약이며 투자 판단 에이전트의 모델/전략 설정을 바꾸지 않는다.

## 적용 위치와 확인 범위

현재 호스트의 ubuntu 사용자에게 다음 파일로 설치했다.

- 정본: `/home/ubuntu/.config/ai-agents/model-routing.md`
- Codex 지침: `/home/ubuntu/.codex/AGENTS.md`
- Claude 지침: `/home/ubuntu/.claude/CLAUDE.md`
- 설치 검증: `/home/ubuntu/.config/ai-agents/verification-2026-09-20.md`

Codex 설정은 `[agents]`의 기본 하위 모델 Terra, effort medium, native 동시 작업자3만 추가했다. 기존 부모 모델·권한·MCP·플러그인 설정은 비교 검증 후 보존했다. 새 Codex 세션의 strict config 검사와 지침 입력 확인, 새 Claude 세션의 실제 `claude-opus-5` 응답에서 정책 ID·작업자 한도·Fable 제외·배포 권한 없음을 확인했다. 전체 행동 준수나 OS 격리를 증명하는 시험은 아니다.

다른 사용자/호스트는 별도 설치가 필요하며 기존 실행 세션은 자동 재시작하지 않는다. Claude에서 user 설정 출처를 제외하거나 safe/bare로 실행하면 전역 지침이 생략될 수 있어 작업에 필요한 규칙을 프롬프트에 명시한다. 지침을 읽히려고 안전 기능을 해제하지 않는다.

정확한 호출 모델은 정본과 현재 tool allowlist를 확인한다. 현재 확인한 Claude ID는 `claude-opus-5`다. 요청 effort와 실제 유효 effort를 혼동하지 않는다. 모델 메타데이터가 없으면 실제 ID 미검증으로 보고한다. Fable 요청은 Opus fallback이 관측되어 자동 배정하지 않는다. Sonnet/Haiku도 이 환경의 실모델 확인 전 자동 배정하지 않는다. max/ultra는 기본값이 아니며 단순 명령 실행에는 모델을 추가하지 않는다.

## Plan → Do → See

1. Plan: 부모가 위험도·base SHA·파일 소유권·인터페이스·금지 행동·인수 시험·시간/사용량 한도를 고정한다. 진행 중 작업/PR을 확인하여 중복 구현을 피한다.
2. Do: 독립 작업만 동일 base의 격리 worktree에서 병렬 실행한다. 한 파일 한 writer, 공통 인터페이스 변경은 순서대로 진행한다. native와 외부 Claude를 합해 부모 외 작업자 최대3명이며 실제 런타임 한도가 더 낮으면 그 한도를 지킨다. 하위 작업자의 재위임은 금지한다.
3. See: 작성자와 분리한 리뷰어가 코드·재현·검증 범위를 확인한다. 중요한 변경은 다른 공급자를 우선하되 합의 자체를 정확성 증거로 보지 않는다. 부모만 검토 후 통합하며 실패한 시험과 미실행 범위를 숨기지 않는다.

외부 Claude는 도구를 끄고 비밀정보를 제거한 source를 전달하는 읽기 전용 리뷰부터 사용한다. 도구 허용 구현은 검증된 개발 sandbox가 있을 때만 한다. worktree만으로 비밀정보 접근을 차단할 수 없다. 인증/과금/모델 불일치/안전 거절/소유권 충돌은 해당 작업을 멈추고 진단하며, 우회나 조용한 모델 강등을 하지 않는다. 필수 교차 검증 불가 시 중요한 통합·승격은 별도 사용자 판단 전 차단한다.

현재 요청의 권한을 넘는 주문·운영 SSH·배포·재시작·live 설정 변경은 이 정책으로 허용되지 않는다. 엔진의 KIS 주문/잔고 및 Toss 관측 전용 경계와 기존 위험 한도는 그대로다.

## 외부 Opus 리뷰 실행·진단

360초 timeout을 모델 장애로 간주해 대체하는 대신, 짧은 대조와 원 입력의 계측 재현으로 원인을 분리한다. 09-20 실제 원 입력은 Opus/xhigh에서692.32초에 완료됐다. 따라서 중요한 장문 리뷰를 무조건6분에 끊지 않는다. 동시에 무제한 대기는 허용하지 않으며 명시한 전체 상한은 진행 이벤트로 연장하지 않는다. 근거와 검증 상태는 [실행기 진단 보고서](../reviews/opus-review-runner-2026-09-20.md)를 따른다.

공용 실행기 `scripts/dev/claude_review.py`는 **부모가 사전에 확인·비식별화한 UTF-8 stdin만** 받아 도구 없는 Opus5/xhigh 리뷰를 실행한다. 저장소·지침·계좌·로그·`.env`를 자동 수집하지 않으며, 입력을 몰래 마스킹하거나 변경하지도 않는다. 민감 자료를 제외하고 원 입력/후보 파일 해시와 범위를 고정하는 책임은 호출자에게 있다. global policy와 적용 계약도 safe-mode 입력에 명시한다.

```bash
python3 scripts/dev/claude_review.py --claude-bin /usr/bin/claude < sanitized-review.txt
```

- 시작 대기120초, 모델 진행 정체180초, 전체900초가 기본이며 명시 옵션으로 조정한다. 이 수치는 모든 리뷰의 완료 보장이 아니다. 작업을 분할할 때도 변경부·관련 호출자·시험의 검토 범위와 누락을 기록한다.
- 진행/종료 메타데이터의 입력 해시·전송 바이트·실제 모델·최종 result·child rc를 확인한다. 요청 effort를 실제 유효 effort로 주장하지 않고, 비용 미관측은0이 아닌 unknown이다. 중간 thinking-token 추정은 최종 과금 token과 다르다.
- timeout/프로토콜 오류/모델 불일치/도구 사용/미완료는 nonzero다. 성공 result와 exit0도 **실행 완료**일 뿐 `APPROVE_THIS_SLICE` 판정이나 main/운영 승인과는 다르다. 부모가 코드 지적을 재현·판정하고 필요한 수정·재리뷰를 진행한다.
- 인증·Claude CLI 전역 설정·브로커 설정을 바꾸거나 모델을 조용히 낮추지 않는다. 실패한 요청의 표면적 반복 대신 진단 기록을 남긴다.
- 초기화/실행 중 SIGINT·SIGTERM과 관측된 프로토콜 예외의 소유 자식 정리를 회귀 시험한다. SIGKILL·모든 순간의 신호 경합·OS sandbox까지 보장하는 도구는 아니다. 완성된 입력 파일과 정상 출력 소비자를 사용하며, 실행기와 리뷰 대상의 검증 범위를 따로 기록한다.
