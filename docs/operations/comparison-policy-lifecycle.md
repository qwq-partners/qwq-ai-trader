# 공유 월 원장의 비교 실험 정책 수명

비교 정책을 새로 등록하더라도 기존 실험 기록과 공유 월 예산은 유지한다. 새 정책 등록은 실호출·운영 worker 활성화·매수 재개를 승인하는 기능이 아니다.

## 불변 기준과 추가 등록

기존 `comparison_policy(id=1)`의 정책 JSON과 `identity_version`를 전역 기준(anchor)으로 보존한다. 새 정책은 버전과 기준 지문을 검사하는 별도 등록부에 승인자·승인 참조와 함께 추가한다. 일반 `ComparisonCallGuard` 생성으로 미등록 정책을 자동 수락하지 않는다.

동일 실험 ID에 다른 날짜·출력 상한·금액·모델·승인 참조를 덮어쓸 수 없다. 이전 실험은 기간이 끝나도 삭제하지 않으며, 과거 완료 응답·미정산 시도·영수증 조회와 재전송 금지 계약을 유지한다. 지원하지 않는 버전, 불완전한 구조, 정책 지문 불일치는 복구를 추정하지 않고 거절한다.

기존 requests·attempts·pairs의 요청/결과/manifest JSON과 ID·시각·토큰은 재작성하지 않는다. 실험 구분은 기존 JSON 안에 고정된 정책 문자열을 사용한다. 정책 등록의 실패는 트랜잭션을 롤백하며 월 설정·활성화 기준선·기존 예약과 대사를 변경하지 않는다.

## 예산과 횟수

| 범위 | 적용 기준 |
|---|---|
| 전체 비교의 일 시도/쌍 | 기존 anchor의 한도, 다른 실험도 함께 계산 |
| 개별 실험의 일 시도/쌍 | 해당 실험의 별도 한도도 함께 적용 |
| 실험 비용 | 같은 실험 ID의 전체 기간 예약/정산 합, 월 전환으로 초기화하지 않음 |
| 공유 월 비용 | 기존 MonthlyBudgetLedger와 동일 원장·예산·정책·불명 비용 처리 |

전체 한도와 실험 한도는 같은 입장 트랜잭션에서 검사한다. 다른 ID를 등록한다고 전체 한도가 새로 생기지 않는다. API는 기존 가드만 월 예약/정산을 소유하고 구독 전송은 일 슬롯만 소비한다. `day_attempts`/읽기 전용 일별 보고는 계속 전체 시도를 보여준다.

## Bear API 400/800 진단

[진단 계약](bear-api-cap-diagnostic.md)의 조건을 유지한다. `prepare`/`check-ledger`는 DB를 변경하지 않는다. 등록 가능이라는 사전점검 결과는 당일 잔여 횟수·비용·모델 응답 완료를 보장하지 않는다.

승인된 `run`은 새 소스 SHA·입력·준비 지문·제어·시간 창을 확인하고 디렉터리 소비 표식과 원장/실험 ID별 소비 표식을 확보한 뒤에만 정책 등록과 가드/전송 생성으로 진행한다. 실패하더라도 두 표식을 지워 재시도하지 않는다. 정책 등록·클라이언트 생성 전후에도 남은 창을 확인한다.

11/4에는 기존 실험이 전역 일 한도4를 모두 사용했다. 400/800 새 진단의 승인과 정책 등록이 그날 한도를 늘리지는 않는다. 다음 KST 날짜의 새 고정 창과 검증된 소스로 진행해야 한다. 별도 월 DB·기존 정책 삭제·과거 승인 재사용·기간 자동 연장으로 우회하지 않는다.

구현·독립 리뷰·WSL/CI·실호출의 실제 완료 상태는 [실행 원장](execution-roadmap.md#e04-comparison-policy-lifecycle-20261104)을 따른다. 합성 검사 통과는 과거 거래 성과나 모델 우위를 입증하지 않는다.
