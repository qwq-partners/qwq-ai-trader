실행 순서는 **고정 입력/현재 운영 확인 → 시도 영수증·백업 → 새 release/입력/보존 스냅샷 설치 → 공용 토스 설정 교체·정적 검증 → 소비된 drop-in 보관/제거 → daemon-reload·기존 PID 확인 → 보존 타이머 → 활성화 타이머**다. 봇을 배포하거나 지금 재시작하는 경로는 없다. 실제 활성화 때는 검증된 실행기가 봇을 한 번 재시작한다.

설치 준비 스크립트는 `scripts/ops/entry_capture_prepare_20261007.py`다. 검토된 사본을 저장소 밖 루트 전용 `/var/lib/qwq-entry-capture/install-20261007/`에서 실행한다. `--check`는 비변경 검사, `--apply`는 한 번의 설치 시도다. 최초 설치 전용 토스 `install.py`는 사용하지 않는다. `/var/backups/qwq-entry-capture-20261007/`가 있으면 재시도하지 않는다.

설정 게시 중 검증/동기화 실패는 교체한 공용 파일을 복구한다. 그 이후 단계가 실패하면 새 타이머 둘을 해제하고 부분 설치와 영수증을 보존한다. **모든 파일을 자동으로 원상 복구하는 설치기는 아니다.** `failed.json`의 상태와 백업을 먼저 조사하고, 실패한 설치를 다시 실행하거나 영수증을 지워 우회하지 않는다.

10월2일·6일 보존 서비스는 각각 당시 설정/launcher/retention 사본 다섯 개를 읽기 전용으로 매핑한다. 새 공용 설정과 무관하게 옛 cohort를 확인하며 실제 보존 작업을 앞당겨 실행하지 않는다. 토큰·시작/발급/송신 안전 기록과 과거 원본은 교체 대상이 아니다.
