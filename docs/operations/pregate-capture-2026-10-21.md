## PLAN — 무엇을 알아내려는가

목적은 엔진의 후보 선정과 진입 시점을 개선할 자료를 확보하는 것이다.
10월 20일 첫 스캔은 후보 21개 모두 시장 방어에 막혔고, 상위 5개 호가 쌍은
있었으나 엄격한 장 상태 조건을 충족한 비교는 0이었다. 그 결과를 변경하지 않는다.
새 관측에서는 기존 판독을 그대로 보존하면서, 체결 채널 수신 뒤 첫 호가와
900초 뒤 호가의 변화를 별도로 확인한다.

관측 전 고정하는 보조 정책은 `pregate-observed-regular-flow-v1`이다.
준비 5초·상태 최대 나이 5초·900초 보유 시점·종료 호가 지연 5초를 유지한다.
10월 20일 자료에 정책을 사후 삽입하거나 결과에 맞춰 준비 시간을 늘리지 않는다.
VI 상태는 `unknown`, 체결 가능성은 미평가, 순수익·계좌 수익은 `null`이다.
호가 변화에는 스프레드가 반영되지만 수수료·세금·슬리피지 및 체결 여부는 반영되지 않는다.

## DO — 구현과 실제 설치의 경계

- 새 고정 날짜 설치기는 10월 20일 설치기를 수정하지 않는다.
- 이전 자료는 정확히 소비된 `20261020-pregate-v1`만 인정한다.
  once·시작 영수증·활성화 상태·기존 drop-in의 경로와 내용을 검증한다.
  기존 원장·study·영수증·판독 결과는 원래 위치에 남긴다.
- 새 입력과 설정은 새 경로에만 생성한다. 기존 타이머를 정지·비활성화하고,
  파일 식별자와 바이트를 재검사한 뒤 소비된 drop-in만 제거한다.
  실패 시 새 타이머가 비활성·정지 상태인지 확인하고 소비된 옛 타이머를 재등록하지 않는다.
- 활성화는 이전 타이머/서비스의 정지를 두 번 확인한다. 재시작 요청 뒤 실패하면
  추가 재시작으로 자동 복구하지 않는다.
- 이번 변경으로 거래 규칙, 매수 중지, 모델 배분, 월 USD100 예산은 바뀌지 않는다.

현재 수집 런타임은 새 최상위 정책을 수용한다. 그러나 설치기는 활성화 실행기 바이트가
**운영 체크아웃의 소스 지문과 같아야 한다**고 검사한다. 따라서 공유 실행기에 새 날짜를
추가한 이 변경은 기존 절차상 **검증된 코드 SHA 운영 반영 → 새 PID·소스·설정 지문 고정
→ 설치 검사 → 예약 설치** 순서를 따라야 한다. 오프라인 판독만 바뀌었다고 운영 반영
단계를 생략하거나 실행기 지문 검사를 제거하지 않는다.

설치 때의 `source_version_ref`는 실제 운영 SHA이고, 판독기는 별도 고정 소스 지문을 쓴다.
개발 브랜치의 SHA나 이전 관측의 PID를 설치 입력에 대입하지 않는다.
설치 후 봉인 전 일반 배포를 하면 고정 조건이 깨지므로 해당 구간에 추가 배포를 계획하지 않는다.

## 판독 준비

새 manifest 버전은 `deterministic-observed-flow-readout-v1`이다.
기존 `legacy`와 `pregate` 버전의 동작을 유지한다.
새 버전은 `report_pregate_observed_regular_flow.py`만 실행하며, 결과 안에
기존 엄격한 판독 `strict_report`를 함께 보존한다.

고정할 판독 시간창은 **10월 21일 09:55~10:30 KST**다. 자동 실행 예약은 별도이며
이 문서만으로 등록되지 않는다. 시간창을 놓치면 기존 manifest·시도 영수증을 덮어쓰지 않고,
새 판독 시간과 새 출력 경로를 가진 별도 manifest를 만든다.

```bash
python scripts/ops/run_capture_readout.py --source-fingerprint --profile observed-flow
python scripts/ops/run_capture_readout.py --manifest <고정-manifest.json> --check
python scripts/ops/run_capture_readout.py --manifest <고정-manifest.json>
```

`--check`는 미래 원장 부재를 허용하는 비소비 검사다. 실제 실행은 study·원장의 제한된
사본과 소스 지문을 검증하고, 원장 미봉인·불완전·드롭·정책 누락이면 차단 결과를 남긴다.
시도는 한 번만 소비하며 자동 재시도하지 않는다. 완료 표시는 진단 실행의 완료다.
