# 주문 귀속 배포·v5 관측 통합 검토

## PLAN

사용자의 “완료되면 배포까지” 지시에 따라 [청산·선정 입력 수정](exit-selection-correctness-2026-10-18.md),
[수급 근거 수정](supply-evidence-correctness-2026-10-18.md),
[판단→주문→체결 귀속](order-attribution-2026-10-18.md)을 운영에 적용한다.
목적은 좋은 종목과 진입 시점을 비용 후 결과에 연결할 수 있는 근거를 만드는 것이다.
이 배포 자체가 순수익이나 매수 재개 근거는 아니다.

기존 원장은 새 귀속 필드를 거부하므로, 과거 동작에 읽기 호환성만 더한 복구 버전을
실제 직전 운영 버전으로 먼저 둔다. 이후 최종 기능을 기존 배포기로 적용하면 실패 시
그 호환 버전으로 자동 복구한다. 매수 중지·월USD100·금액 미확인 로그 후 계속 정책,
수동 진화 설정, 과거 원장과 관측 파일을 보존한다.

## DO

- 호환 reader는 승인된 #219의 검증기/원장 파일과 바이트가 같다. 기존 8필드 기록기는
  그대로 둔다. 합성 forward 원장을 고정 자료로 추가해 shallow CI에서 읽기 전용 검증,
  대사·종료·재개·legacy 추가와 잘못된 형식 거부를 검증한다.
- 최종 기능에서는 같은 호환 지문과 합성 자료를 유지하면서, 기록기 시험의 기대값을
  명시적으로 새 9필드로 바꾼다. 복구 기준의 8필드 검증과 혼동하지 않는다.
- v5는 v4 이하 설치기 소스를 고정 해시로 재사용하며 과거332파일을 보존한다. 이전 네
  예약의 정지·미소비를 설치 경계와 활성화 영수증 생성 전/재시작 전에 확인한다.
- 새 study는 `selection-basis-v4`, 런타임 payload는 `kr-selection-basis-v3`이다.
  v5의 private adapter만 공통 제한을 과거 검증기에 투영하며 실제 파일·해시·런타임
  입력은 바꾸지 않는다. 과거 v1~v4의 허용 형식은 유지한다.
- 실제 once 입력→CapturePlan→관측 런타임→활성화 준비 판정과, 새 수급 근거가 포함된
  비어 있지 않은 원장의 네 판독 CLI 연결을 검증한다. 장 상태 결측과 순수익 미확정을 유지한다.

## 운영 적용과 남은 관측

개발/병합, 실제 배포, 예약 설치, 실제 수집·판독을 각각 구분해 기록한다.
예약 창은10월19일09:25 활성화,09:30~09:40 입장,10:00 종료이며 판독 시작 허용 창은
10:05~10:20이다. 자동 판독을 새로 예약하지 않으며 판독 입력 사전검사와 실수집 결과는 다르다.
실제 배포/기동/설치 영수증은 적용 후 이 절과 운영 정본에 추가한다.
