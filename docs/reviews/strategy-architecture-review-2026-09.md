## 2. 왜 못 벌었나 — 구조 원인 5가지

### 2-1. 회전이 엣지를 수수료로 환급 (critical)
보유 중앙값 1.1~1.9일, 45%가 1일 내 청산. 왕복 0.227%에서 1일 보유의 필요 엣지는 하루 0.23%+슬리피지 = 지수
일평균(0.05%)의 5배. stale 5일 ±2%, SEPA/VCP stale_high 3일 <3%, 익절 후 stale 5일, max_holding 10일 —
"스윙" 전략을 데이트레이딩으로 만드는 규칙 4종(`exit_manager.py` ExitConfig, `run_trader.py:552`).

### 2-2. 청산 사다리가 우측 꼬리를 절단 (critical)
TP1(+10%)은 10%만 팔지만 stage를 FIRST로 올려 **본전보호(net ≤ -0.5% 전량)·복합 MA5-0.5%/전일저가 전량·익절 후
stale**을 동시에 무장한다(`exit_manager.py:977-1135`). 실거래 분할 발동 55건 평균 +3.33%·최대 +12%, 전체 p90 +4.9%,
+15% 초과 1.4%. 해석적으로 +30% 추세를 잡아도 실현 +18.7~20.1%. 동일 진입에 대한 G2 백테스트(홀드아웃 n=217):
**엔진식 청산 -0.044R vs 채널 청산 +0.828R**. 이 구조의 손익분기 승률은 51.9%인데 돌파·추세 전략의 구조적 승률은
35~50% — 수학적으로 성립하기 어렵다. (2026-08-02 "트레일링 완화는 악화"는 사다리+복합청산이 유지된 국소 실험.)

### 2-3. 명목 사이징 → 위험이 손절폭에 종속, 3~4종목 집중 (major)
25~28% × 손절 4~8% = 건당 자본 위험 1.0~2.24%(ATR 큰 종목일수록 큼). 95% 투자 시 3.4~3.8종목이 상한이라
max_positions 8·섹터 제한은 유명무실. -5% 일일한도는 손절 2.5~5건이면 도달, -2.5%부터 사이징 반감 → 4/14(-8.42%),
6/22(매수 32회 차단) 사고. sepa 손실 건 원화가 이익 건의 1.6배인 것도 같은 원인.

### 2-4. 배분이 근거와 역상관 (major)
gap_and_go 35%(백테스터 미지원, 실거래 기대값 -0.41%/건, 문서 승률 64%는 중복집계) · core_holding 15%(실거래 PF 0.44~0.57,
6월 부검 최대 손실원) · vcp 10%(실거래 0건·백테스트 없음) · sepa 30%(백테·실거래 모두 기대값 ≈ 0). 8/2 배분 최적화는
이벤트 단위 통계·in-sample 백테스트에 기반.

### 2-5. 레짐 계층 4겹이 서로 다른 라벨로 후행 동작 (major)
배치 5d/20d, 일중 등락+VIX, LLM 08:10 분류(청산 파라미터 구동), 장중 급락 단계 + 변동성 타게팅 + KOFR. SEPA의 실효 허용
레짐은 bull뿐. 45% 변동성 약세장에서 전략을 끄는 것 자체는 옳으나(변동성 타게팅 검증: 꼬리만 2배 악화), 스위치가
후행·불일치·다중이라 회복 초입을 체계적으로 놓친다(4/8 -15.51%p 알파 손실 기록). 실거래에서 trending_bull 라벨 진입이
최악(PF 0.57) — 블로오프 국면이 bull로 라벨돼 고점 추격.

## 4. 코드 건전성 — 수익 리스크로서

- src 79,926줄/167파일 중 `kr_scheduler.py` 7,084줄(단일 클래스, 루프 31개, broad except 205개), `run_screening` 1,054줄(if 114).
- 테스트 1,454줄(1.8%), 76건 — **ExitManager·_sync_portfolio·calculate_position_size·cross_validator.validate·on_signal·킬스위치 테스트 0**.
  과거 사고 3건(4/20 코어 연쇄매도, 4/22 저널 67% 유실, 8/5 이중매도)이 정확히 이 봉합선.
- 최근 8건의 지배적 실패 유형은 **조용한 성능저하**(HTTP 500 하루 4,000건 14일 방치, 수확 shadow 이틀 정지, daily_bias 7/2 정지 미인지).
  `_supervised`는 죽은 루프만 잡고 "돌지만 아무것도 안 하는" 루프는 못 본다.
- 진화 게이트가 실거래 코드가 아닌 `scripts/backtest_strategies.py`(1,756줄 병렬 재구현, `src.strategies` import 0)로 검증 — parity 테스트 없음.
- 유지보수성 4/10. 투자 순서(위험 감소/시간): ExitManager+_sync_portfolio 특성화 테스트(~8h) → 하트비트 staleness 알림(~2h)
  → 재시작·킬스위치 드릴(~3h) → systemd MemoryMax(~0.5h) → 백테스트↔실거래 parity(~4h) → 비거래 루프 분리(~3h).

## 7. 증거의 약점 (독자가 알아야 할 것)
- DB(-139만) vs 저널(+224만) 불일치 — DB 정본, 저널은 이벤트 단위 상향 편향. sync류 31건의 exit_price 정확도 미확인.
- 벤치마크 KODEX200은 중소형주에 불리할 수 있음(4·5월 -20~-30pp) — 게이트 간 상대 비교는 벤치마크 선택에 둔감.
- n이 작다(t 무의미): 4월 흑자는 KOSPI +30.6% 베타와 분리 불가; G4 p=0.18; 규칙#11 n=10.
- 자산 변동 +139만 미설명(입출금 미기록 → TWR 계산 불가), 펩트론 DB 110주 vs KIS 120주, 272210 좀비 행 1건.
- 8/8 이후 매수 0건이라 position_ledger·TCA·팩터 스냅샷은 비어 있다 — 위 권고의 효과는 매수 재개 후 첫 30건(canary)에서 측정.
