## Plan — 무엇을 검증할 수 있는가

**신규 거래가 없으면 현재 버전의 신규 종목 선정·진입에 따른 실제 순수익은 입증할 수 없다.**
현금 부족은 계좌 자산 부재와 다르다. 기존 보유자산의 평가/실현 손익과 과거 실제 체결은
자료가 충분하면 분석할 수 있지만, 사용자 수동 보유나 이전 버전의 결과를 새 엔진에 귀속하지 않는다.
이것은 현금이 생기거나 코드가 배포되면 자동으로 해결되는 조건도 아니다. 실제 자본·거래 허용·
해당 버전의 식별 가능한 진입/체결/비용·충분한 표본이 필요하다. 자금 추가나 매수 재개를 요청하는 계획은 아니다.

| 지금 가능한 검증 | 한계 |
|---|---|
| 선정 원천·점수·탈락 사유·수수료/손익비 산식 | 좋은 후보의 실제 기대수익이나 승률은 아님 |
| 실제 LLM 호출의 완료/모델/지연/사용량·비용 | 모델 정확도·거래 순수익의 증거는 아님 |
| 기존 판단 후 호가/장 상태가 함께 있는 건의 가격 이동 | 조건부 가격 분석. 호가 수량은 체결/대기열/슬리피지의 보증이 아님 |
| 기존 보유와 과거 실제 체결의 계좌 손익 | A01 시작 NAV·외부 입출금·권리/비용 의미·전략 귀속 결측을 먼저 해결 |

현재 버전의 신규 거래 성과는 **미측정**으로 유지한다. 거래 없음으로 승률/순수익을 0으로 채우거나
전략 실패/성공으로 판정하지 않는다. 실제 발생한 API/운영비는 거래 부재와 무관하게 비용으로 기록한다.
모의투자·가상 현금·가상 체결·새 20일 관측은 시작하지 않는다.

참고로 [GIPS의 실제/이론 성과 구분](https://www.gipsstandards.org/standards/gips-standards-for-firms/gips-standards-handbook-for-firms/)
도 실제 자산의 성과와 모형/백테스트 성과를 구별한다. 이 원칙을 표시 기준으로 참고하며,
이 프로젝트의 GIPS 준수나 인증을 주장하는 것은 아니다.

## Do — 현금 때문에 도달하지 않는 경로

- 장중 스크리너는 후보를 기록한 뒤 `available_cash >= min_position_value`에서 막힌다
  (`src/schedulers/kr_scheduler.py`, `cash` gate). 이후 후보 quote/신호/LLM/order-ready는 보장되지 않는다.
- 배치 신호는 다른 경로다. 후보/손익비 통과와 앞단 조건을 만족하면 엔진의 LLM 검증에 도달한 뒤
  `G5_cash`에서 막힐 수 있다 (`src/core/batch_analyzer.py`, `src/core/engine.py`).
  따라서 현금이 없다고 모든 LLM 호출/기록이 없어지는 것도 아니다. 기록 큐에 넣은 사실과 파일 저장 완료를 구분한다.
- 최종 사이징은 예약 자금/예비금/정수 수량 제약을 추가로 적용한다. KIS BUY 킬스위치도 독립적으로 유지된다.
- `Portfolio.strategy_effective_daily_pnl`은 manual 당일 미실현 변동을 분리하는 측정이며,
  기준선 부재/귀속 변경은 `None`이다. 이 속성만으로 계좌 전체나 현재 전략의 순수익을 완성할 수 없다.

## Do — SEPA 통과 영역 재현

현재 파일의 유효 병합을 읽기 전용으로 확인했다. `sepa_trend.min_score=60`이며
`min_stop_pct`, `max_stop_pct`, `max_atr_pct`는 override가 없어 소스 기본 4/7/6을 사용한다.
이는 설정 파일 대조이며 실행 중인 객체를 덤프한 확인은 아니다.
`exit_manager.max_stop_pct=8`은 다른 소비자의 설정으로, SEPA 생성 시점의 상한 7을 대체하지 않는다.

```text
손절폭 s = max(4, min(7, 2 × ATR))
목표폭 t = max(2 × s, min(20, 3 × ATR))
비용 c = 매수가 1주 금액에서 계산한 매수 수수료 + 매도 수수료/세금 (각 원 단위 반올림)
게이트 RR = (목표가 - 진입가 - c) / (진입가 - 손절가 + c)
```

수수료는 저장소 `FeeCalculator`의 설정값을 썼다. 계좌의 실제 약정 수수료/부과 세액을 새로 확인한 것이 아니다.
비용률 근사는 0.2271054%이나 원 단위 반올림 때문에 가격별로 다르다.
진입가 100,000원의 산술 사례(실제 후보/가상 매매가 아닌 단위 계산)는 다음과 같다.

| ATR % | 손절 % | 목표 % | 비용 전 RR | 게이트 비용 후 RR | 판정 |
|---:|---:|---:|---:|---:|---|
| 2.0 | 4.0 | 8.0 | 2.0000 | 1.8389 | 차단 |
| 2.6 | 5.2 | 10.4 | 2.0000 | 1.8745 | 차단 |
| 3.5 | 7.0 | 14.0 | 2.0000 | 1.9058 | 차단 |
| 4.8 | 7.0 | 14.4 | 2.0571 | 1.9611 | 차단 |
| 4.9 | 7.0 | 14.7 | 2.1000 | 2.0026 | 통과 |
| 5.0 | 7.0 | 15.0 | 2.1429 | 2.0441 | 통과 |
| 6.0 | 7.0 | 18.0 | 2.5714 | 2.4593 | 통과 |

재현은 4개 가격(1천/1만/10만/30만원) × 9개 ATR의 36조합에서 실제 게이트를 호출했다.
비용 전 2R 구간은 양의 비용이 있으면 순2R을 충족하지 않는다. 상단 구간에서는
`ATR >= 14/3 + c/진입가×100`이 필요해 약 4.9~6%가 남는다. 경계는 가격/반올림에 의존한다.
예컨대 목표 +14.6%/손절 -7%는 1천원에서는 통과하지만 1만/10만원에서는 차단된다.

**결론:** 계산 오류로 단정하기보다는 목표 생성의 비용 전 2R과 입장의 비용 후 2R이 합쳐져
낮거나 중간 변동성 후보를 배제하는 구조가 확인됐다. 현재 코드에 따른 차단은 일관적이나,
이 변동성 선택이 전략 목적에 맞고 순수익에 유리하다는 증거는 없다.
오늘 `7후보 → 점수 통과1 → RR 차단1`의 정확한 진입가/ATR 정밀값은 이 분석에 확보하지 않았으므로
위 산술 사례를 그 실제 후보의 정확한 RR로 보고하지 않는다.

추가 한계 두 가지를 다음 비용 계약 검토에 넘긴다.

1. 게이트는 매도 비용도 진입가로 계산한다. `calculate_net_pnl`은 실제 목표/손절 매도가와 수량을 쓰므로
   원 단위 반올림과 매도 금액 차이에 따라 경계 판정이 달라질 수 있다. 게이트에는 슬리피지·API 비용도 없다.
2. 기존 게이트는 비용 조회 예외 때 0을 가정한다. 이번에는 이를 `unavailable_zero_assumed`로 드러내지만
   판정 정책은 유지한다. 이를 정상 비용 0이나 비용 검증 완료로 해석하면 안 된다.

**Do 예정:** `src/analytics/order_rr_comparison.py`의 순수 Decimal 대조 함수와 합성 단위 검사를
구현한다. 기존 엔진·스케줄러에 연결하지 않는다. 입력은 출처/가격 기준·계획 P/T/S·수량 q·
명시적 비용 설정/버전·원래 검사 산식/문턱/근거다. 미확인 문턱을2.0으로 채우지 않는다.
q=0은 미계획, q/가격 결측은 미평가, 비정상 입력·비용 실패는 각각 구분한다.

동일 입력에서 비용 전 RR, 기존1주 근사, 아래 수량별 가격형 RR을 나란히 계산한다.

```text
B = P × q
C = B + buy_fee(B)
reward = T × q − sell_fee(T × q) − C
risk   = C − (S × q − sell_fee(S × q))
RR = reward / risk
```

각 비용은 Decimal·유한·비음수를 확인하고 기존 원 단위 비용 반올림을 따른다. 가격에 이미
반영한 슬리피지를 중복 차감하지 않으며 귀속 규약 없는 LLM 비용을 임의 배분하지 않는다.
[기존 위험 사이징](../../src/utils/sizing.py)의 `(진입금액+매수비용)×net SL%`와는 다른 분모다.
비용 전 문턱과 비용 후 RR 비교는 정책 변경 가정이며 기존 검사 결과로 이름 붙이지 않는다.

**See 예정:** ①1주 근사/목표·손절별 매도비용 ②P1000/T1146/S930·q1/10/100 반올림
③가격 상승/손절 조정 스냅샷 ④문턱2.0 net·1.5 gross·1.3 gross 구분 ⑤문턱 출처 부재
⑥수량0/결측/음수/비정수·손절 역전/비유한 가격 ⑦비용 오류/정상0
⑧수량 합산/산술 분할의 반올림 차이를 검증한다. ⑧은 실제 부분체결을 가정하지 않는다.
독립 리뷰·관련/전체 검증 후 원장에 인수한다. 현금 없이 가능한 계산 검증이며 모의투자·
가상 체결·계좌 성과를 만들지 않는다. 라이브 연결은 RR 출처 보존과 실제 청산 정책 관계를
먼저 확정해야 한다. 구현/배포 상태 및 단일 NEXT는 원장이 정본이다.
