# Claude CLI 사용 검증 — D01 후속

2026-10-24 KST. 사용자 요청: Claude 사용 중 보이는 문제를 검증한다. 개발 CLI 호출과 결과 판정을 조사하며 엔진 모델·예산·운영 배포는 변경하지 않는다. 작업 상태 정본은 [실행 원장 D01](../operations/execution-roadmap.md#d01-사용-검증)이다.

## 결론

로그인 실패나 Opus 미가용으로 설명할 근거는 없다. 도구 없는 코드 검토에서 **실행하지 않은 도구 호출과 결과를 텍스트로 만드는 현상**을 재현했다. 기존 실행기의 `success=true`는 프로세스·terminal·모델 확인만 뜻했고, 검토 결과의 적합성은 별도였다. 앞선 위키 작업에서는 coordinator가 잘못된 응답을 거부했으므로 그 응답으로 병합 승인한 사실은 없다.

입력 검토만 하도록 별도 출력 계약을 추가한 두 실험은 유용한 판독 내용을 반환했다. 둘 다 JSON 바깥에 코드블록을 붙여 원래의 엄격한 형식 검사는 실패했다. 원본 영수증을 보존하고 **응답 전체를 감싼 단일 JSON 코드블록만** 제거한 별도 검사에서는 적합했다. 형식 적합과 사실·심각도의 정확성은 별개다. 작은 결함의 `P0` 분류가 과도한 사례도 있었다.

Claude는 제한된 자료의 독립 검토에 계속 활용할 수 있다. 종료코드0·`APPROVE`만으로 자동 통합하지 않으며, 실시간 엔진 API 대체와 도구 사용 개발 샌드박스의 검증 완료로 해석하지 않는다.

## Plan — 범위와 가설

- 기존 위키 리뷰의 성공·시간 초과·비정상 응답을 대조한다. 별도 Sol/high 분석자는 실행기·입력·결과를 읽기 전용으로 검토하고, coordinator만 실제 호출을 담당한다.
- 최대3회, 매회 `claude-opus-5`/high·180초 절대 제한·60초 시작 제한·90초 모델 진행 제한·CLI 표시 비용 $1.50 상한. 추론 텍스트는 저장하지 않고 진행 시각/종류만 기록한다. 운영/API 자격증명은 전달하지 않는다.
- A: 실패했던 stdin/CLI 옵션을 유지해 재현한다. B: 같은 stdin·인증·모델·effort·권한에 출력 계약만 추가한다. C: 같은 출력 계약으로 알려진 결함을 가진 작은 소스를 검사한다.
- 각 호출은 새 비공개 작업 폴더/새 세션이다. 기존 사용자 세션을 재개하지 않는다. 작업 폴더와 서비스 상태의 차이가 있으므로 엄밀한 무작위 A/B나 성능 추정으로 취급하지 않는다.

## Do — 확인한 환경과 과거 근거

- 현재 호스트 Claude Code **2.1.310**, `auth status`: loggedIn=true, authMethod=claude.ai, subscriptionType=max. 이메일·토큰은 출력/복사하지 않았다. 별도 컨테이너나 모든 Claude 실행 모드를 검증한 것은 아니다.
- `--safe-mode -p --model claude-opus-5 --effort high --tools "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' --no-session-persistence --permission-mode plan`을 유지했다. API 키 없이 기존 구독 인증을 사용하며 승인된 전역 라우팅 정책을 stdin에 명시했다.
- [공식 CLI 설명](https://code.claude.com/docs/en/cli-reference)에 따르면 safe mode는 사용자 확장을 생략하지만 인증·기본 도구·권한 설정은 유지한다. 따라서 별도로 도구/MCP를 비활성화했다. 권한을 풀거나 `--bare`로 인증을 바꾸지 않았다.
- [공식 프로그램 실행 문서](https://code.claude.com/docs/en/headless)는 종료 상태·스트리밍·구조화 출력을 지원하지만 모델의 판정 내용 자체를 보증하지 않는다. 이번에는 스트리밍을 유지하고 반환 텍스트를 외부에서 검사했다. `--json-schema`의 현재 옵션 조합 호환성을 실험한 것은 아니다.

A의 모델 이벤트 최대 간격은1.589초였으므로 멈춤이나 시간 초과가 비정상 최종 출력의 원인이었다고 볼 수 없다. B/C는 도구 실행을 꾸며내지 않았고 정적 검토의 한계를 밝혔다. 다만 작은 순수 함수의 하한 누락을 C가 P0로 분류한 것은 제시된 영향 근거에 비해 과도하다. 심각도·수정 필요성·부수 제안은 coordinator가 다시 판단한다.

진단 실행기의 결과 계약 검사9건, 단일 코드블록 처리/전후 문장·복수 코드블록·중복 JSON 키·명령 주장 거부10건을 오프라인 확인했다. 최초 검사는 기존 유효 보고서의 Markdown 제목을 허용하지 못하는 진단 코드 문제를 찾아 수정했다. 이19건은 비공개 진단 검사이며 제품 pytest 신규19건이 아니다. 기존 비정상 응답은 거부되고 유효한 수정 요구는 승인과 구분된다.

이번3회 CLI 표시 추정비 합계 **$0.428506**, 실제 구독 증분 청구액은 **null**이다. 과거 시간 초과 비용도 미확정이며0으로 정산하지 않는다. 엔진 USD100 원장에 임의 합산하지 않았다. 이 표본으로 p95·장기 오류율·다른 모델 대비 우열을 주장하지 않는다.

## 확정한 결함과 적용할 사용 규칙

1. **실행 완료와 리뷰 완료 분리:** 기존 비공개 실행기를 복사해 `success` 하나로 판정하지 않는다. `execution_success`, `review_valid`, `verdict`, coordinator의 최종 수락을 분리한다. 실제 모델·terminal·도구 경계 확인과 내용 확인은 모두 필요하다.
2. **정적 검토 역할 명시:** 도구 없는 호출에는 전달된 소스만 읽는다는 점, 실제 검사 미실행, 가짜 도구 호출/결과 금지, 문맥 부족을 표현할 수 있는 `INSUFFICIENT_EVIDENCE`를 출력 계약으로 명시한다. 이전 리뷰·소스·현재 지시를 구분한다. 이번 결과는 개선 단서이며 특정 프롬프트의 무오류 보장은 아니다.
3. **원본 보존과 제한된 형식 처리:** JSON 필드는 verdict/findings/limitations/executed_commands이며 마지막은 빈 배열이어야 한다. 순수 JSON 또는 응답 전체를 감싼 단일 JSON 코드블록만 처리하고 원본/처리 후 지문을 남긴다. 본문 중간에서 JSON을 임의 추출하거나 `eval`하지 않는다. 중복 키·추가 문장·가짜 실행 기록·P0/P1이 있는데 APPROVE인 결과는 거부한다. 이 schema도 모든 거짓 주장/우회 표현을 탐지하지는 못한다.
4. **유효한 REQUEST_CHANGES는 실행 실패와 구분:** 파싱·검토 완료로 기록하되 통합은 막는다. 유효한 APPROVE도 정확한 소스·실제 테스트·범위·심각도를 독립 확인한 뒤 해당 변경만 수락한다.
5. **시간 초과 진단:** 시작/모델 유휴/절대 제한을 구분한다. 진행 이벤트가 절대 제한을 늘리지는 않는다. 과제 크기·시간/사용량 상한을 먼저 정하고, 불완전하면 범위를 줄인 새 요청이나 승인된 대체 리뷰를 명시한다. 같은 요청의 무제한 재시도·권한 확대·모델 정체 은폐는 하지 않는다.

이 규칙은 [개발 운영 문서](../operations/local-development.md#claude-result-contract)에 반영한다. 저장소 공용 실행기·자동 승인 시스템을 새로 구현한 것은 아니다. 기존 private 실행기는 역사 근거로 남기며, 새 호출에 재사용할 때 위 계약을 적용하고 결과를 검증해야 한다.
