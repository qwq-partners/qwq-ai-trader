## CLI의 thinking 환경변수 의미

설치된 Claude Code **2.1.316**의 정적 요청 구성을 확인했다. `CLAUDE_CODE_DISABLE_THINKING`은 실제로 읽히므로 “지원하지 않아 무시된다”는 설명은 맞지 않는다. 이 값이 켜지면 명시적 thinking 설정을 생략한다. Opus 5.5 descriptor에는 `adaptive_thinking`과 `rejects_disabled_thinking`이 있고, 해당 모델은 생략된 설정도 thinking 활성으로 취급한다. 따라서 **이 환경변수만으로 Opus 5.5의 추론이 꺼진다고 볼 수 없다**.

공식 [Opus 5.5 migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide)는 thinking이 항상 활성이고 `max_tokens`에 추론과 최종 텍스트가 함께 포함된다고 설명한다. [thinking 제어 문서](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost)는 effort가 소프트 제어임을 설명한다. 확인일은 2026-11-04다. low/400이 “추론 없이 답변 400토큰”이라는 전제는 사용하지 않는다.

설치본에서 출력 상한400은 유효 값으로 받아들여지며 일반 요청 경로의 `max_tokens`에 전달된다. 이는 정적 코드 증거로서, 과거 실제 전송된 요청 본문 전체의 재구성이나 공급자 동작의 실측을 뜻하지 않는다.
