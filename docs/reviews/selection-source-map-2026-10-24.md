# 선정 입력 매핑과 수급 연속성 수정

작업 ID는 [실행 원장 E02](../operations/execution-roadmap.md#e02-입력-점검)다.
목적은 좋은 종목과 진입 시점을 골라 비용 후 순수익을 개선하는 것이다.
이번에는 기존 입력 경로를 대조하고 확인된 수급 가점 결함 하나를 고친다.
기준 소스는 `3663ded0`; 운영·10/26 고정 예약 변경과 수익성 판정은 범위 밖이다.

## Plan — 자료가 늘어나는 것과 정보가 늘어나는 것을 구분

장중 `StockScreener`는 원천별 후보를 병합한 뒤 보정·필터·정규화를 한다.
배치 `SwingScreener`는 일봉 지표·전략별 평가·대기 신호 경로를 사용한다.
두 경로를 같은 스코어나 동일한 관측 모집단으로 합치지 않는다.

### 장중 후보와 보정 경로

| 입력 | 코드 경로 / 병합 가중치 | 선정에 반영되는 내용과 한계 |
|---|---|---|
| KIS 거래량·신고가 | `screen_volume_surge` 0.5, `screen_new_highs` 0.4 | 각각 후보 생성. 둘 다 가격·거래량에서 나온 정보라 독립성은 별도 검증 대상 |
| KIS 등락·프리마켓 갭 | `screen_fluctuation_rank` 0.3, `screen_premarket_gap` 0.5 | 같은 등락 순위 입력 계열. 갭 경로의 호출 조건은 코드상 로컬 hour 8~9이며 별도 야간 갭 원천이 아님 |
| KIS 기관·외국인 | `screen_institutional_buying` 0.3, `screen_foreign_buying` 0.4 | 순매수·거래대금 조건으로 후보를 만들지만 기본 점수는 `min(60 + change_pct * 3, 100)`. 수급량에 비례한 점수가 아니며 두 경로 모두 당일 등락 정보가 포함됨 |
| Naver 거래량·등락·파생 신고가 | `use_naver=False` 기본; 켜졌을 때만 병합 | 등락/신고가는 같은 입력 계열. 현행 장중 호출부는 기본값을 유지하므로 Naver까지 항상 후보를 공급한다고 설명하면 안 됨 |
| 뉴스·테마 | `theme_news` 0.6 또는 `llm_news` 0.5, 추가15점 | 두 분기는 `if/elif`. 실제 장중 호출부는 `theme_detector`를 전달하며 직접 뉴스 LLM 인자는 전달하지 않음. 테마 대장/후발·재료 단계 보정도 같은 테마 자료를 재사용 |
| 재무·모멘텀·RS·거래량·ATR | `_apply_valuation_bonus` 이후 순차 보정 | 재무 상위30, 모멘텀/ATR 각 단계의 상위20 등 조사 대상이 순위에 의존. 일봉을 공유하므로 보정 항 수가 독립 자료 수는 아님 |
| 섹터·DART·야간시장 | 섹터 분산/회전, `_apply_dart_catalyst`, overnight | 기존 후보의 가점/감점/제외. 원천 병합 항에 없다고 효과0으로 단정할 수 없음 |
| 수급 파생 보정 | 동시 순매수·SPDI·기관 매도·누적 참여·개인/야간 | 같은 수급 근거가 여러 단계에 들어감. 명단 미등재/결측과 관측된 비양성은 구분해야 함 |
| 최종 출현 가점·정규화 | 출현2회 +10, 3회 이상 +20; 조건부30~100 정규화 | 출현 횟수는 독립 확인 수가 아님. 한 원천을 제거하면 후보군·중간 상위N·최솟값/최댓값도 달라질 수 있음 |

코드 근거: [장중 스크리너](../../src/signals/screener/kr_screener.py)의 `screen_all`,
`merge_stock`, 각 원천/보정 메서드와 [실제 호출부](../../src/schedulers/kr_scheduler.py)의
`screen_all` 호출. [lineage_diagnostic](../../src/analytics/selection_source_status.py)은
알려진 파생 계열만 묶고 `independence_verified=False`를 유지한다.

RS 보정은 전달된 일봉 캐시에252행 이상을 요구하지만 앞선 모멘텀 단계는30일을 요청한다.
따라서 보정 함수의 존재를 실제 RS 가점 사용의 근거로 삼지 않는다. 장기 일봉을 추가 조회하는
변경은 비용·새 점수 영향 검토가 필요한 별도 제안이며 이번에는 적용하지 않는다.

### 배치 후보와 실행 입력

| 단계 | 현재 연결 | 비교할 때의 한계 |
|---|---|---|
| 유니버스 | 종목 master·KIS 등락/외국인/기관·당일 수급/VCP 캐시 합집합 | 종목코드로 합치면서 원천별 편입 경로를 보존하지 않음 |
| 기술·전략 후보 | FDR 일봉 → SEPA/RSI2 필터·VCP 탐지 → 종목별 중복 제거 | 기술·VCP는 같은 OHLCV의 파생. 일봉 실패·필터 제외 전체 행은 영속 모집단에 없음 |
| 점수 보강 | KIS 수급/재무·LCI·수급 추세·전문가·VCP·섹터 | 여러 기간의 수급과 이미 사용한 VCP가 다시 보정되므로 층 개수로 독립성을 계산하지 않음 |
| 신호·대기 | BatchAnalyzer의 전략/레짐 검사·LLM 재정렬 → PendingSignal | 최종 선택자의 지표 snapshot은 보존하지만 후속 스캔이 파일을 교체. 모든 거절자나 과거 신호의 불변 원장은 아님 |
| 실행 | quote·진입 조건 → 보존 snapshot을 가진 SignalEvent | 계산시각/조회시각과 공급자 bar·거래소 시각은 별개. snapshot 수정만으로 원천 최신성이 확정되지 않음 |

코드 근거: [SwingScreener](../../src/signals/screener/swing_screener.py)의
`run_full_scan`, `_build_universe`, 전략 필터·수급/오버레이 함수;
[BatchAnalyzer](../../src/core/batch_analyzer.py)의 `run_morning_scan`,
`pit_universe` 저장, PendingSignal 저장/실행 경로.
`pit_universe`에 저장하는 것도 필터 통과 후보이며 전체 최초 유니버스가 아니다.
기존 [10/21 지표 전달 수정](selection-input-followthrough-2026-10-21.md)은 보존한다.

배치 분석에서 **E02-F2 비활성 전략의 중복 제거 우선권**도 별도 발견했다.
`run_full_scan`은 초기 score0인 RSI2/SEPA를 RSI2 먼저 종목별로 중복 제거하고,
BatchAnalyzer는 그 뒤 비활성 RSI2를 제외한다. 같은 종목이 두 필터를 통과하면
SEPA 행이 먼저 버려질 수 있다. VCP 제외 집합도 이보다 앞서 두 목록으로 만든다.
이는 기존 코드의 조건부 경로이며 **실제 발생 빈도·경제적 영향과 합성 재현은 미확인**이다.
F1에 섞어 수정하지 않고 다음 하위 작업으로 실제 필터/설정 배선 재현부터 수행한다.
최소 수정 후보는 비활성 전략 후보를 중복 제거 전에 제외하는 것이며,
전략 점수/임계값과 기존 VCP 후단 복구 정책까지 변경하는 안은 아니다.

## Do — E02-F1: 연속 수급 가점의 끊김 처리

기존 `_record_supply_demand`는 참여 표시가 양성인 경우만 이력에 추가했다.
비양성/미확인 스캔과 후보 이탈이 기록되지 않아 아래 두 경우 모두 잘못 가점됐다.

| 합성 입력 순서 | 수정 전 | 수정 후 |
|---|---:|---:|
| 참여 → 공백 → 참여 → 공백 → 참여 | 연속3회로 +6점 | 마지막 연속1회, 가점0 |
| 참여3회 → 현재 참여 표시 없음 | 과거3회 +6점 유지 | 가점0 |
| 참여가 끊기지 않은3회 | +6점 | +6점 유지 |

현재 스캔에서 외국인 또는 기관 참여 표시가 있는 종목 집합을 만들고, 그 집합 밖의
기존 연속 이력만 제거한다. 스캔이 비면 이력도 끊는다. 현재 양성이 이어지는 다른 종목의
기록에는 영향을 주지 않는다. 3회 시작·회당2점·최대15점, 일자 초기화·36개 상한은 유지한다.

**공백은 순매도나 순매수0의 증거가 아니다.** 연속 양성의 근거가 끊겼으므로 가점을 주지
않는 것이며 SPDI/개인/야간의 기존 결측 정책이나 별도 감점은 변경하지 않는다.
이는 **호출된 스캔 횟수** 기준의 참여 표시 연속성이다. 장중 루프 외에
`daily_report.py`의 보고 폴백도 `screen_all`을 호출하므로 `수급누적N회`가 N×5분의
실시간 연속 순매수를 보장하지 않는다. 누적 단계에 전달된 후보 집합을 기준으로 하며,
그보다 앞선 DART 위험공시 차단도 후보 이탈에 해당한다. 공급자 캐시의 같은 응답을 반복 관측했을 때
새 순매수 사건이 발생했음을 증명하지 않으며, 실행되지 않은 구간·공급자 기준일의 최신성도
판정하지 않는다. 기존 통합 결과 캐시 폴백은 별도 계약으로 유지한다.

## 비교에 사용할 수 있는 자료와 다음 순서

[10/19 판독](../research/selection-readout-2026-10-19.md)의 반환41건 중 병합 항은
외국인38·갭3·등락1이었다. 이는 해당 두 스캔의 반환 집단이지 전체 원천 호출과 후속 보정의
기여도나 현재 버전의 분포가 아니다. 이미 한 동일 계열 보너스/단일 SPDI 산술 비교를
새 실험으로 재집계하지 않는다.

`SelectionBasisBuilder.finish`는 최종 반환 후보에 근거를 붙인다. 따라서 기존 자료만으로
내부에서 제외된 종목이 원천 제거 후 새로 올라오는 경우까지 복원할 수 없다. 원천의 호출/완료
시각·캐시 나이가 있어도 `source_as_of`가 없는 자료는 원천 기준일 확정으로 승격하지 않는다.

후속은 같은 입력의 최종 점수에서 기여 항을 빼는 방식이 아니라, 비교하려는 한 단계의
입력/후보 모집단·중간 순위·캐시/수급 근거 시각과 같은 청산/비용을 먼저 대조하는 것이다.
현재 가용 자료에서 가능한 부분과 결측을 E01에서 확정한다. **T03/T04→조건부 T05→T06→E01**의
순서를 유지하며 새 수집기·점수 완화·원천 가중치 변경·모의투자를 시작하지 않는다.
