## S1′ 독립 작업의 준비 범위

`gateway.py:151–165`의 `_bind`는 현재 `(symbol, side, strategy)` 캐시에서 intent를 재사용한다. `lifecycle.py:280–285`는 그 intent의 남은 목표 수량으로 새 attempt를 제한한다. 보호 에피소드마다 별도 intent를 넘기려는 S1′ 방향은 이 경계에 맞는다.

- 제품 소유 파일: `src/execution/safety/gateway.py` 하나. S1 writer의 `runtime.py`와 겹치지 않는다.
- 인터페이스: SELL이고 `event.metadata['protection_intent_id']`가 유효한 비어 있지 않은 문자열이면 그 ID를 request 생성 **전에** 사용. 해당 분기에서 `_intents` 읽기·쓰기 모두 0. BUY 및 비태그 SELL의 기존 분기는 보존.
- RED 대상: 태그 ID 그대로 binding, 미리 채운 캐시와 무관, 캐시 불변, attempt ID는 매번 신규, BUY 태그는 우회 권한 없음. 추가로 1차 익절 10주 뒤 손절 90주·EOD의 새 intent와 `pending_owners` 결합을 실제 owner fixture로 검증.
- 변이 후보: 태그 무시 / 보호 ID의 캐시 오염 / BUY에도 override 허용. 유효하지 않은 태그를 새 거부 사유로 바꾸는 것은 별도 계약 결정 없이 추가하지 않는다.
- S1′ 단독 GREEN은 생산자·설치 완료나 보호 매도 전 경로 인수가 아니다. S2~S4 배선 전에는 부품으로만 보고한다.
