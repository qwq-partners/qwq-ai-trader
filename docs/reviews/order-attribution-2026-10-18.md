# 후보·판단과 주문·증분 체결의 연결

> **후속 운영 적용 완료:** 호환 reader710af553 선행 후 최종ba29b903에 이 변경을 배포했다. [배포·v5 예약·판독 정본](../operations/selection-capture-2026-10-19.md#10월18일-주문-귀속-배포와-v5-교체). 아래 미배포·v4 유지·미병합 문구는 개발 당시 이력이며 수익성/실측의 남은 한계는 계속 유효하다.

## PLAN

목표는 어떤 후보와 판단이 실제 주문·체결로 이어졌는지 추정 없이 연결해,
진입 지연·부분체결·청산·비용 후 성과를 같은 근거로 비교하는 것이다.
이전 [수급 후속 계획](supply-evidence-correctness-2026-10-18.md#다음-계측-작업의-plandosee)의
상위 식별자 보존과 기존 오프라인 대사 보완을 진행한다.

기준 SHA는 PR #218의 `ed0439aa`다. 별도 feature 브랜치에서 주문 생성부,
실행 원장, 오프라인 대사를 나누어 작업한다. 기존 제출/취소 상태 전이와 체결 처리 흐름을
재작성하지 않는다. 운영 `a0bc9c94`, 설정·매수 중지·월100 예산·10월19일 고정 관측은 변경하지 않는다.

## DO

- `Order.attribution`은 후보·계획·신호·LLM 판단의 네 ID를 불변 값으로 보존한다.
  고정 버전과 허용한 결측 사유만 기록하며, 임의 메타데이터를 복사하지 않는다.
  ID가 없는 직접 주문이나 LLM 우회 경로도 정상 경로다. ID 존재는 판단 내용·저장 성공의 증명이 아니다.
- RiskManager는 실제 주문 객체를 만들 때 현재 SignalEvent에서 한 번 복사한다.
  후보 ID는 같은 신호 ID로 기록된 후보/신호 원문이 모두 있을 때만 복사한다.
  관측이 꺼졌거나 유실·충돌이 있으면 null이며, 종목/시각으로 ID를 새로 만들지 않는다.
  기존 emit 이벤트와 관측 스키마를 수정하지 않는다.
- 기존 실행 의도에 귀속 정보를 함께 commit한다. 각 증분 체결은 원래 주문 key 아래에
  있으므로 같은 정보를 Fill이나 매수/매도 요약마다 중복 저장하지 않는다.
- 오프라인 보고서는 주문일·계좌 범위·증권사 주문번호와 개별 `execution_id`를 함께 대조한다.
  수량/가격이 맞아도 실행 ID가 바뀌거나 중복이면 정확한 연결로 보지 않는다.
  원장에 기록된 미전송·거절·접수 불명·무체결 취소도 의도 분모에 남긴다.
  의도 기록 전 차단된 신호나 전체 후보 수까지 포함하는 분모는 아니다.
- 제공된 거래 행의 ID 일치와 실제 DB commit 증빙을 구분한다. 포트폴리오 메모리 반영과
  `handoff_returned`만으로 영속 거래 저장을 확정하지 않는다. 입력 파일 출처의 진실성은 별도 확인이다.

```mermaid
flowchart LR
    A[기록된 후보·신호 / 계획 / LLM 판단] --> B[Order의 불변 ID]
    B --> C[실행 의도 원장]
    C --> D[증권사 접수 ID]
    D --> E[각 누적 체결 증가분의 execution_id]
    E --> F[오프라인 거래 행의 정확한 ID 대사]
    F --> G[진입·체결·청산·비용 성과 평가의 입력]
```

## 적용 한계와 다음 순서

1. 새 코드는 과거 원장을 원형 그대로 읽는다. **새 귀속 행을 쓴 뒤에는 과거의 엄격한
   원장 reader를 가진 바이너리로 단순 롤백할 수 없다.** DB user_version 변경이나 과거 행
   자동 수정은 없으며, 배포 시 롤백 대상도 새/구 facts를 읽는 호환 reader를 갖춰야 한다.
   구체적인 적용 순서는 호환 읽기만 가능한 복구 버전을 먼저 확보하고 임시 원장의 새/구 행으로
   복귀 검증한 뒤 새 기록 기능을 배포하는 것이다. 이 작업에서는 그 운영 적용을 실행하지 않았다.
2. 후보 ID는 선택적 관측 범위 안에서만 제공된다. 과거 후보·주문을 소급 복원하지 않는다.
   직접 주문과 기존 시장가 폴백은 신호 출처가 없으면 명시적으로 미관측이다.
3. 내부 `execution_id`는 KIS 누적 조회의 증가분이며 거래소 고유 체결 ID/체결시각이 아니다.
   계획은 shadow 자료다. 보고서의 일치는 매수 재개·재생·자동 복구 승인으로 사용하지 않는다.
4. 기존10월19일 관측을 판독하고, 새 버전 실수집 전에는 소스와 입력을 다시 고정한다.
   독립 DB/증권사 원본 대사를 마친 후 동일 진입의 청산 재생과 비용 후 성과 비교로 이어간다.
