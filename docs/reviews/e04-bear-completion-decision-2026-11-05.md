# E04-BEAR-COMPLETION-DECISION — 제어 유지와 후속 순서

기준은 PR #338 병합 `4d0f2ad2d795b1d6a682d67a91819ff4819cdbb8`이며 PR HEAD `9841eb14`와 tree가 같다. 사용자는 다음 작업·문서 갱신·커밋/푸시·운영 배포를 승인했다. 추가 실호출과 기존 완료 검증 반복은 제외한다.

**결정: 모델·low effort·프롬프트·운영 CLI/API400·패널12/내부11.5/CLI5.75초를 유지한다.** 기존400 절단2건과800 timeout1건으로 API800 승격·시한 연장·모델 교체를 선택할 근거는 부족하다. 이 결정은 현행 설정의 충분성이나 Bear 완료율 개선을 뜻하지 않는다. 유효 독립 의견을 얻지 못하면 hold인 경계도 그대로다.

| 확인된 것 | 확정할 수 없는 것 |
|---|---|
| API400 두 응답의 HTTP200·max_tokens·known | 완료에 필요한 최소 토큰/시간, 추론·최종 답변 배분 |
| API800의 외부 timeout·unknown | 800 충분성, 지연 단계, 사용량·총비용 |
| 취소 첨부 네 상태의 합성 전달 | 과거800 응답 복원, 실제 완료율·경제성 개선 |

[직전 판독](e04-bear-completion-review-2026-11-05.md)의 근거를 재사용했다. 프롬프트는 이미 선두 판정과 짧은 시나리오를 요구하며, low 전송이나 시한 집행의 새로운 결함은 확인되지 않았다. CLI 시간을 늘리면 고정 내부 시한에서 API 잔여가 줄어든다. 별도 진단의 API5.75초 결과를 실제 fallback 잔여 시간의 성공률로 옮기지 않는다. 팀 심의의 다른 상한·시한 결과도 entry 결과로 합산하지 않는다.

새 `timeout_observation`은 실패 영수증의 보조 기록이다. 성공/의견/정산/다음 시도 판단에 사용하지 않고 과거 영수증도 다시 쓰지 않는다. unknown 비용은 공급자 사용량/청구 증빙이 있을 때만 기존 대사 절차로 처리하며 이번에 원장을 열거나 대사하지 않는다.

## 이번 배포가 하는 일

운영 `a399c297` 이후 누적 소스를 고정 SHA로 적용한다. 누적 변경은 journal 종료 실패 진단, 명시 승인 E04 실행기·API400/800 진단, 기존 기록을 보존하는 비교 정책 등록/소유권 검사, 안전한 취소 상태 전달이다. 의존성·운영 설정·스케줄러·정상 LLMManager/전송에는 변경이 없다.

worker OFF와 R1 비활성을 실제 적용 설정에서 확인해야 한다. `install_from_env`는 worker OFF면 반환하지만, ON인 다른 manifest에서는 raw-client 거절 전에 guard가 생성될 수 있으므로 무조건 부작용 없는 함수로 표현하지 않는다. 정상 운영의 기존 회계 쓰기와 이번 비교 실험의 실행/등록을 구분한다.

배포·복구·인수는 [WSL 정본 절차](../operations/lightsail-deployment.md)를 따른다. 과거 완료된 WSL/PR 검사는 재실행하지 않는다. 이후 새 경합 테스트 변경은 자체 WSL/PR/main CI를 거치며, 배포 스크립트의 필수 서버 전체 검증과 재시작150초 뒤 인수를 별도 배포 근거로 남긴다. 실제 상태·SHA/PID·보호 지문·독립 리뷰는 [원장](../operations/execution-roadmap.md#e04-completion-deploy-20261105)에 기록한다.

## 후속

배포 인수를 마친 뒤 E04를 위한 동일400/800 재실행이나 새 계측 과제를 자동으로 만들지 않는다. 본질 과제인 E02-RR/E01은 신규 매수용 현금·매수 중지라는 입력 전제가 유지되면 구조적 WAIT다. 사용자가 전제를 결정하고 구별 가능한 새 선정 snapshot·판단·양수 수량/비용 자료가 생길 때 선정→진입→청산→비용 순으로 판독한다. 매수 재개·가상자금·모의투자는 실행하지 않는다.

완료 개선을 별도 우선순위로 선택한다면 제어1개와 허용 지연/비용·성공 기준을 먼저 고정해야 한다. 현재 자료로 특정 변경을 정답으로 고르거나 추가 실호출을 예약하지 않는다. O02 기존 예약과 자연 보고는 유지하며 도래 영수증을 해당 작업 범위에서 확인한다.

독립 Sol6.1/high 정적 분석과 Astra/xhigh 누적 배포 검토를 사용했다(정본 Sol5.6 런타임 미제공 대체, 실제 모델/실효 effort metadata 미노출). 완료 제어 결정 자체에는 새 소스·테스트 수정이 없다. 병합 main CI에서 별도로 발생한 비교 정책 동시성 실패는 E04-COMPARISON-CONTENTION으로 조사·최소 수정한 뒤 배포한다. 운영 반영과 실제 완료율/순수익 실증을 구분한다.

## 운영 반영 결과

PR #339와 main 검증 후 `4117371c`를 WSL 정본으로 배포했다. 서버10,529검사와 보호48파일/설정 보존·서비스/브로커/복구는 확인했다. 다만 초기 KIS 한도 거절2건으로 엄격한 거절0 인수는 충족하지 못했다. 후속 기존 HTTP집계와 지적을 원장에 함께 남겼으며, 이 결과를 Bear 완료율·순수익 개선이나 전 항목 PASS로 표현하지 않는다. 추가 실호출·제어 변경 없이 배포를 유지한다.
