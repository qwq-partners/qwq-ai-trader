# Lightsail 안전 배포 설계

## 목표

로컬 WSL에서 명시적으로 승인한 `main` 커밋만 Lightsail 운영 서버에 배포한다. 배포 후 systemd 서비스와 HTTP 상태를 확인하며, 실패하면 직전 커밋으로 자동 복구한다.

## 범위와 안전 경계

- 운영 저장소: `/home/ubuntu/projects/qwq-ai-trader`
- 서비스: `qwq-ai-trader.service`
- 상태 확인: `http://127.0.0.1:8080/api/health`
- 배포 소스: `origin/main`의 정확한 SHA
- SSH 키와 `.env`는 로컬/서버에만 보관한다.
- 서버 작업 트리가 깨끗하지 않거나 동시 배포가 진행 중이면 중단한다.
- 실제 변경은 로컬 실행기의 `--deploy` 플래그가 있을 때만 허용한다.

## 흐름

1. 로컬 실행기가 `origin/main`을 갱신하고 대상 SHA를 확정한다.
2. SSH 연결과 서버 사전 조건을 확인한다.
3. 원격 실행기가 배포 잠금을 획득하고 기존 SHA를 기록한다.
4. 대상 SHA로 이동하고 Python 의존성 및 저장소 검증을 수행한다.
5. systemd 서비스를 재시작하고 상태 API가 성공할 때까지 제한 시간 동안 확인한다.
6. 실패하면 기존 SHA로 되돌린 뒤 의존성, 서비스, 상태 API를 다시 복구한다.

## 실패 처리

- 배포 전 실패: 운영 코드를 변경하지 않고 종료한다.
- 대상 적용 후 실패: 자동 롤백을 시도하고, 배포 실패 상태로 종료한다.
- 롤백 실패: 원래 오류와 롤백 오류를 모두 표시하고 즉시 수동 점검 대상으로 표시한다.

## 테스트 전략

임시 Git 저장소, 가짜 `sudo`/`curl`, 가짜 SSH를 사용해 실제 분기와 복구 동작을 검증한다. 운영 서버에는 테스트 단계에서 쓰기 작업을 하지 않는다.
