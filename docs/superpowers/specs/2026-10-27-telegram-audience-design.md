## 4. 설계 선택과 목표

문구만 짧게 만드는 방법은 기존 수신 대상 혼합과 여러 생성자의 중복을 남긴다. 각 보고서마다 개별 예외를 추가하면 기존 cron과 신규 보고에서 다시 누락될 수 있다. **두 수신 대상·메시지 종류를 명시하는 공통 발송 계약과, 각 대상의 전용 본문**을 채택하는 것이 사용자 요구에 맞다. 계산/수집 스케줄과 발송 스케줄은 분리한다.

수신 대상 분리는 사용자 지정 사항이다. 사용자는 추가 답변에서 **채널에 장중 핵심 변화1회를 추가**했다. 따라서 채널 장전·장중·장후3회, 개인 일일1회+주문·중요 장애 즉시 알림을 기준으로 설계한다. 구체적 시각·길이와 장중 변화 없음 처리 방식은 아래 coordinator 제안이며 운영 미적용이다.

| 구분 | 채널 — 한국 주식시장 | 개인 — 엔진 |
|---|---|---|
| 독자가 얻을 것 | 오늘 한국 시장에서 무엇이 달라졌고 어떤 조건을 볼지 | 엔진이 무엇을 했고 왜 했으며 내가 무엇을 조치해야 하는지 |
| 정기 빈도 | 거래일 장전·장중·장후3슬롯, 권장07:40/13:10/16:40 | 일일1회, 권장21:00. 주간 요약은 해당 날 일일 보고를 대체 |
| 기본 본문 | 핵심3줄 → 국내 지수·시장 폭·거래대금/수급 → 주도·약세 업종과 대표 종목 근거 → 한국에 관련 있는 해외 변화/일정 → 다음 확인 조건 |
| 개인 본문 | 해당 없음 | 조치 필요 → 운영/현금·매수 중지 → 후보·탈락 단계/변경 → 주문·체결/보유 위험 → 데이터·LLM 비용/오류 → 다음 확인 |
| 제외 | 계좌/현금·보유·킬스위치·주문·후보 내부점수·모델/버전/원장/실험 상태 | 일반 시장 장문/전문가별 의견 재방송 |
| 모바일 규격 | 원칙 텍스트1개, 약1,200~1,800자·25~35줄 상한 안에서 유용한 내용만. 핵심 표 대신 짧은 행 | 일일 요약도1개. 긴 원장/연구는 별도 저장하고 필요 링크/상태만 |
| 이미지 | 기본 추가 발송 없음. 판단에 도움이 되는 경우만 이미지1개를 별도 선택 | 기본 없음 |
| 미확인 자료 | 해석/순위에서 제외하고 영향이 있으면 자료 범위 한 줄. 동일 경고를 항목마다 반복하지 않음 | 원인·영향·복구 상태를 기록, 최초 발생/상태 변화/해소 시 알림 |

장중 슬롯은 장전 대비 지수·시장 폭·거래대금/수급·주도 업종의 **변화분**을 보여준다. 오전 미국시장 목록을 재방송하지 않는다. 유효한 새 입력/중요 변화가 없는 경우 독립 알림을 생략하고 기록에 사유를 남기는 것을 제안한다. 엔진의 안전 경보는 계속 개인에게 즉시 전달한다. 휴장일/주말 정기 시장 보고와 별도 주간 발송은 기본 중단 제안이며, 유효한 일정은 다음 정기 보고에 묶는다.

공통 발송 계약은 최소한 `audience`, `kind`, `report_date`, `source_snapshot_id`, `dedupe_key`를 받는다. 채널 formatter에 엔진/계좌 객체를 넘기지 않고 허용한 시장 입력만 전달한다. 개인 formatter에는 해당 권한의 엔진 요약만 전달한다. 잘못된 대상·누락된 설정은 반대 대상으로 폴백하지 않는다.

정기 요약은 날짜/종류/대상별 재시작 중복을 막되 `생성`, `발송 시도`, `API 수락`, `실패`, `접수 불명`을 구분한다. Telegram의 서버측 멱등성을 보장한다고 주장하지 않는다. 부분 전송/응답 불명 때 즉시 전체를 무한 재전송하지 않고 확인 가능한 결과와 제한된 재시도 정책을 기록한다. 사용자 수동 재조회는 자동 알림과 별도다.

긴급 주문/체결/접수 불명·매도 실패·계좌 대사 이상·중요 건강 상태·위험 전환·예산 정책 전환은 요약 대기나 일일 상한에 넣지 않는다. 연구 shadow/후보0/거래0/변화 없는 hold는 독립 알림을 만들지 않는다. 계산·감시·저장·예산 정책 자체는 발송 통합으로 끄지 않는다.

## 5. 기준일과 내용 신뢰성 보정

1. **원천 시각 보존:** v8 flat의 선택한 close와 같은 위치의 timestamp, nested의 선택한 가격에 해당하는 원천시각을 보존한다. 배열 길이 불일치·미래/비유한 시각·가격/시각 불일치에는 날짜를 만들지 않는다. `regularMarketTime`과 일봉 timestamp의 의미 차이도 보존한다.
2. **날짜를 분리:** 자료의 시장일/관측시각, 수신시각, 보고서 작성일은 다른 필드다. 미국 ET/KST·휴장·주말·조기 종료를 테스트하며 단순 전날 계산으로 거래일을 만들지 않는다. 기존 달력의 실제 범위와 동작을 구현 단계에서 검증한다.
3. **같은 기준의 사실만 비교:** 지수/ETF/종목의 실제 날짜를 각각 평가한다. 지수 날짜를 다른 그룹에 복사하지 않는다. 미상·혼재·오래된 값은 현재 시장 방향/업종 순위 근거로 사용하지 않는다. 확인 수치도 전체 시장 대표성/현재성까지 검증된 뜻은 아니다.
4. **한국 시장이 주어:** KOSPI/KOSDAQ, 한국 업종지수, 한국 상장 섹터 ETF, 미국 ETF를 명확히 표시한다. 종목2개의 상승으로 전체 업종 강세를 단정하거나 미국5일 약세를 한국 당일 약세로 바꾸지 않는다. 기간·구성·비교 대상이 다른 근거는 구분한다.
5. **결측과 정상0 분리:** KIS 빈 필드·비유한 값은 결측으로 보존한다. 명시적인0%는 보합으로 유지한다. `전일대비` 변화율과 `전일 관측 자료`를 구분하고 실제 원천일이 없으면 후자를 쓰지 않는다.
6. **내용 편집:** 사실 → 한국 시장에 대한 해석 → 확인할 조건을 분리한다. 출처 없는 원인·예측·확률은 만들지 않는다. 원자료 날짜 문제가 해결되지 않은 수치를 수십 개 나열하는 대신 유효한 국내 핵심 정보부터 보여준다. 국내 자료가 부족하면 엔진 보고로 채널을 채우지 않는다.

채널에 필요한 국내 지수·업종·수급의 기존 입력과 날짜가 실제로 확보되는지 먼저 대조한다. 확보되지 않는 항목은 새 수집/API 비용을 몰래 추가하지 않고 누락 범위로 기록한다. 보고용 기준일 수정이 기존 거래 점수에 영향을 주는 공유 provider를 건드릴 때는 아래2단계의 중요 리뷰와 consumer 회귀를 포함한다.

## 7. 인수 테스트와 검토 한계

- 발송 대역으로 `대상·종류·슬롯·분할 수`를 기록한다. 채널 본문에 엔진 전용 canary 값이 없어야 한다. 대상 누락·다른 대상 폴백·설정 누락·사진/문서도 검사한다.
- 정상/무거래/후보0/장중 후보 변화/변화 없는 hold/자료 장애·회복/주간 보고의 합성 날짜를 검증한다. 여러 기존 생성자가 호출돼도 정기 요약 횟수는 계약대로다.
- 주문·체결·접수 불명·손실 방어·매도 실패·중요 장애·예산 전환은 통합 정책을 우회해 지정 개인 대상에 즉시 도달한다.
- v7/v8 flat/nested·일자 누락·다른 일자·미래·장 마감 전후·미국 휴장·주말·시간대·빈 숫자/진짜0·불완전 시계 입력을 검사한다. 실제 공급자 스키마를 합성만으로 자격 확인했다고 주장하지 않는다.
- 부분 Telegram 성공/명시 실패/응답 불명/재시작에서 상태와 재시도가 구분되는지 검사한다. mock 성공은 실제 수신이나 최종 가독성 입증이 아니다.
- 독립 소스 감사2건: 요청 `gpt-5.6-sol`/high, 실제 모델·실효 effort metadata 미노출. coordinator가 소스와 기존 아카이브를 대조하고, 수신자 혼합을 즉시 계좌 유출 사고(P0)로 단정하는 표현은 채택하지 않았다. 현재 확인은 경로/내용 분리 결함과 잠재 오발송 위험이다.
- 이 문서는 감사 결과와 제안 설계이며 구현 완료·운영 적용·경제성 검증을 뜻하지 않는다. 최종 문서 검토/통합 기록은 후속 PR 영수증에 남긴다.
