# 동일 진입의 첫 청산 판단 재생

## 목적

순수익 개선을 위해 청산 정책이 **같은 진입과 장중 가격 경로에서 언제 다른 판단을 내리는지**
분리한다. 일봉의 고가·저가 순서를 임의로 가정하지 않는다. 기존 동일 진입 비교는 호가 기준
손절 대용치이며, 이번에는 실제 `ExitManager`의 첫 신호까지 재사용한다.

## 범위와 입력 계약

- `first_exit_replay_v1`: 동일 KST 날짜의 신규 KR 진입 한 건, 시간순 PRICE 경로, 정책 두 개.
- 진입: 종목, 양의 정수 수량, 양의 유한 소수 문자열 가격, 시간대 포함 시각, 원천 참조.
- 이벤트: 증가하는 sequence, 역전 없는 시간대 포함 시각, `kind=PRICE`, 가격, 원천 참조.
  진입 전·날짜 변경·BOOK/bid 대용 입력은 거부한다. 같은 시각의 순서는 sequence가 결정한다.
- 두 정책의 이름은 서로 다르다. ExitConfig와 지원하는 등록 인자는 명시적으로 전달한다.
  생략한 값은 코드 기본값이며, 운영 환경에서 가져온 설정이라고 주장하지 않는다.
- 매수·매도 수수료와 매도세율은 명시 입력한다. 모두 유한한 0 이상 1 미만 소수 문자열이다.
- 최대 2,000,000 bytes / 10,000 이벤트. 입력 지문, 청산 및 의존 소스 지문, 해석된 설정을 남긴다.
- 공개 인터페이스: `replay_first_exit(payload: dict) -> dict`; 잘못된 입력은 ValueError.
  `expected_policy_sha256`를 주면 실제 소스 지문과 대조한다.

## 실행과 격리

운영 청산 클래스의 메서드 코드를 독립 globals로 묶고, 재생 시계·임시 상태 경로·독립 수수료
계산기를 주입한다. 실제 생성자와 등록·가격 갱신 순서를 사용한다. 환경 HOME 변경, 모듈 전역
교체, 공유 수수료 계산기 변경, 운영 파일 조회, 브로커·LLM 호출은 없다.

각 정책은 최초 신호에서 멈춘다. `on_fill`은 호출하지 않으며 부분 매도 신호를 체결 또는
FIRST 완료로 바꾸지 않는다. 신호가 없으면 `not_observed_in_supplied_path`다. 두 정책 모두
미관측이면 판단 차이는 null이다. 이벤트 시각은 실제 내부 로직에 KST naive 시계로 공급한다.

## 결과 해석

출력은 첫 신호의 시각·원천 이벤트·가격·행동·수량·사유, 정책별 설정과 상태를 보존한다.
`fill_status=not_simulated`, `net_pnl=null`, `live_exit_parity=false`를 유지한다.
원천 참조/해시는 추적 수단이며 입력 진실성·원장 완전성·체결 가능성의 인증이 아니다.

완료 후 부분 체결, 주문 거절/취소, 다일 보유·휴장, 레짐/급락 변화, 보유 중 재기동,
FIRST 이후 복합 트레일링, 실행 비용 후 성과는 v1 범위 밖이다. v5 관측의 진입 호가와
900초 대용치는 이 도구에 필요한 전체 PRICE 경로와 체결 자료를 대신하지 않는다.
운영 ba29b903 및 10월19일 v5 예약을 유지한다. 오프라인 기능은 재배포하지 않는다.
