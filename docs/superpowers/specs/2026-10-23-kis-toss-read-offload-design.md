# KIS 조회 절약과 Toss 분석 연결 설계

사용자는 KIS와 Toss를 역할별로 병행하고, 반복 조회 정비 → 읽기 소비자 연결 →
기준이 맞는 일봉 분석 확대 순서로 진행하도록 승인했다.

## 목표와 선택

- 계좌·주문·보유 청산은 KIS를 유지하고 후보·표시·분석 조회 부담을 줄인다.
- KIS 제한만 낮추는 방식은 자료 적시성을 잃고, 전역 Toss 폴백은 시장 기준을
  섞으므로 채택하지 않는다. 개별 분석 소비자에서 명시적으로 분담한다.
- 성공 기준은 실제 HTTP 요청·거절 감소, 자료 나이·후보 누락이다. 수집량 증가나
  오프라인 시험 통과를 순수익 개선으로 표시하지 않는다.

## 1. KIS 직접 오류와 분석 일봉 재사용

직접 GET은 이미 공용 acquire를 거치지만 non-200 본문을 읽지 않아 EGW00201을
공용 거절 처리에 전달하지 않는다. 오류 본문은 16KiB/짧은 시간 상한으로 읽고,
확인된 msg_cd만 분류한다. 일반 HTTP500을 유량 초과로 추정하지 않는다. 재시도,
초당 상한, 원장 간격은 유지한다. 취소는 호출자에게 전달한다.

일봉은 브로커 전역 메서드를 변경하지 않고 분석 소비자의 별도 공유 캐시를 쓴다.
동일 브로커·KST 날짜·세션에서 최대 60초 재사용, 충분한 깊이의 성공 자료만 저장,
최대 64종목/500봉, 반환 복사, 원 요청 시작 시각부터 만료를 계산한다. 동일한
진행 요청은 합치되 한 대기자 취소가 다른 대기자의 조회를 취소하지 않는다.
모든 대기자가 취소되면 송신 작업도 회수한다. 날짜/세션 전환 뒤 오래된 진행
요청의 결과를 새 자료로 저장하지 않는다. 스크리너·섹터 분석만 명시 연결한다.
당일 봉을 확정봉으로 승격하지 않으며 5분 뒤 스캔은 다시 조회한다. 따라서 이
캐시만으로 5분마다 발생하는 모든 요청이나 오류가 사라진다고 주장하지 않는다.

## 2. Toss 읽기 소비자

기존 관측 서비스의 명령/승인/일정은 관측 전용이다. 토큰이나 grant를 재사용해
새 용도를 자동 허용하지 않는다. 실제 호출을 줄일 소비자와 운영 수명주기까지
확인한 뒤 연결하며, 호출되지 않는 보조 함수만 만들고 통합 완료라 하지 않는다.
가격의 원천·수신시각·통화·시장 기준을 보존하고 KRX+NXT 통합 호가를 KIS의
주문 가능 가격으로 표시하지 않는다. 소비자 연결의 구체안과 남은 근거는 계획에
추가한다. 이미 승인한 병행 개발을 반복 확인받지는 않는다.

첫 소비자는 장후 후보 보고의 참고 현재가다. 별도 서비스의 비공개 원장 권한은
변경하지 않고, 봇 내부 supervisor의 불변 가격 결과를 전달한다. 새 REST v3에
`daily_report_current_price` 목적과 수명/TTL을 결합하며 v1/v2 관측은 보고 소비를 허용하지
않는다. 완전 원장 후 가격만 반환하고, supervisor가 여전히 실행 중이며 승인/시각이
유효한 경우에만 메모리에 게시한다. 종료·실패·만료는 읽기 자료를 무효화한다.
보고 생성기는 지연 주입으로 초기화 순서에 의존하지 않으며, 유효 Toss 가격이
없으면 기존 경로를 따른다. REST의 시장 기준이 unknown이면 통합 시세로 꾸미지
않고 참고가 대비 변화율도 계산하지 않는다. 가격 확인/비교 불가/가격 결측을 구분한다.

이 연결만으로 대시보드나 후보 실시간 WS가 전환되지는 않는다. 특히 기존 보고의
KIS 분기는 `_bot` 주입이 없어 운영 호출 감소를 주장할 수 없다. 첫 연결은 실제
가격 전달과 기존 보고 조회 생략을 검증하며, KIS 절감은 별도 분석 캐시 계수와
향후 대시보드/일봉 소비자 전환에서 측정한다. 새 v3 deployment/기간/grant를
설치하기 전에는 운영 Toss 대체가 발생하지 않는다.

## 검증·운영 경계

외부 API·운영 자격 없이 실패 재현 → 관련 시험 → 전체 verify·비밀 검사 →
독립 중요 리뷰 → 문서/커밋/푸시 순서로 진행한다. 구현과 실제 설치·배포·측정은
구분한다. KR 매수 중지·월 USD100·기존 관측 원장·사용자 설정을 보존한다.
