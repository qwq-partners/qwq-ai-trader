# Local Development Control Plane Design

## 목적

QWQ AI Trader의 개발 중심을 운영 서버에서 Windows PC의 WSL2 Ubuntu로 옮긴다. 로컬에서는 Claude Code와 Codex를 이용해 코드 작성, 검증, 리뷰, 백테스트, 명시적으로 요청한 dry-run만 수행한다. 실제 주문, 운영 서비스 재시작, 배포는 로컬 개발 흐름에서 분리한다.

## 범위

이번 설계가 구현하는 첫 하위 프로젝트는 로컬 개발환경이다.

- WSL2 Ubuntu 내부의 `~/projects/qwq-ai-trader`를 유일한 로컬 작업본으로 사용한다.
- Python 가상환경, 프로젝트 의존성, Claude Code, Codex, Git, GitHub CLI의 준비 상태를 검사한다.
- Claude Code와 Codex가 동일한 프로젝트 규칙과 검증 절차를 따르게 한다.
- 문법 검사, 테스트, 비밀정보 검사를 한 명령으로 수행한다.
- 새 개발자가 문서와 부트스트랩 명령만으로 환경을 재현할 수 있게 한다.

다음 항목은 별도 설계와 구현 계획으로 다룬다.

- GitHub 브랜치 보호와 필수 PR 검사 설정
- GitHub Actions 기반 CI
- Lightsail 자동 배포, 상태 확인, 롤백
- 운영 서버의 systemd 단위 파일과 sudo 정책 변경
- 운영 저장소에 기록된 평문 비밀번호 형태의 명령 제거

## 확정된 제약

- 표준 로컬 환경은 Windows 위의 WSL2 Ubuntu다.
- 저장소 경로는 `~/projects/qwq-ai-trader`다. `/mnt/c` 아래에는 별도 작업본을 만들지 않는다.
- Python 3.11 이상을 지원하며 현재 WSL의 Python 3.12를 사용한다.
- 로컬 환경은 실거래 주문을 실행하지 않는다.
- 운영 `.env`, 로그, 캐시, PID 및 거래 상태 파일을 로컬로 복사하지 않는다.
- 모든 변경은 `feature/*` 작업 브랜치에서 수행하고 PR을 통해 `main`에 병합한다.
- `main` 병합은 이 단계에서 운영 배포를 유발하지 않는다.

## 아키텍처

개발 흐름은 네 개의 경계로 나뉜다.

1. **WSL 개발 작업본**: 소스, `venv`, 테스트 도구, Claude Code, Codex가 위치한다.
2. **Git 브랜치와 PR**: 검증된 변경만 공유하고 `main` 직접 변경을 피한다.
3. **GitHub 품질 관문**: 다음 하위 프로젝트에서 자동 검사와 브랜치 보호를 추가한다.
4. **Lightsail 운영 런타임**: 배포 단계 전까지 로컬 개발 흐름과 연결하지 않는다.

로컬 작업본은 운영 서버와 코드만 Git으로 공유한다. `.env`, `logs/`, `~/.cache/ai_trader/`와 같은 런타임 데이터는 환경별로 독립적이다.

## 구성 요소와 파일 책임

### `AGENTS.md`

Codex의 진입점이다. `CLAUDE.md`, `CHANGELOG.md`, `docs/README.md`와 작업 분야별 문서를 먼저 읽도록 지시한다. 다음 안전 규칙을 명시한다.

- 명시적 사용자 요청 없이 주문 실행, 운영 SSH 명령, 서비스 재시작, 배포를 수행하지 않는다.
- 금액과 가격은 `Decimal`을 사용하고 기존 비동기 및 문서 갱신 규칙을 따른다.
- 코드 변경에는 관련 테스트와 문서를 함께 갱신한다.
- 구현자와 리뷰어 역할을 분리하고 동일 파일의 동시 수정을 피한다.

`AGENTS.md`는 기존 `CLAUDE.md`의 프로젝트 지식을 복제하지 않고 이를 권위 있는 상세 규칙으로 참조한다.

### `scripts/dev/bootstrap.sh`

WSL에서 재실행 가능한 개발환경 준비 명령이다.

- Linux 및 저장소 루트에서 실행 중인지 검사한다.
- Python 3.11 이상, Git, Node.js, npm, GitHub CLI, Claude Code, Codex의 존재 여부를 검사한다.
- 기존 `venv`가 없을 때만 생성한다.
- `requirements.txt`를 `venv`에 설치한다.
- 기존 `.env`나 가상환경을 덮어쓰지 않는다.
- 인증 정보나 토큰 값을 출력하지 않는다.
- 실패한 검사 또는 설치 단계에서 즉시 종료하고 해결 방법을 표시한다.

도구 자체의 전역 설치와 로그인은 자동화하지 않는다. 사용자 계정과 인증 상태를 변경하는 동작은 안내 문서에서 명시적 명령으로 제공한다.

### `scripts/dev/verify.sh`

로컬 변경의 단일 검증 진입점이다.

- `venv`가 없으면 실행을 중단하고 부트스트랩 명령을 안내한다.
- 추적 중인 Python 소스에 `py_compile`을 실행한다.
- 전체 pytest 모음을 실행한다.
- Git 추적 대상에서 대표적인 비밀정보 패턴을 검사한다.
- 어떤 단계든 실패하면 0이 아닌 상태로 종료한다.
- `systemctl`, SSH, 주문 스크립트, 운영 API 호출을 실행하지 않는다.

비밀정보 검사는 예방용 기본 관문이다. 전문 비밀 스캐너와 GitHub 차단 정책은 후속 CI 프로젝트에서 추가한다.

### `.env.example`

필요한 환경변수의 이름과 설명을 제공하되 실제 값은 포함하지 않는다. 거래 관련 값은 비어 있거나 개발 환경을 가리키는 안전한 기본값을 사용한다. `.env`는 계속 `.gitignore`에 포함한다.

### `docs/operations/local-development.md`

다음 사용자 흐름을 설명한다.

1. WSL 실행과 저장소 경로 확인
2. 저장소 복제 및 SSH 원격 확인
3. 부트스트랩 실행
4. Claude Code와 Codex 실행
5. 작업 브랜치 생성
6. 검증 실행
7. push와 PR 생성
8. dry-run을 수행할 때의 별도 안전 확인

## Claude Code와 Codex 협업 흐름

기본 역할은 Claude Code가 구현자, Codex가 조사·테스트 보강·리뷰어다. 작업 성격에 따라 역할을 바꿀 수 있지만 한 변경에서 구현과 최종 리뷰는 분리한다.

모든 세션은 다음 순서로 시작한다.

1. `CHANGELOG.md`에서 최근 변경과 미해결 사항을 확인한다.
2. `CLAUDE.md`와 `docs/README.md`를 읽는다.
3. 작업 분야에 해당하는 문서를 읽는다.
4. 작업 브랜치와 작업 트리 상태를 확인한다.
5. 변경 전에 테스트 범위와 안전 영향을 정한다.

변경 후에는 관련 문법 검사, 관련 테스트, 전체 테스트, 비밀정보 검사, 독립 리뷰, 문서 갱신 순으로 완료한다.

## 데이터와 비밀정보 흐름

- Git은 소스와 비밀이 제거된 예제 설정만 전달한다.
- 로컬 `.env`는 사용자가 직접 만들며 커밋되지 않는다.
- 초기 환경 구성과 단위 테스트는 `.env` 없이 성공해야 한다.
- 외부 조회 API가 필요한 테스트는 명시적으로 선택한 통합 테스트로 분리한다.
- dry-run에 필요한 조회용 자격증명만 로컬에 추가하며 실거래 자격증명의 복사를 기본 절차로 문서화하지 않는다.
- 운영 캐시와 거래 상태는 Lightsail에 남고 로컬에서 참조하지 않는다.

## 오류 처리

- 부트스트랩과 검증 스크립트는 `set -euo pipefail`로 첫 실패에서 중단한다.
- 누락된 도구, 지원하지 않는 Python 버전, 누락된 가상환경은 서로 구분되는 메시지로 보고한다.
- 기존 파일과 환경은 묵시적으로 삭제하거나 덮어쓰지 않는다.
- 의존성 설치 오류는 원래 설치 명령의 출력을 보존한다.
- 검증 실패 후 push, PR, 배포 같은 후속 동작을 자동 실행하지 않는다.
- 비밀정보 검사 결과에는 비밀값 전체를 다시 출력하지 않고 파일 위치와 규칙만 표시한다.

## 테스트 전략

스크립트 로직은 실제 사용자 환경을 변경하지 않는 셸 테스트로 검증한다.

- 지원되는 Python 버전에서 부트스트랩 사전 검사가 통과한다.
- 오래된 Python 또는 필수 도구 누락 시 명확히 실패한다.
- 기존 `venv`와 `.env`를 덮어쓰지 않는다.
- 검증 스크립트가 문법 오류, pytest 실패, 대표 비밀 패턴을 각각 감지한다.
- 정상 저장소에서는 검증 스크립트가 성공한다.
- 어느 테스트도 운영 서버 SSH, systemd 또는 실제 주문 경로를 호출하지 않는다.

저장소 전체 테스트가 외부 서비스나 운영 자격증명에 의존하는 경우, 그 사실을 먼저 기록하고 로컬 기본 테스트와 선택적 통합 테스트의 경계를 후속 계획에서 명확히 한다.

## 완료 기준

- WSL의 `~/projects/qwq-ai-trader`에서 Claude Code와 Codex를 실행할 수 있다.
- 한 개의 부트스트랩 명령으로 로컬 Python 개발환경을 재현할 수 있다.
- 한 개의 검증 명령으로 문법, 테스트, 기본 비밀정보 검사를 수행할 수 있다.
- 기본 로컬 흐름에서 실거래 주문, 운영 SSH, 서비스 재시작이 실행되지 않는다.
- 비밀값과 운영 런타임 데이터가 Git에 포함되지 않는다.
- 새 개발자가 `docs/operations/local-development.md`만 보고 동일한 흐름을 수행할 수 있다.

## 후속 프로젝트

첫 프로젝트가 검증된 뒤 다음 순서로 별도 설계한다.

1. GitHub Actions와 브랜치 보호를 포함한 품질 관문
2. 수동 승인 기반 Lightsail 배포, 상태 확인, 실패 시 롤백
3. 필요성이 확인될 때만 컨테이너 또는 잠금 파일 기반 재현성 강화
