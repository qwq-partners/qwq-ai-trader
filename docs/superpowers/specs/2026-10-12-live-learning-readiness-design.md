# 순수익 개선과 일별 검증 설계 (2026-10-12)

## 목적과 결정

어떤 종목을 어떤 가격·시점에 매수해야 비용 후 수익이 개선되는지 검증한다. 사용자가 두 우선순위의 통합·순차 진행을 요청했으므로, 모든 개선을 20일 관측 종료까지 보류하지 않는다. 일별 오류 수정과 경제적 우위 판정은 구분한다.

1. **호출·평가 결함과 비용 계측**: 모델 이름/추론 옵션의 실제 전송, 사용량/재시도 비용, 잘못된 일수익 목표를 먼저 정비한다.
2. **입력과 실측 가능성**: 판단 시점의 자료·결측·전략 버전을 보존하고, 호가 당시 장 상태와 LLM 응답 이후 실제 진입 가능한 호가를 연결한다. 고정 소수 종목의 짧은 수집은 기술 검증이며 H1 수익 증거가 아니다.
3. **동일 입력 모델 비교**: 현행 모델을 기준으로 한 후보 모델·추론 수준씩 비교한다. 첫 비교부터 고가 모델을 전 호출에 적용하지 않는다.
4. **일별 누적 점검과 제한적 적용**: 데이터/오류는 매일 수정하고, 모델·전략 경제성 변경은 버전별 코호트를 고정해 한 번에 하나씩 평가한다. 실제 거래 재개와 위험 한도는 별도 운영 결정이다.

## 이번 구현 경계

- 기존 모델 설정과 TASK_CONFIG 라우팅을 유지한다. 신규 paid shadow·실거래·관측 예약·운영 재시작을 켜지 않는다.
- 공급자 옵션 검증 강화로 기존 호출자가 깨지는지 전수 점검한다. ResearchTeam은 OpenAI 옵션을 Gemini에도 넘기고 있었으므로 공급자별로 나누고 원장에도 명시한 옵션만 기록한다. Gemini의 기존 기본 추론과 프롬프트/모델은 유지한다.
- GPT/Gemini 추론 제어는 지원 조합만 명시적으로 전달하며 잘못된 조합은 HTTP 전에 거절한다.
- 서버가 보고한 모델과 요청 모델을 분리하고, 토큰·추론 토큰·종료 사유·지연을 보존한다. 실제 추론 기본값을 추정해 기록하지 않는다.
- 각 완료 시도(빈 응답/재시도/fallback 포함)의 사용량을 비용에 반영한다. 미지의 모델 단가나 전송 후 미상 사용량은 0원으로 간주하지 않는다.
- daily_budget는 유한한 비음수 USD 설정을 읽는다. 기존 프로세스 내 사후 누적 제한이며, 동시 실행/재시작/미상 비용까지 보장하는 전역 일일 상한은 아니다.
- 메타데이터 감사는 audit_dir 명시 주입 시만 기록한다. 프롬프트/응답 본문/키/계좌를 기록하지 않고 보존 기간을 제한한다. 운영 활성화는 다음 단계다.
- 위 본문 미기록은 새 metadata audit의 경계다. 기존 응답 본문 로그는 이 변경으로 제거하지 않는다. 감사 파일 I/O는 동기식이므로 활성화 전 실제 부하/저장 지연 검증이 필요하다.
- 복기 입력에는 계좌 NAV·입출금·비용 완결성이 없다. 거래 평균 수익률을 계좌 일수익/TWR/초과수익으로 바꾸지 않는다. 계좌 성과는 미측정으로 표시한다.
- 일 1%·거래 횟수·임의 손절 폭 목표를 제거한다. LLM 실패 시 기초 통계와 증거 공백만 반환하고 파라미터/새 규칙 제안을 만들지 않는다. 기존 반환 스키마와 하위 검증기를 유지한다.

## 매일 수정하면서도 비교가 유효한 조건

관측 원본은 수정하지 않고 코드 SHA·설정 지문·프롬프트/모델/요청 추론 수준·자료 시각·장 상태를 함께 보존한다. 오류 수정으로 의미가 바뀌면 새 코호트로 나누며, 이전 기간을 현재 엔진의 실적으로 재표기하지 않는다. 기술적 결측/수집 실패는 즉시 중단·수정하고, 하루 손익으로 손절/점수/모델을 반복 최적화하지 않는다.

매일 보는 항목은 수집 완결성, 요청/응답 시각, 알려진/미상 비용, 실패·기권, 종목 선택/진입/청산의 분리 성과, 회피한 손실과 잘못 거절한 이익이다. 응답 후 호가가 없으면 진입 가격과 순손익은 unknown이다. 전체 KODEX200 비교와 사전 정의한 대칭적 반도체 제외 비교를 병기하며 상승 종목을 사후 삭제하지 않는다.

20일 H1 계약은 유지한다. 짧은 pilot은 자료 연결을 증명하고, 20일 결과가 나기 전에도 검증된 결함은 배포할 수 있다. 조기 손실/운영 결함 중단은 가능하지만 유리한 중간 결과만으로 성공을 선언하지 않는다. 규칙을 바꾸면 새 프로토콜/코호트를 만든다. 연속 관측 자체는 매매 의무가 아니다.

## 수용 기준

가짜 HTTP 세션으로 실제 요청 payload, 옵션 거절, 사용량·비용·재시도·fallback·예산·감사 비밀정보 배제를 검증한다. 실제 ReviewResult를 이용해 거래 횟수가 늘어도 계좌 수익률을 만들어내지 않으며 실패가 손절 축소로 이어지지 않는지 검증한다. 전체 오프라인 verify와 독립 critical 리뷰 후에만 통합한다. 실측 수익과 모델 우위는 이번 테스트의 결론이 아니다.
