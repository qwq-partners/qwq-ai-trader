# E04-BEAR-API-CAP-PREP — API 400/800 비교 진단 준비

사용자 승인 범위: 기존 가드·어댑터를 재사용한 코드·오프라인 검증·준비 자료. 실제 공급자 호출은 별도 승인 전 금지. 기준 main `af35f601`, 직전 조사 `51a23912`. 정본 상태는 `docs/operations/execution-roadmap.md`.

## 계약과 보존

- API만 순서대로 400/800 각 1시도, 최대 2시도·재시도 0·추정비 USD0.50. Bull/CLI/운영 worker/R1은 사용하지 않는다.
- `claude-opus-5-5`, low, temperature/seed None, 기존 공통 입력+Bear suffix/system 동일. 각 시도의 고정 API 시한 5.75초는 진단 예산이며 기존 fallback의 실제 잔여 시간 상한이라는 뜻은 아니다. 운영 패널12/내부11.5/CLI5.75초·설정·매수 중지는 불변이다.
- 기존 입력을 읽기 전용으로 재사용해 새 실험 ID·새 출력 디렉터리에 동결한다. 과거 승인·시도·영수증은 재사용하지 않는다. 준비에는 자격증명·공유 원장·전송 생성이 필요 없다.
- 준비물의 입력·제어·프롬프트·소스 SHA와 새 승인 창을 지문으로 묶는다. 승인자·승인 지문·창·코드/운영 제어 일치 확인 전에는 전송 생성도 하지 않는다. 한 번 소비한 계획은 실패/중단/프로세스 종료 뒤에도 자동 재개하지 않는다.
- 첫 400 응답의 `max_tokens`는 신원·사용량·정산이 알려져 있고 해당 중단 사유만 남은 경우에 한해 승인된 800 조건으로 이어진다. 이 예외는 승인 요청서에 명시한다. 다른 실패·거절·신원 불일치·불명 정산·늦은 결과는 중단한다. 부분 답변을 유효 의견으로 승격하지 않는다.
- 예약·정산은 `ComparisonCallGuard`, 단일 전송은 `ClaudeSingleAttemptAdapter`가 소유한다. 기존 PairSpec/Bull 비교기·어댑터·설정은 변경하지 않는다. 전용 API 클라이언트를 종료한 뒤 안전한 영수증을 저장한다. 응답/프롬프트/숨은 추론을 영수증에 넣지 않는다.
- 조사 중 확인한 선행 제약: 공유 원장은 `comparison_policy(id=1)` 하나에 결합되며 현재 11/4 실험의 400토큰 정책이 있다. 새 정책은 `comparison_policy_mismatch`로 거절된다. 준비 경로는 이 충돌을 읽기 전용으로 표시하고 실행 전 차단한다. 원장 초기화·다른 예산 DB·기존 실험 ID 재사용으로 우회하지 않는다. 따라서 코드 준비와 실제 공유 원장에서의 실행 가능 상태를 구분한다.

## Task 1 — 준비·실행 계약과 오프라인 회귀 검사

추가 파일: `src/analytics/bear_api_cap_diagnostic.py`, `scripts/ops/bear_api_cap_diagnostic.py`, `tests/test_bear_api_cap_diagnostic.py`만. 구현자는 별도 worktree, coordinator는 문서만 수정한다. 먼저 실패하는 수락 검사를 작성하고 관련 검사에서 RED→GREEN을 남긴다.

필수 검증: 승인 전/창 밖/지문·SHA·제어 불일치 전송0; 동시·중복 실행0; 같은 입력에서 cap만 다름; 예약 각1·구독0; max_tokens 예상 경로; timeout/refusal/unknown/신원 불일치 중단; 가드 지연으로 시한 연장 불가; 종료·영수증 비유출. 테스트는 가짜 HTTP 또는 가짜 raw API와 임시 월 원장만 사용한다. 현재 작업에서 실제 run을 호출하지 않는다.

## Task 2 — 리뷰·WSL 검증·준비 자료

독립 critical 리뷰로 계약과 diff를 확인하고 지적을 반영한다. 새 소스만 AWS 관련 검사로 확인하고 실제 사용자 WSL에서 정본 `verify.sh` 직렬 전체를 통과시킨 뒤 푸시한다. 이미 완료된 과거 WSL/CI는 반복하지 않으며 AWS 전체는 WSL 대용으로 쓰지 않는다. 기존 WSL 호스트 핀·사용자 키·설정을 보존한다. 인증 부재 시 준비와 리뷰를 먼저 완료하고 재등록에 필요한 최소 정보만 요청한다.

변경 문서: 원장·CHANGELOG·CLAUDE·docs/README와 준비 절차. 원문·계좌·환경·비공개 영수증은 커밋하지 않는다. 준비 실행으로 승인되지 않은 계획을 만들고 승인 요청에 정확한 SHA/지문/새 창/중단 조건을 제시한다. 실호출·배포·재시작·발송·새 예약은 0이어야 한다.
