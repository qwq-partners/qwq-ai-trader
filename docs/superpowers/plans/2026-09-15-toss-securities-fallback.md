기존 조사에서 KIS 실패·일부 네이버/pykrx 채널 부재가 관측됐다(§2, 현재 상태 재측정과 구분). 토스증권 Open API 를 **2차 데이터 소스**로 추가해 발굴·표시·분석의 가용성을 보완한다. **청산 피드의 KIS 장애를 토스로 복구하는 작업은 이번 범위가 아니다.** 가용성 개선과 매매 성능 개선을 구분한다.

이 문서는 설계만 다룬다. 구현·배포는 단계별 승인 후 진행한다.

### 3.2 토스로 대체 불가 (잔여 외부 의존)

- **VIX** — yfinance `^VIX` 유지. 위 8종 카탈로그에 VIX가 없으며, 이를 토스 API 전체가 국내 전용이라는 뜻으로 확대하지 않는다.
- **미국 시장 데이터 전반** — 토스도 US 주식을 제공하지만 이번 범위 밖(US 엔진 미운용).
- **업종·섹터 분류(WICS)** — 토스 종목 정보에 **업종 필드가 없다**(`market`, `securityType` 만). pykrx WICS 대체 불가. 별도 해결 필요.
- **DART 공시·재무** — 범위 밖.

### 3.3 확인된 필드 제약 (설계에 반영해야 함)

1. **`/prices` 는 `symbol`·`timestamp`·`lastPrice`·`currency` 만 준다.** 등락률·거래량·전일종가·시가·고가·저가가 없다. KIS `get_quote` 소비자는 `change_pct`·`volume`·`prev_close` 를 쓰므로 **1:1 대체가 불가**하다.
   - 보완 1(기본): 일봉으로 필요한 필드를 보완하되 **2봉은 최소 조회 최적화일 뿐 당일/전일 계약이 아니다**. `bar_date`로 당일 봉과 직전 거래일의 확정봉을 찾는다. 장초에 오늘 봉이 없으면 직전 봉을 오늘 OHLCV로 쓰지 않는다. 휴일/주말을 건너뛰는 거래일 근거가 없거나 직전 거래일 봉이 없으면 해당 필드는 미획득이다. `prev_close`는 직전 거래일 확정 종가이며, `change_pct`는 동일 시장·가격조정 기준의 현재가와만 계산한다.
   - 보완 2(제한적): 랭킹 응답 재사용은 **`MARKET_*` 타입에 한정**하고, 거래량 합성은 `duration=realtime|1d` 만 쓴다(`tradingVolume`·`tradingAmount` 는 duration **누적**이라 1w 이상은 당일 누적이 아니다). `TOSS_SECURITIES_*` 는 **토스증권 체결분만** 집계하므로 배제하고, `TOP_GAINERS`/`TOP_LOSERS` 는 `price.basePrice`·`price.changeRate` 가 duration 시작 시점 기준의 **기간 등락률**이라(게다가 `realtime` 미지원 — 400 `unsupported-ranking-duration`) 등락률·거래량 합성 소스에서 배제한다.
   - 필드 경로는 `price.basePrice`·`price.changeRate`(top-level 은 `tradingVolume`·`tradingAmount` 뿐)이고, **`changeRate` 는 소수비율**(`0.0125` = 1.25%)이라 KIS `change_pct`(`prdy_ctrt`, 퍼센트) 자리에 넣을 때 ×100 변환이 필요하다. `basePrice=0` 이면 `changeRate` 가 null 이다.
   - 합성 값은 필드별 출처·관측 시각·거래일·완성 여부를 보존한다. 서로 다른 조회의 결과를 **동시점 완전 quote로 포장하지 않는다**. 필요한 값이 없거나 기준이 다르면 §4.4 소비자 계약에서 차단한다.
2. **`timestamp` 는 조건부 nullable 이다.** 지수 현재가는 실측에서 `null` 이었고, `/prices`·`/orderbook` 도 스펙상 nullable(`[string, null]`)이다. 항상 null 인 것이 아니라 **데이터 미제공 시** null 이다. T9/T10 의 "관측 시각 모르면 None" 계약상 null 이면 **`data_status=partial`** 로 취급하고 신선도 게이트를 통과시키지 않는다.
3. **가격 기준 차이** — 토스 국내 시세는 **KRX+NXT 통합**이라 정규장 종료 후에도 20:00 까지 갱신된다. 실측 예: 같은 종목이 토스 149,500원(19:59 애프터마켓) vs 봇이 KIS 로 보유한 평가 기준 150,800원(정규장 종가). **약 0.9% 차이.** 청산·사이징에 그대로 넣으면 판단이 달라진다 — §6.1.
4. 기존 조사에서 KODEX 200은 `nxtSupported=false`·시각 15:59로 보고됐다. 이 표본만으로 모든 ETF의 장후 확정/갱신 시점이나 시세 거래소를 추정하지 않는다.
5. **일봉(`/candles`) 계약이 KIS `get_daily_prices` 와 세 곳에서 다르다. 무증상 오염 위험이 가장 큰 항목이다.**
   - **(a) 정렬이 반대다.** 토스는 **최신순 내림차순**(배열 첫 요소가 최신 봉), KIS 는 **오래된 순**이다. 소비자 9곳이 전부 `closes[-1]`·`closes[-200:]`·`[-20:]` 로 "끝이 최신"을 가정한다(코어 스크리너, 스윙 스크리너, 섹터 모멘텀, 배치 분석기). **같은 유형의 정렬 역전이 2026-08-07 에 이 저장소에서 두 번 실사고를 냈다**(섹터 수익률 부호 역전). 예외가 나지 않고 값만 틀리는 실패다.
   - **(b) 날짜 포맷이 다르다.** 토스 `timestamp` 는 ISO8601(`2026-09-15T00:00:00+09:00`), KIS 는 `YYYYMMDD` 문자열이다. 정렬만 고쳐도 당일 부분봉 제외 가드·전일 거래량 비교·CF 추적의 날짜 비교가 조용히 무력화된다.
   - **(c) 거래대금 축이 없다.** `Candle`에는 OHLCV·통화만 있다. 전용 내부 결과에서는 `value=None`+미획득을 허용하되 **기존 KIS 숫자 dict로 그대로 내보내지 않는다**. legacy 소비자가 `value`를 요구하면 이 소스는 미지원이다. 종가×거래량 또는 0으로 거래대금을 위조하지 않는다. 키 생략 허용도 소비자별 계약 테스트가 있어야 한다.
   - **(d) `adjusted` 기본값이 `true`** 다. KIS 는 `fid_org_adj_prc="1"` 고정이며 두 기준이 같은지는 미확인이다. 어댑터에서 **명시적으로 고정**하고 Phase 1 에서 액면분할 이력 종목으로 대조한다.
   - → 어댑터는 **오래된 순 정렬 + KST 거래일 `YYYYMMDD` + 수치 변환**을 수행한다. `before`는 inclusive이므로 응답의 **`nextBefore`를 그대로** 다음 요청의 `params`로 전달한다(`+` 인코딩 보장). 페이지 중복 제거·커서 미진행 검출·페이지 상한·필요 구간 충족 후에만 완전 결과를 반환한다. 빈/실패한 후속 페이지를 성공으로 합치지 않는다.
6. **필드별 시각·유효성** — `observed_at`(자료 관측), `fetched_at`(수신), `bar_date`/봉 시작, `complete`(확정 여부)를 분리한다. 일봉 자정은 실시간 관측 시각이 아니다. `fetched_at`/파일 mtime로 오래된 데이터나 null을 신선하게 만들지 않는다. 필드별 최대 나이·시각 차이·미래 허용 오차를 Phase 1 manifest에 사전 등록하며, 모르면 fresh 불가. 문자열 숫자는 유한값·통화·종목 일치·OHLC 정합성을 검증한다(가격 >0, 거래량 ≥0, bool/NaN/Infinity 거부). 진짜 0 거래량과 미획득을 구분한다.
7. **수급 단위·집계 대상** — 종목 `investor-trading`은 KRX+NXT의 **주식 수**, 등록외국인 기준이다. 시장 지표 수급의 거래대금·등록/미등록 합계와 섞지 않는다. 당일 잠정치의 세부 null은 매매 0이 아니다. `updatedAt`은 기록 전체의 마지막 보완 시각이며 모든 하위 필드가 그때 새 관측됐다는 뜻이 아니다. 이후 확정/수정치는 새 버전으로 저장하고 과거 판단·replay에는 당시 알 수 있던 버전만 사용한다. 금액이 필요한 기존 스코어에는 단위 변환을 발명하지 않고 미지원 처리한다.
8. **유니버스** — `/stocks/all`은 토스 거래 가능 종목 목록이다. 기존 마스터/보유 종목을 덮어쓰거나 누락 종목을 상장폐지·매도 대상으로 해석하지 않는다. 시장·상품 유형·상장일·종목 코드 문자열(선행 0/영숫자)을 검증하고 추가 커버리지만 관측한다. 과거 목록이 없는 경우 현재 목록으로 과거 백테스트를 돌려 무편향이라고 주장하지 않는다.

## 4. 아키텍처 설계

### 4.1 모듈 배치

```
src/data/providers/toss/
  __init__.py
  client.py        # TossClient — 읽기 endpoint allowlist·공유 deadline·에러 매핑
  token.py         # 단일 토큰 캐시 (파일 + asyncio.Lock + 프로세스 간 락)
  rate_limit.py    # 동일 자격 전체의 그룹별 게이트 (KIS와 독립)
  market_data.py   # 현재가·호가·캔들·상하한가·최근체결
  reference.py     # 종목 마스터·전체 종목·캘린더·환율
  supply.py        # 투자자별·프로그램·공매도·신용·대차
  ranking.py       # 랭킹
  indicators.py    # 지수 현재가·캔들
src/data/providers/quote_router.py   # 1차 KIS → 2차 토스 라우팅 + source 태그
```

기존 `src/data/providers/kis_market_data.py` 와 같은 계층에 둔다. 브로커(`src/execution/broker/`)에는 **넣지 않는다** — 주문 경로와 물리적으로 분리하기 위해서다.

`quote_router`는 **브로커를 주입받는 별도 provider wrapper**다. **기존 브로커 메서드에 폴백 훅을 주입하거나 monkey-patch하지 않는다.** 기존 `broker.get_quote/get_daily_prices`는 KIS 단독이며 시그니처도 유지한다. wrapper의 opt-in은 `allow_fallback=False` 기본값에 더해 승인된 `consumer_id`/필수 필드 계약으로 제한한다. 광범위한 호출부를 한꺼번에 교체하지 않는다.

- **opt-in 후보**: 표시 전용 dashboard SSE/HTTP, 표시 전용 리포트. 정확한 함수와 하류 쓰기 경로를 §4.6 원장에 등록해야 한다.
- **별도 Phase 2 승격**: 스크리너·수급/섹터 점수·지수 레짐 등 신규 후보/정책 입력에 영향을 주는 경로. 함수 이름이 '분석/리포트'여도 위험이 낮다고 간주하지 않는다.
- **전 세션 KIS 단독**: REST/WS 가격 피드, 배치 보유 모니터, 포트폴리오 현재가/최고가/평가액, ExitManager, 진입 재확인·사이징·주문·수동 주문·호가. 스케줄러의 '전광판'도 엔진 시장 이벤트를 발행하므로 표시용 allowlist에서 제외한다.

### 4.2 토큰 관리 (가장 중요한 제약)

토큰은 **클라이언트당 1개만 유효**하다. 봇·스크립트·백테스트가 각자 발급하면 서로를 끊는다(대시보드는 별도 프로세스가 아니라 봇과 같은 프로세스다 — 파일 락은 스크립트·배치·수동 호출 대비용이다).

- 전용 보안 디렉터리의 단일 캐시(예정 `~/.cache/ai_trader/toss/toss_token.json`). **일반 `atomic_write_json`을 그대로 쓰지 않는다**: 현재 헬퍼의 고정 `.tmp`+기본 권한은 0600을 보장하지 않는다. 전용 디렉터리 소유권/0700·별도 고정 락 파일 소유권/0600을 검증하고 symlink를 거부한다. 고유 임시 파일을 생성 순간부터 0600으로 열어 flush/fsync→원자 교체→디렉터리 fsync한다. 기존 공유 상위 캐시 디렉터리 권한을 임의 변경하지 않는다. 실패는 공유 게시 실패로 전파한다.
- **캐시·락 경로는 상수가 아니라 생성자 인자**로 둔다. `tests/conftest.py` 격리 가드가 `~/.cache/ai_trader` 하위 접근을 차단하며, 같은 원인(운영 경로 접근)으로 2026-09-15 배포가 verify 실패로 자동 롤백된 전례가 있다
- **역할 명시**: 승인된 봇 1개만 `issuer`, 조사/스크립트는 `reader`다. reader는 캐시 없음·손상·만료·401에서도 절대 발급하지 않는다. 로컬 파일 락은 다른 호스트/수동 외부 발급자를 조정하지 못한다. 같은 자격으로 외부 발급을 병행하지 않는 소유권 절차가 선행 조건이다.
- 구조: `{access_token, issued_at, expires_at, issuer_pid, generation, client_identity, origin, schema_version}`. client identity는 비밀이 아닌 설정 식별자로 대조하며 토큰 원문/부분문자열을 로그 식별자로 쓰지 않는다. `issuer_pid`만으로 발급 권한을 인정하지 않는다.
- 정상 발급: 단일 issuer가 검증된 수명의 만료 **30분 전 이내** 갱신하며 짧은 수명/오류 응답으로 반복 발급하지 않도록 최소 갱신 간격도 둔다. 별도 고정 파일의 `LOCK_NB`로 직렬화하고 락 안에서 캐시·발급 소유권·회로 상태를 재확인한다. 대기/갱신 모두 §6.6 deadline 적용. 초기 캐시 부재의 bootstrap 발급은 별도 승인된 1회 절차이며 일반 reader 초기화의 부작용이 아니다.
- **`401 token-revoked` 수신 시: 재발급하지 않는다.** 스펙 권고는 "최신 토큰으로 다시 시도"다. 이 코드는 *다른 주체가 이미 더 새 토큰을 발급했다*는 신호이므로, 여기서 재발급하면 방금 정당하게 발급된 상대의 토큰을 다시 죽여 §6.2 의 상호 무효화 핑퐁이 그대로 발생한다("1회만" 은 각 프로세스가 독립적으로 1회씩 하므로 전역 루프를 막지 못한다).
  ① 캐시 재읽기 → ② 실패한 토큰과 **다르고 유효한** 동일 client/origin 캐시이면 1회 조회 재시도 → ③ 같음/없음/손상이면 **발급 0회**, `auth_unavailable`과 경보로 종료한다. **캐시 삭제 금지.** 이 경우 auth 회로를 지속 상태로 잠가 다음 폴링·재시작·일반 만료 갱신이 재발급 금지를 우회하지 못하게 한다. 최신 캐시 공유 확인 또는 사용자 승인 복구 전 해제하지 않는다.
- `expired-token`도 우선 캐시 재확인하며 **소유권이 확인된 issuer만** 정상 갱신을 할 수 있다. `invalid-token`/기타 401/403은 무조건 발급 신호로 보지 않고 분류 후 중단·경보한다. 응답 **`error.code`**로 분기하며 HTTP 401만으로 결정하지 않는다.
- 토큰 발급은 비멱등이다. 발급 POST 타임아웃·응답 유실·발급 성공 후 저장 실패는 `issuance_unknown`으로 잠그고 **자동 재발급하지 않는다**. 발급 전 intent를 안전하게 남겨 프로세스 중단 후에도 중복 발급하지 않는다. 공유 저장 성공 전 새 토큰을 정상 게시한 것으로 처리하지 않는다. KIS 캐시 부재 자동 발급/저장 실패 흡수 패턴은 이식하지 않는다.

### 4.3 레이트 리미터

- `kis_rate_limit` 과 **완전히 분리된 독립 게이트**. 토스 호출이 KIS 예산을 소모해서는 안 된다(현재 네이버 크롤링이 저지르는 실수의 반복 금지).
- 그룹별 토큰 버킷은 **동일 client identity의 모든 모듈·재시도·페이지 호출**이 공유한다. Phase 1은 봇 단일 송신자로 한정하고 reader 스크립트의 동시 네트워크 조회는 금지한다. 다중 프로세스 조회가 필요하면 공유 게이트/중앙 송신자를 구현·검증한 별도 변경으로 허용한다. process-local 전역 객체 여러 개를 합산 제한으로 주장하지 않는다.
- 그룹 매핑을 고정하고 `X-RateLimit-Limit`로 상한을 낮춘다. `X-RateLimit-Remaining`은 남은 버킷 토큰, **`X-RateLimit-Reset`은 토큰 1개 보충까지의 예상 초**다(UTC epoch 아님). 429 hold/하향 한도를 같은 그룹 전체에 반영한다.
- 429는 `Retry-After` 우선, 없으면 유효한 Reset/제한된 백오프+jitter를 사용한다. **조회 재시도는 §6.6의 공유 예산 1회**뿐이다. AUTH 그룹/발급 POST는 이 재시도에서 제외한다. 제한 헤더 없음·손상 시 보수적 초기 한도를 유지하고 자동 상향하지 않는다.

### 4.4 라우팅 정책 (`quote_router`)

```
wrapper.get_quote(symbol, consumer_id, allow_fallback=False) ->
    1차: 기존 KIS 조회 (성공 → 복사본에 source="kis")
    opt-in + 승인 소비자 + 활성 단계 확인 -> 토스 조회/필드 검증
    소비자별 필수 필드·시점·시장 계약 충족 -> 숫자 legacy payload
    불충족 -> {} / 별도 표시 전용 partial 결과 (소비자 계약으로 구분)
기존 broker.get_quote/get_daily_prices -> KIS 단독, 토스 훅 없음
```

- **반환 계약 불변 = 타입 도메인 불변.** 기존 소비자는 KIS 가 결측을 숫자 0 으로 채운다는 전제로 작성돼 있고 `quote.get(k, 0)` 로만 방어한다. 같은 dict 에 `None` 을 넣으면 `dict.get(k, default)` 가 default 를 쓰지 않고 `None` 을 돌려주므로 `Decimal(str(quote.get("open", price)))` 가 `InvalidOperation`, 비교·`round()` 가 `TypeError` 로 죽는다. 그 예외는 REST 피드 루프의 per-symbol `except → logger.debug` 에 삼켜져 **폴백이 성공했는데 해당 종목의 청산 체크가 조용히 건너뛰어진다** — §0 목표의 정반대다.
  - **내부 결과와 legacy dict를 분리한다.** 내부 값은 미획득 `None`과 사유를 보존한다. legacy 반환은 `required_fields(consumer_id)`의 숫자 타입·유한값·시점 계약이 모두 충족된 경우만 허용하며, 필수 값 하나라도 없으면 **`{}`/스킵**이다. `price`만 있다고 성공으로 보지 않는다. 0/전일 OHLCV로 결측을 채우지 않는다. 메타를 읽지 않는 소비자 앞에서 wrapper가 차단해야 한다.
  - 표시 전용 소비자는 명시적으로 계약을 바꿔 partial+N/A를 표시할 수 있지만, 그 dict를 숫자 legacy 소비자·엔진에 재사용하지 않는다. 누락 키 생략/선택 필드도 소비자별 테스트로 고정한다.
  - **타입도 계약에 포함된다** — 토스는 가격·수량을 전부 **decimal 문자열**로 준다(`lastPrice`, 캔들 OHLCV, `tradingVolume`). KIS `get_quote` 소비자는 float/int 를 전제하므로 어댑터에서 변환한다. 금액 계산으로 넘어가는 값은 `Decimal(str(v))` 를 거친다(CLAUDE.md 정밀 계산 규칙).
  - CLAUDE.md의 결측/0 구분 규칙을 신규 키에만 한정하는 예외를 만들지 않는다. 기존 KIS 성공 응답은 변경하지 않지만, 신규 토스 결측을 숫자 0으로 성공 포장하는 것은 금지한다. 숫자 변환 안전성과 의미적 충분성은 서로 다른 인수 조건이다.
- 모든 응답에 `source`·`as_of`·`data_status` 를 붙인다. **주의**: 대시보드는 quote 의 `source` 를 읽지 않고 `"kis"` 를 리터럴로 써넣는다(폴백은 `"yahoo"`). 라우터의 `source` 가 화면에 자동 반영되지 않으므로 표시 배선을 Phase 3 작업 항목에 포함한다.
- 폴백 발동은 **계측 + 집계 INFO/상태 전환 로그**로 남긴다. 실패/미지원/결측/노후/인증/한도/회로를 구분하고 최초 성공 시각과 마지막 성공 시각을 갱신한다. 토큰·raw body는 기록하지 않는다.

### 4.5 캐시

| 데이터 | TTL | 근거 |
|---|---|---|
| 전체 종목 마스터 | 1일 (일 1회 배치) | 문서 권장, `STOCK_ALL` 초당 1 |
| 장운영 캘린더 | 1일 | 3영업일치를 한 번에 줌 |
| 일봉 | 장중 부분봉 최대 5분 / 확정봉은 기준 거래일별 | 부분봉은 시간 경과만으로 확정되지 않음; 재조회·확정 근거 필요 |
| 현재가 | 캐시 없음 | 신선도가 본질 |
| 랭킹 | 1~5분 | 기존 KIS 랭킹 캐시와 동일 |

TTL은 보관/재조회 정책이지 신선도 증명은 아니다. **기존 캐시 코드 재사용≠운영 파일 공유**다. `toss/shadow` namespace를 따로 두고 source·client identity(필요 시)·시장/거래소 기준·symbol·interval·adjusted·조회 기간/인자·schema version을 키/메타에 포함한다. KIS 전용/플래그 off 소비자는 Toss 캐시도 읽지 않는다. 운영 수급 날짜 캐시·섹터 캐시·포트폴리오·이벤트 버스를 shadow가 갱신하지 않는다. 부분 실패/노후값은 last_success/TTL을 갱신하지 않으며, 롤백 후 캐시를 KIS 자료로 재해석하지 않는다.

## 5. 단계별 도입 계획

각 단계는 독립 PR이며 **구현 승인·실자료 관측 승인·소비자 승격 승인을 구분**한다. 모든 단계의 배포 기본값은 **`TOSS_API=0`**이다. off이면 토스 client 생성·토큰/네트워크 조회·토스 캐시 소비·shadow 잡 등록도 하지 않는다. 구현/테스트만으로 플래그를 바꾸지 않는다. master on도 허용 단계/consumer allowlist 승인을 대신하지 않는다.

### Phase 0 — 자체 버그 수정 (토스와 무관, 선행)

토스를 붙이기 전에 고쳐야 오염된 비교가 안 된다.

- `kr_screener` 거래량 순위 화면코드 `20101`→`20171`; 비율 미획득 시 `prdy_vol` 계산 또는 스킵(1.0 위조 금지)
- `kr_scheduler` 의 `supply_score_provider` 모듈명 오타 수정
- 네이버 크롤링이 `kis_rate_limit` 예산을 쓰는 배선 제거
- 코드 3건은 PR #60으로 완료. 운영 인수는 API 원행수/파싱 성공/필터 탈락/후보 수와 16:00 배치 실행·자료 획득 성공을 따로 계측한다. **실제 조건을 만족하는 종목이 없어 0건인 경우는 정상**이며, 호출 성공/잡 실행만으로 데이터 복구를 선언하지 않는다.
- 인수(계측): 배포 후 **3영업일간 일별 통합 후보 수와 채널별 기여 수**를 집계해 **Phase 0 단독 기준선**으로 이 문서에 기록한다. 이 기준선이 없으면 Phase 2 의 토스 효과가 Phase 0 버그 수정 효과와 분리되지 않는다

### Phase 1 — 인프라 + shadow 대조 (기본 OFF, 승인 후 기록만)

- `TossClient`·토큰·리미터 구현, 어떤 소비자도 토스 값을 **쓰지 않는다**
- 오프라인 fixture/§10 인수를 먼저 통과한다. **약관·자격 발급 소유권·실자료 관측 manifest 승인 전 인증 API 호출 금지**. shadow는 독립 저우선순위 잡이며 기존 청산/동기화 루프에 await를 추가하지 않는다. KIS 비교 조회도 기존 리미터를 사용하고 신규 호출 예산을 사전 등록한다. KIS 지연/한도 악화 시 shadow를 스킵하고 비교 자료 부족으로 기록한다.
- 5분마다 보유 종목·후보 상위 N 종목에 대해 KIS ↔ 토스 값을 대조해 원장(JSONL)에 기록: 가격 차이 bp, 응답 지연, 실패율, 세션별 분포
- 캘린더 API 를 매일 받아 `utils/session.py` 하드코딩과 대조, 불일치 시 경고
- **거래소/수정주가 기준 확인**: `/candles`의 KRX 단독/통합 기준은 공급자 문서 또는 답변으로 확인한다. 20종목 KIS 일봉 대조는 **수치 일관성 관측일 뿐 거래소 계약의 증명은 아니다**. 답변 없으면 `market_basis=unknown`으로 보존하고 KRX 동등성이 필요한 소비자에 승격하지 않는다. 수급의 통합/KRX·주/금액 기준도 분리한다.
- 인수: 3영업일 이상. 관측 전에 manifest에 종목 N/선정 규칙(보유·후보·ETF·NXT·비NXT), 세션/거래일, 시각 허용차, 필드별 freshness, 분모/제외 사유, 최소 유효 표본·커버리지, 장애율·p95 지연 상한, KIS 신규 호출 예산, 계산식·코드/설정/스펙 SHA를 **숫자로 사전 등록**한다. 값 미확정이면 실자료 관측/승격을 시작하지 않는다.
- 가격 차이는 `100 * abs(toss-kis) / kis`(kis>0), p95 계산법도 고정한다. 기존 초안 X=0.3%·차이0.5% 초과 비율 Y=0.5%는 **미승인 예시**이며 삭제/변경으로 소급 통과시킬 수 없다. 종목-시점 고유 표본을 단위로 사용하고, null/노후/실패/부적격은 차이 분모에서만 제외하여 **전체 시도 수 대비 비율을 별도 공개**한다. 조건 미달/표본 부족이면 승격 보류. 정상 시점의 가격 근접성은 청산 사용 허가가 아니다.
- 인수: **일봉 정규화 대조** — 60거래일 정렬/날짜/OHLCV 대조에 더해 200봉 경계를 넘는 소비자별 전체 구간, 두 번째 페이지 실패/중복, 분할 이력, 당일 부분봉을 검증한다. 값이 비슷해도 미지원 필드/시장 기준을 같다고 판단하지 않는다.
- 인수: **토큰 경합/오류**는 가짜 transport·임시 캐시·두 프로세스로 §10을 검증한다(정상 단일 issuer 갱신 1회, reader 0회, revoked/불명확한 발급 결과 재발급 0회). 실서버에서 의도적으로 토큰을 여러 번 발급해 재현하지 않는다.
- 현금 고갈로 신규 매수가 0건이라 **매수 후보 기반 표본이 비어 있을 수 있다.** 대조 대상은 보유 종목 + 스크리닝 상위 N 종목으로 고정해 주문 발생과 무관하게 표본을 만든다

### Phase 2 — 발굴·분석 입력 보강 (돈 경로 간접, 별도 승격)

Phase 0 이후에도 부족한 채널만 대상으로 한다. 후보·점수·레짐이 달라지므로 **매매 의미 변경**이다. 먼저 별도 namespace에서 기존 결과와 shadow 비교하고, 소스별 승격 승인 전에는 live 후보/점수를 바꾸지 않는다.

- 랭킹(거래량·거래대금·등락률) → 네이버 크롤링 제거, KIS 랭킹은 유지하되 병합
- 신고가: **200은 페이지 크기이지 52주 구간이 아니다**. 소비자의 20/250/252거래일 또는 달력 52주 정의·당일 제외·종가/고가 기준을 사전 명시하고, 페이지를 모아 중복 제거한 **고유 확정봉/기간**이 그 구간을 충족해야 한다(수익률은 시작점 포함 추가 봉 필요). 둘째 페이지의 고점을 빠뜨리거나 200봉/짧은 상장 이력을 완전한 52주로 표시하지 않는다. MA200은 200개 유효 확정봉이면 1페이지일 수 있으나 부분봉 제외·중복 시 추가 조회한다.
- 투자자별 수급: 종목 단위 일별 조회로 전환
- 섹터 ETF 일봉: 13종목의 전체 페이지·성공/실패·p95/최대 지연을 예산 안에서 측정한다. 20 TPS로부터 '1초 이내' 완료를 추론하지 않는다.
- 인수: 후보 수를 **09-09(35개)가 아니라 Phase 0 기준선 대비**로 판정한다 — Phase 0 만으로 회복된 분을 토스 효과로 오인하지 않는다
- 인수: 랭킹 유형·duration·단위·시장·가중치·동일 종목 중복/상관 소스 이중 가산 정책·허용 점수/후보 변화·rollback 기준을 관측 전에 고정한다. '크게 다르지 않음'이나 후보 수 증가만으로 통과시키지 않는다. 같은 날짜/동일 유니버스에서 Phase 0 기준군과 소스 추가군을 비교하고, 가용성/커버리지와 향후 수익률 평가는 분리한다. 신규 후보가 나와도 실제 진입 가격/위험 검사는 KIS만 사용한다.

### Phase 3 — 표시 전용 KIS 실패 폴백 (돈 경로 제외)

Phase 1 대조 결과가 허용 범위일 때만 진행한다.

- §4.6의 승인된 **표시 전용 호출부만 별도 wrapper를 opt-in**한다. 브로커 전역 훅·메서드 교체 금지. 전략 일봉/지수/스크리닝에 대한 추가 사용은 Phase 2로 분류한다. 호가·청산·사이징·주문은 제외한다.
- 대시보드 `source` 표시 배선(§4.4 주의 참조)
- **세션 제한**: 첫 승격은 정규장(09:00~15:20) 표시만. 이 시간에도 KRX 단독가라고 라벨링하지 않는다. 다른 세션 표시는 별도 승인·라벨/신선도 검증이 필요하다. **어느 세션에서도 Toss 값을 청산에 쓰지 않는다.**
- 인수: 플래그 off 시 Order 지문 불변(특성화 테스트), 폴백 발동 시 `source=toss` 가 원장·대시보드에 노출
- 인수: 플래그 **on** + KIS 실패/복구 + Toss 성공/실패/부분/노후에서 금지 호출부의 Toss 호출 0·엔진 이벤트 불변·portfolio current/highest/equity 불변·ExitManager/Order 인자 지문 불변. `source` 문자열만 검사하지 않는다(REST는 `rest_polling`으로 재라벨링한다). spy는 예외에 삼켜질 수 있는 내부 assert 대신 **호출 후 외부 단언**으로 검증한다.
- 인수: 폴백 응답으로 기존 소비자 경로가 **예외를 내지 않음** — 결측 키 조합 특성화 테스트. 오발동뿐 아니라 **미발동**(예외가 삼켜져 청산 체크가 누락되는 경로)도 인수 대상

### Phase 4 — WebSocket (선택, 별도 승인)

- 향후 KR 관측용 WS 대체 가능성을 연구한다. **KIS 실행 피드 이관/approval_key 해제는 이번 설계의 승인 범위가 아니다.**
- 계정당 동시 연결 2개 제한, 180초 내 PING 필수, 시세는 LOSSY 보장
- 통합 시세는 세션 필터만으로 KRX 동등성을 보장하지 않는다. 소비 측 시장/시각 검증, 누락·중복·역순·재접속 스냅샷·backpressure·토큰 회전/구독 복구를 별도 AsyncAPI 고정 스펙으로 설계한다. 현 단계는 KIS 실행 피드/청산과 연결하지 않는다.
- 인수: 별도 연구 설계·승인 후 결정. REST와의 이중화라는 이름으로 금지된 실행 경로를 자동 확장하지 않는다.

## 6. 위험과 완화

### 6.1 가격 기준 차이 (최대 위험)

토스 국내 시세는 KRX+NXT 통합이다. 정규장 종료 후에도 갱신되므로 **KIS 정규장 종가와 다르다**(실측 0.9% 차이).

- 청산 판정(`ExitManager.update_price`)에 통합 시세를 넣으면 손절·트레일링이 장외 가격으로 발동할 수 있다
- 완화: **청산·포트폴리오 평가/최고가 갱신은 전 세션 KIS 단독**으로 유지한다. 표시용 토스 값은 출처·시장 기준·관측 시각을 구분하며, 세션 태그나 가격 오차 통과를 청산 허가로 사용하지 않는다. 기존 NXT 조회/실패 동작도 변경하지 않는다.
- 사이징·주문 가격은 **KIS 값만** 사용한다(폴백 금지)
- **이 금지는 호가에도 그대로 적용된다.** 호가 조회는 매도 지정가 산출로 직결되는데, 토스 호가는 요청 파라미터가 `symbol` 하나이고 응답(`timestamp`/`currency`/`asks`/`bids`)에 **거래소 식별 필드가 없어** 어느 거래소의 호가인지 알 수 없다. 통합 최우선 매수호가는 KRX 최우선 매수호가 이상이므로 그 값으로 지정가를 내면 KRX 에 미체결로 남아 **청산이 지연된다**. 호가는 어떤 단계에서도 폴백 대상이 아니며, KIS 호가 실패 시 기존 강등 동작(시그널 가격 지정가 → 시장가)을 그대로 유지한다

### 6.2 토큰 상호 무효화

§4.2의 단일 issuer·reader·안전 게시·최신 캐시 재시도·불명확 시 발급 중단이 필요하다. **파일 락만으로 외부 발급자를 보호할 수 없다.** 공유되지 않은 최신 토큰/발급 결과 불명 상태는 자동 회복 대신 `auth_unavailable/issuance_unknown`으로 드러내고 승인된 복구를 기다린다.

### 6.3 세션 판정 자동 교체 금지

캘린더 API 가 정본이라도 세션 판정을 자동으로 바꾸지 않는다. 세션은 주문 허용·스케줄러 주기·동기화 케이던스에 걸려 있어 외부 응답 하나로 바뀌면 사고 범위가 크다. **불일치 경고 → 사람이 확인 → 코드 수정** 순서를 지킨다.

### 6.4 약관·계정 리스크

- 자동화 시세 조회·저장·화면 표시/재배포 허용 범위는 계정 적용 약관/공급자 답변으로 **확인 필요**다. 이번 리뷰는 법적 허용성을 판정하지 않는다. 인증 실자료 shadow도 확인·승인 이후에만 한다(오프라인 구현/공개 스펙 조회와 구분).
- 허용 IP는 선행 조건이다. master on + 승인된 모드에서만 조회 전용 상태 점검을 수행하고, 실패는 Toss만 unavailable 처리한다. 전체 봇/KIS 기동을 막거나 403으로 토큰을 재발급하지 않는다. off 기동은 인증/네트워크 0회다.

### 6.5 자격증명 관리

- `.env` 에 `TOSS_CLIENT_ID`·`TOSS_CLIENT_SECRET` 추가(2026-09-15 운영 반영 완료), 커밋 금지(기존 `.gitignore` 적용)
- 공개 OAuth 정의의 scopes는 비어 있어 시세 전용 권한을 주장할 수 없다. 동일 bearer가 주문/계좌 API의 인증에도 쓰이고 계좌 헤더는 비밀이 아니다. 허용 IP도 허용 서버 내부의 오호출을 막지 못한다. 공급자 권한 정책은 별도 확인하되, 우리 코드에는 아래 transport 전 경계를 둔다.
- 설계 과정에서 시크릿이 평문 전달됐고 재발급을 권고했으나 **사용자 판단으로 현재 키를 유지**한다(2026-09-15). 위 스코프 부재를 전제로, 허용 IP 를 운영 서버 단일 IP 로만 유지하고 IP 변경 절차를 runbook 에 기재한다.
- **메서드+정확한 조회 endpoint allowlist**: 주문/취소/조건주문/계좌는 GET도 거부한다. 고정 HTTPS origin·TLS 검증·redirect 금지·URL/경로 정규화 검증·계좌 헤더 주입 금지. 발급 POST는 issuer 전용 정확한 `/oauth2/token`만 예외로 두며 일반 client에 노출하지 않는다. 이 경계는 오호출 방어이지 서버측 read-only scope나 키 탈취 방지가 아니다.
- 로그는 status·정규화 error_code·그룹·지연·attempt 등 허용 필드만 구성한다. 인증 헤더·토큰 요청/응답 본문·raw 예외 문자열은 기록하지 않는다. 현재 `_mask_secrets`는 Authorization/Bearer/JWT 일반 문자열을 모두 가리지 못하므로 그대로 재사용했다고 안전하다고 주장하지 않는다. 합성 비밀로 오류/파싱/저장 실패 경로까지 검사한다.

### 6.6 폴백 실패 경로의 지연

청산 피드에는 토스 await를 추가하지 않는다. 표시/분석 wrapper도 동일 이벤트 루프·세션 풀·KIS 예산을 공유할 수 있으므로 HTTP timeout만으로 격리를 주장하지 않는다.

- 호출 시작의 **단일 monotonic deadline**을 KIS 1차·토큰/락·리미터·HTTP·페이지·재시도·응답 변환이 공유한다. 잔여 시간이 없으면 폴백을 시작하지 않는다. KIS 브로커 자체 정책은 수정하지 않고 wrapper 바깥 금지 경로는 영향 0을 검증한다.
- 토스 **논리 조회당 총 재시도 1회**를 401 최신 캐시 재시도/429/5xx/연결 실패/페이지 재시도가 함께 소비한다. 페이지 첫 요청 수는 따로 제한한다. 라이브러리·router·client의 중첩 retry를 금지한다. 토큰 POST는 자동 retry 0회다.
- `Retry-After`가 deadline을 넘으면 **일찍 재시도하지 않고 포기**한다. 락은 비블로킹 제한 대기, 취소는 finally로 락/응답/세션 자원을 해제한다. 취소를 삼키거나 백그라운드 갱신이 뒤늦게 토큰을 회전시키지 않는다. 발급 취소/불명확 결과는 §4.2로 처리한다.
- 연속 실패 N·open 기간·half-open probe 수·동시성·페이지 상한·deadline 값은 Phase 1 manifest에 숫자로 고정한다. auth 회로는 일반 HTTP 성공만으로 해제하지 않는다. health에 unavailable/last_success/실패 원인/skip을 노출하고 KIS heartbeat가 대기 중에도 진행하는지 테스트한다.
- 복귀/rollback: 승인된 Toss 플래그/consumer를 끄면 신규 잡·조회·캐시 소비가 중단되고 KIS 기준선으로 돌아간다. 진행 중 작업 취소·세션 close·캐시 분리를 확인하며 주문/pending/포트폴리오 상태를 삭제하거나 토큰을 재발급하지 않는다. 운영 플래그 변경은 별도 사용자 승인 작업이다.

## 7. 보류·확인 필요

1. **이용약관/키 소유권** — 확인·승인 전에는 Phase 1의 인증 실자료 관측도 진행하지 않는다
2. **업종·섹터 분류** — 토스에 필드가 없다. pykrx WICS 대체안을 별도로 찾아야 한다(현재 키워드 12개 폴백은 반쪽)
3. **200봉 페이지 상한** — MA200은 유효 확정봉 200개, 250/252거래일 고점은 해당 전체 구간, 252기간 수익률은 시작점까지 필요하다. 짧은 역사/일부 페이지 실패는 기간 부족으로 표시한다. 비용/커버리지는 Phase 1에서 측정
4. **NXT 커버리지 세부** — ETF 등 `nxtSupported=false` 종목의 장외 갱신 부재를 소비자별로 확인
5. **US 확장** — 토스도 US 를 제공하나 이번 범위 밖
6. **거래소/수정주가 계약·시각 신뢰도·승격 manifest** — 공급자 확인/필드 계약/숫자 기준 미완이면 해당 소비자의 승격을 보류한다. 값이 비슷하다는 이유로 unknown을 확정으로 바꾸지 않는다
