# 토스증권 Open API 2차 데이터 소스 도입 설계 (T12)

> 작성 2026-09-15 · 기준 SHA `dc26235` · 상태: **설계 단계 (구현 미착수, 승인 대기)**
> 원칙: **주문·체결·잔고·계좌는 KIS 단독 유지.** 토스는 읽기 전용 시세·참조 데이터에만 쓴다.

## 0. 요약

KIS OpenAPI 의 초당 한도·HTTP 500 이 스크리닝·시세 경로를 반복적으로 비우고 있고, 백업이던 네이버 크롤링과 pykrx 는 이미 사실상 사망했다. 토스증권 Open API 를 **2차 데이터 소스**로 추가해 (a) 이미 죽어 있는 발굴 채널을 복구하고 (b) KIS 실패 시 돈 경로의 조용한 스킵을 없앤다.

이 문서는 설계만 다룬다. 구현·배포는 단계별 승인 후 진행한다.

> **검토 이력**: 2026-09-15 적대적 검토(스펙 정확성·아키텍처·돈 경로 위험·단계 검증 가능성 4관점, 지적 43건 → 확정 34건 중 blocking 11건) 반영본. 주요 정정은 토큰 `token-revoked` 처리 방향 반전(§4.2), 반환 계약의 `None` 금지(§4.4), 일봉 정렬 역전(§3.3.5), 호가 폴백 전면 금지(§6.1), 랭킹 필드 의미 한정(§3.3.1), Phase 3 사전 등록 임계값(§5).

## 1. 검증된 사실 (2026-09-15 실제 호출로 확인)

토큰 발급과 조회를 운영 서버에서 직접 수행해 확인했다. 아래는 문서 인용이 아니라 실측이다.

| 항목 | 확인 결과 |
|---|---|
| 인증 | `POST /oauth2/token`, client_credentials. `expires_in` **86399초(24h)**, refresh token 없음 |
| **토큰 단일성** | **클라이언트당 유효 토큰 1개.** 재발급하면 이전 토큰이 `token-revoked` 로 즉시 무효화 |
| 허용 IP | 운영 서버 공인 IP 에서 호출 성공 (사전 등록 완료 상태). 미등록 IP 는 403 |
| 권한 분리 | 시세·종목·수급·랭킹·지수·캘린더는 **토큰만** 으로 조회. 계좌 헤더 불필요 |
| Base URL | `https://openapi.tossinvest.com` · WebSocket `wss://openapi-ws.tossinvest.com/ws/v1` |
| 스펙 | OpenAPI 3.1 `1.2.17` (`/openapi-docs/latest/openapi.json`), AsyncAPI 3.0 |
| Rate limit | 그룹별 TPS, 응답 헤더 `X-RateLimit-Limit/Remaining/Reset`, 429 시 `Retry-After` |

### 1.1 실측한 rate limit 그룹 (응답 헤더 기준)

| 그룹 | TPS | 해당 API |
|---|---|---|
| `MARKET_DATA` | 15 | 현재가(다건 200), 호가, 최근체결, 상/하한가 |
| `MARKET_DATA_CHART` | 20 | 캔들(1분봉·일봉, 최대 200봉) |
| `STOCK` | 5 | 종목 기본정보(다건 200) |
| `STOCK_ALL` | 1 | 마켓별 전체 종목 |
| `STOCK_TRADING_TREND` | 10 | 투자자별·프로그램·공매도·신용·대차 |
| `RANKING` | 5 | 랭킹(최대 100위) |

| `MARKET_INFO` | 3 | 환율, 장운영 캘린더 |

KIS 의 계좌당 초당 1건(EGW00215) 같은 병목이 없고, 무엇보다 **원장 TR 레인과 완전히 분리**된다.

## 2. 현재 데이터 소스 실태 (조사에서 드러난 것)

폴백을 붙이기 전에 **이미 죽어 있는 채널**이 다수 확인됐다. 이것이 이번 도입의 실제 동기다.

| 채널 | 현재 상태 (30일 로그 실측) |
|---|---|
| 거래량 급증 순위 (KIS `volume-rank`) | 2,474회 호출 **전부 0개 발굴**. rt_cd=0 정상 응답인데 `vol_inrt` 파싱 결과가 항상 1.0 → `min_volume_ratio=2.0` 에서 전량 탈락. screen_all 최대 가중치(0.5) 라인이 30일간 0 기여 |
| 신고가 포착 (KIS `capture-uplowprice`) | 2,469회 **전부 0개**. 200/rt_cd=0 + 빈 output. 모멘텀·VCP 핵심 발굴 채널이 사실상 부재 |
| 네이버 금융 크롤링 (백업 3종) | 09-11 부터 파싱 성공 **0건**(테이블 구조 변경 800건). 게다가 크롤링이 `kis_rate_limit.acquire()` 를 호출해 KIS 초당 예산까지 소모 |
| pykrx WICS 업종분류 | 30일간 성공 **0건**(KRX 인증/차단). 섹터 분산·로테이션이 키워드 12개 하드코딩 폴백에만 의존 |
| 전종목 5일 수급 배치 | `supply_score_provider` **모듈명 오타**로 30일간 한 번도 실행되지 않음(`ModuleNotFoundError`). 소스(pykrx)도 차단 상태 |
| 등락률 순위 (KIS) | limit=50 을 요청해도 **30행 고정** 반환 — 상위 30위 밖은 구조적 미발굴 |

| 섹터 ETF 일봉 (KIS) | `FHKST03010100` HTTP 500 일 233~606건 |

### 3.2 토스로 대체 불가 (잔여 외부 의존)

- **VIX** — yfinance `^VIX`. 토스는 국내 전용.
- **미국 시장 데이터 전반** — 토스도 US 주식을 제공하지만 이번 범위 밖(US 엔진 미운용).
- **업종·섹터 분류(WICS)** — 토스 종목 정보에 **업종 필드가 없다**(`market`, `securityType` 만). pykrx WICS 대체 불가. 별도 해결 필요.
- **DART 공시·재무** — 범위 밖.

### 3.3 확인된 필드 제약 (설계에 반영해야 함)

1. **`/prices` 는 `symbol`·`timestamp`·`lastPrice`·`currency` 만 준다.** 등락률·거래량·전일종가·시가·고가·저가가 없다. KIS `get_quote` 소비자는 `change_pct`·`volume`·`prev_close` 를 쓰므로 **1:1 대체가 불가**하다.
   - 보완 1(기본): 일봉 2봉(`candles?interval=1d&count=2`)으로 전일 종가·당일 거래량을 합성한다.
   - 보완 2(제한적): 랭킹 응답 재사용은 **`MARKET_*` 타입에 한정**하고, 거래량 합성은 `duration=realtime|1d` 만 쓴다(`tradingVolume`·`tradingAmount` 는 duration **누적**이라 1w 이상은 당일 누적이 아니다). `TOSS_SECURITIES_*` 는 **토스증권 체결분만** 집계하므로 배제하고, `TOP_GAINERS`/`TOP_LOSERS` 는 `price.basePrice`·`price.changeRate` 가 duration 시작 시점 기준의 **기간 등락률**이라(게다가 `realtime` 미지원 — 400 `unsupported-ranking-duration`) 등락률·거래량 합성 소스에서 배제한다.
   - 필드 경로는 `price.basePrice`·`price.changeRate`(top-level 은 `tradingVolume`·`tradingAmount` 뿐)이고, **`changeRate` 는 소수비율**(`0.0125` = 1.25%)이라 KIS `change_pct`(`prdy_ctrt`, 퍼센트) 자리에 넣을 때 ×100 변환이 필요하다. `basePrice=0` 이면 `changeRate` 가 null 이다.
   - 합성 값은 **출처를 태그**해 KIS 원본과 구분한다.
2. **`timestamp` 는 조건부 nullable 이다.** 지수 현재가는 실측에서 `null` 이었고, `/prices`·`/orderbook` 도 스펙상 nullable(`[string, null]`)이다. 항상 null 인 것이 아니라 **데이터 미제공 시** null 이다. T9/T10 의 "관측 시각 모르면 None" 계약상 null 이면 **`data_status=partial`** 로 취급하고 신선도 게이트를 통과시키지 않는다.
3. **가격 기준 차이** — 토스 국내 시세는 **KRX+NXT 통합**이라 정규장 종료 후에도 20:00 까지 갱신된다. 실측 예: 같은 종목이 토스 149,500원(19:59 애프터마켓) vs 봇이 KIS 로 보유한 평가 기준 150,800원(정규장 종가). **약 0.9% 차이.** 청산·사이징에 그대로 넣으면 판단이 달라진다 — §6.1.
4. ETF 는 `nxtSupported=false` 라 정규장 종료 후 갱신되지 않는다(실측: KODEX 200 타임스탬프 15:59).
5. **일봉(`/candles`) 계약이 KIS `get_daily_prices` 와 세 곳에서 다르다. 무증상 오염 위험이 가장 큰 항목이다.**
   - **(a) 정렬이 반대다.** 토스는 **최신순 내림차순**(배열 첫 요소가 최신 봉), KIS 는 **오래된 순**이다. 소비자 9곳이 전부 `closes[-1]`·`closes[-200:]`·`[-20:]` 로 "끝이 최신"을 가정한다(코어 스크리너, 스윙 스크리너, 섹터 모멘텀, 배치 분석기). **같은 유형의 정렬 역전이 2026-08-07 에 이 저장소에서 두 번 실사고를 냈다**(섹터 수익률 부호 역전). 예외가 나지 않고 값만 틀리는 실패다.
   - **(b) 날짜 포맷이 다르다.** 토스 `timestamp` 는 ISO8601(`2026-09-15T00:00:00+09:00`), KIS 는 `YYYYMMDD` 문자열이다. 정렬만 고쳐도 당일 부분봉 제외 가드·전일 거래량 비교·CF 추적의 날짜 비교가 조용히 무력화된다.
   - **(c) 거래대금 축이 없다.** 토스 `Candle` 은 timestamp/open/high/low/close/volume/currency 뿐이다. 현재 `value` 를 읽는 소비자는 없지만(KIS 쪽도 채우기만 하는 필드), 키를 빼면 KeyError 가 나므로 `None` 으로 채운다.
   - **(d) `adjusted` 기본값이 `true`** 다. KIS 는 `fid_org_adj_prc="1"` 고정이며 두 기준이 같은지는 미확인이다. 어댑터에서 **명시적으로 고정**하고 Phase 1 에서 액면분할 이력 종목으로 대조한다.
   - → 어댑터는 **오래된 순 재정렬 + `YYYYMMDD` 변환 + 수치 변환**으로 KIS 계약에 정규화한 뒤에만 소비자에게 넘긴다.

```
src/data/providers/quote_router.py   # 1차 KIS → 2차 토스 라우팅 + source 태그
```

기존 `src/data/providers/kis_market_data.py` 와 같은 계층에 둔다. 브로커(`src/execution/broker/`)에는 **넣지 않는다** — 주문 경로와 물리적으로 분리하기 위해서다.

`quote_router` 는 `SectorMomentumProvider(broker=...)` 와 동일하게 **브로커 인스턴스를 주입받는 provider 계층 모듈**로 두고, **폴백은 호출부 opt-in** 으로만 켠다. 시그니처는 `get_quote(symbol, *, allow_fallback: bool = False)` 이며 **기본값은 KIS 단독**이다. `get_quote` 는 KR 에서만 23곳, `get_daily_prices` 는 12곳이 호출하므로 전역 교체는 변경면적이 과도하다.

- **opt-in 대상**: 대시보드, 스크리닝, 리포트 경로
- **기본값 유지(KIS 단독)**: 청산·사이징·주문 경로 — REST 가격 피드, 배치 실행부, 수동 주문

### 4.2 토큰 관리 (가장 중요한 제약)

토큰은 **클라이언트당 1개만 유효**하다. 봇·스크립트·백테스트가 각자 발급하면 서로를 끊는다(대시보드는 별도 프로세스가 아니라 봇과 같은 프로세스다 — 파일 락은 스크립트·배치·수동 호출 대비용이다).

- 단일 캐시 파일 `~/.cache/ai_trader/toss_token.json` (mode 0600, `atomic_write_json` 재사용)
- **캐시·락 경로는 상수가 아니라 생성자 인자**로 둔다. `tests/conftest.py` 격리 가드가 `~/.cache/ai_trader` 하위 접근을 차단하며, 같은 원인(운영 경로 접근)으로 2026-09-15 배포가 verify 실패로 자동 롤백된 전례가 있다
- **봇 외 발급 전면 금지** — 조사·디버깅용 수동 호출도 캐시 파일의 토큰을 읽어 쓴다. 사람이 `/oauth2/token` 을 직접 부르면 운영 봇의 토큰이 즉시 무효화된다
- 구조: `{access_token, issued_at, expires_at, issuer_pid}`
- 발급 규칙: 만료 **30분 전** 선제 갱신. 프로세스 간 경합은 파일 락(`fcntl.flock`)으로 직렬화하고, 락 획득 실패 시 **발급하지 않고 캐시를 다시 읽는다**.
- **`401 token-revoked` 수신 시: 재발급하지 않는다.** 스펙 권고는 "최신 토큰으로 다시 시도"다. 이 코드는 *다른 주체가 이미 더 새 토큰을 발급했다*는 신호이므로, 여기서 재발급하면 방금 정당하게 발급된 상대의 토큰을 다시 죽여 §6.2 의 상호 무효화 핑퐁이 그대로 발생한다("1회만" 은 각 프로세스가 독립적으로 1회씩 하므로 전역 루프를 막지 못한다).
  ① 캐시 파일을 다시 읽는다 → ② 실패한 토큰과 **다르면** 그 토큰으로 1회 재시도(발급 없음) → ③ **같을 때만** 파일 락을 잡고, 락 안에서 캐시를 한 번 더 확인(double-check)한 뒤 그래도 같을 때만 1회 발급한다. **캐시 파일 삭제 금지.**
- `401 expired-token` / `invalid-token` 은 재발급 경로가 맞다. `token-revoked` 와 **응답 본문의 에러 코드로 구분**해 처리한다(HTTP 401 만으로 분기 금지).
- KIS `_token_mgr` 의 기존 패턴을 참고하되, "재발급이 남을 끊는다"는 제약이 KIS 에는 없으므로 락은 새로 만든다.

### 4.3 레이트 리미터

- `kis_rate_limit` 과 **완전히 분리된 독립 게이트**. 토스 호출이 KIS 예산을 소모해서는 안 된다(현재 네이버 크롤링이 저지르는 실수의 반복 금지).
- 그룹별 토큰 버킷. 그룹 매핑은 `rate_limit.py` 에 상수로 두고, 응답 헤더 `X-RateLimit-Limit` 을 읽어 **런타임에 상한을 낮춘다**(문서상 값은 사전 공지 없이 바뀔 수 있다고 명시돼 있다).
- 429 수신 시 `Retry-After` 우선, 없으면 지수 백오프 + jitter. 재시도 상한 2회.

### 4.4 라우팅 정책 (`quote_router`)

```
get_quote(symbol) ->
    1차: KIS get_quote        (성공 → source="kis")
    2차: 토스 prices(+캔들 합성)  (성공 → source="toss", data_status 태그)
    실패: 기존과 동일하게 {} 반환 (동작 불변)
```

- **반환 계약 불변 = 타입 도메인 불변.** 기존 소비자는 KIS 가 결측을 숫자 0 으로 채운다는 전제로 작성돼 있고 `quote.get(k, 0)` 로만 방어한다. 같은 dict 에 `None` 을 넣으면 `dict.get(k, default)` 가 default 를 쓰지 않고 `None` 을 돌려주므로 `Decimal(str(quote.get("open", price)))` 가 `InvalidOperation`, 비교·`round()` 가 `TypeError` 로 죽는다. 그 예외는 REST 피드 루프의 per-symbol `except → logger.debug` 에 삼켜져 **폴백이 성공했는데 해당 종목의 청산 체크가 조용히 건너뛰어진다** — §0 목표의 정반대다.
  - 따라서 (a) 폴백 dict 는 KIS 와 **동일한 타입 도메인**(숫자)을 유지하고 `open/high/low/volume/prev_close` 는 §3.3.1 의 일봉 2봉 합성으로 채운다, (b) `price` 를 채울 수 없으면 부분 dict 대신 **`{}` 를 반환**해 기존 실패 경로로 떨어뜨린다, (c) 결측 사실은 값 자리가 아니라 `data_status`·`missing_fields: list[str]` **메타 키로만** 전달한다.
  - **타입도 계약에 포함된다** — 토스는 가격·수량을 전부 **decimal 문자열**로 준다(`lastPrice`, 캔들 OHLCV, `tradingVolume`). KIS `get_quote` 소비자는 float/int 를 전제하므로 어댑터에서 변환한다. 금액 계산으로 넘어가는 값은 `Decimal(str(v))` 를 거친다(CLAUDE.md 정밀 계산 규칙).
  - CLAUDE.md 의 "0 금지" 규칙은 **이번에 새로 추가하는 키**(`as_of`, `data_status`, `value`)에만 적용하고 기존 float/int 계약 키에는 적용하지 않는다. 0 과 결측을 구분해야 하는 소비자는 Phase 3 착수 전 개별 감사해 이 문서에 목록으로 남긴다(KR `get_quote` 소비자 20곳 이상).
- 모든 응답에 `source`·`as_of`·`data_status` 를 붙인다. **주의**: 대시보드는 quote 의 `source` 를 읽지 않고 `"kis"` 를 리터럴로 써넣는다(폴백은 `"yahoo"`). 라우터의 `source` 가 화면에 자동 반영되지 않으므로 표시 배선을 Phase 3 작업 항목에 포함한다.
- 폴백 발동은 항상 **INFO 로그 + 계측**. 조용한 대체 금지.

## 5. 단계별 도입 계획

각 단계는 독립 PR 이며 **다음 단계로 넘어가기 전에 승인**을 받는다. 플래그 `TOSS_API=0` 이면 전 경로가 토스를 호출하지 않는다(기본값은 단계마다 명시).

### Phase 0 — 자체 버그 수정 (토스와 무관, 선행)

토스를 붙이기 전에 고쳐야 오염된 비교가 안 된다.

- `kr_screener` 거래량 비율 산출(`vol_inrt` → 항상 1.0) 원인 확인·수정
- `kr_scheduler` 의 `supply_score_provider` 모듈명 오타 수정
- 네이버 크롤링이 `kis_rate_limit` 예산을 쓰는 배선 제거
- 인수: 거래량 급증 채널이 0개가 아닌 결과를 내는지, 16:00 수급 배치가 실제로 실행되는지 로그로 확인
- 인수(계측): 배포 후 **3영업일간 일별 통합 후보 수와 채널별 기여 수**를 집계해 **Phase 0 단독 기준선**으로 이 문서에 기록한다. 이 기준선이 없으면 Phase 2 의 토스 효과가 Phase 0 버그 수정 효과와 분리되지 않는다

### Phase 1 — 인프라 + shadow 대조 (기본 `TOSS_API=1`, 기록만)

- `TossClient`·토큰·리미터 구현, 어떤 소비자도 토스 값을 **쓰지 않는다**
- 5분마다 보유 종목·후보 상위 N 종목에 대해 KIS ↔ 토스 값을 대조해 원장(JSONL)에 기록: 가격 차이 bp, 응답 지연, 실패율, 세션별 분포
- 캘린더 API 를 매일 받아 `utils/session.py` 하드코딩과 대조, 불일치 시 경고
- **거래소 기준 확정**: `/candles` 일봉이 KRX 단독인지 KRX+NXT 통합인지 스펙에 없다(수급 API 는 명시돼 있다 — `investor-trading` 통합, `program-trades` KRX 전용). 표본 20종목으로 KIS 일봉과 대조해 확정하고 이 문서에 기록한다. 기존 수급 캐시는 KRX 기준이라 통합 기준 값을 섞으면 5일 누적 스코어가 오염된다
- 인수: 3영업일 이상 축적. **Phase 3 진입 조건은 데이터를 보기 전에 숫자로 사전 등록한다** — 정규장 09:00~15:20 동시각 KIS↔토스 |차이| 의 p95 ≤ X%, 0.5% 초과 샘플 비율 ≤ Y%. X·Y 는 Phase 1 PR 승인 시 확정하고(초안 X=0.3, Y=0.5 — 트레일링 3% 대비 여유치이지 유도값이 아니다) **측정 개시 후 변경하지 않는다.** 미달이면 Phase 3 는 보류하고 폴백을 스크리닝·대시보드 등 **비청산 경로로 한정**한다
- 인수: **일봉 정규화 대조** — 동일 종목 60거래일 일봉을 양쪽에서 받아 정렬·날짜·OHLCV 일치율을 확인한다(가격 대조만으로는 §3.3.5 의 정렬 역전이 드러나지 않는다). 액면분할 이력 종목 1건으로 수정주가 기준 일치도 확인
- 인수: **토큰 발급 횟수** — 두 프로세스가 동시에 폴링하는 상태에서 선제 갱신이 1회 일어날 때 발급 총 횟수가 **1회**임을 원장으로 확인(§4.2 핑퐁 방지 검증)
- 현금 고갈로 신규 매수가 0건이라 **매수 후보 기반 표본이 비어 있을 수 있다.** 대조 대상은 보유 종목 + 스크리닝 상위 N 종목으로 고정해 주문 발생과 무관하게 표본을 만든다

### Phase 2 — 죽은 채널 복구 (토스를 **주** 소스로, 돈 경로 간접)

이미 0건인 채널이라 "대체"가 아니라 "복구"다. 위험이 가장 낮다.

- 랭킹(거래량·거래대금·등락률) → 네이버 크롤링 제거, KIS 랭킹은 유지하되 병합
- 신고가: 일봉 200봉으로 20일·52주 고가를 **자체 계산**(외부 신고가 API 의존 제거). **§3.3.5 정규화를 통과한 리스트로만 산출한다** — 52주 고가는 `max` 라 순서 무관이지만 20일 고가는 순서 의존이다
- 투자자별 수급: 종목 단위 일별 조회로 전환
- 섹터 ETF 일봉: 13종목 1초 이내 수집
- 인수: 후보 수를 **09-09(35개)가 아니라 Phase 0 기준선 대비**로 판정한다 — Phase 0 만으로 회복된 분을 토스 효과로 오인하지 않는다
- 인수: 토스 랭킹은 스크리너의 **가중 병합에 새 소스로 들어가 매수 후보를 바꾼다.** 이 PR 에 소스별 가중치 값을 명시하고, 신규 후보의 점수 분포가 기존과 크게 다르지 않은지 확인한다

### Phase 3 — KIS 실패 시 폴백 (돈 경로 직접, 가장 신중)

Phase 1 대조 결과가 허용 범위일 때만 진행한다.

- `get_quote`·`get_daily_prices`·지수 현재가에 2차 소스 배선 (**호가는 제외** — §6.1)
- 배선은 **주입형 폴백 훅**으로 한다 — 브로커는 KIS 실패 시 기동 시점에 주입된 선택적 콜러블만 호출하고, **토스 코드·import 는 브로커에 두지 않는다**(§4.1 경계 유지). 대상 함수가 브로커 안에 있다는 사실과 "브로커에 토스를 넣지 않는다"는 원칙을 이 방식으로 양립시킨다
- 대시보드 `source` 표시 배선(§4.4 주의 참조)
- **세션 제한**: 폴백은 정규장(09:00~15:20)에만 허용한다. 토스는 **KRX 단독가를 제공하지 않으므로**(`/prices` 파라미터는 `symbols` 뿐이고 응답에 거래소 필드가 없다) 정규장 중에도 통합가가 KRX 최종가와 다를 수 있다. 이 차이는 **제거 불가이며 측정 대상**이다 — Phase 1 의 사전 등록 임계값으로만 판정한다. **장외·단일가 구간에는 폴백을 청산 판단에 쓰지 않는다**(§6.1)
- 인수: 플래그 off 시 Order 지문 불변(특성화 테스트), 폴백 발동 시 `source=toss` 가 원장·대시보드에 노출
- 인수: 플래그 **on** 상태에서 청산·사이징·주문 경로가 `source=toss` 를 **한 건도 받지 않음**을 원장으로 검증(opt-in 이 새지 않는지)
- 인수: 폴백 응답으로 기존 소비자 경로가 **예외를 내지 않음** — 결측 키 조합 특성화 테스트. 오발동뿐 아니라 **미발동**(예외가 삼켜져 청산 체크가 누락되는 경로)도 인수 대상

### Phase 4 — WebSocket (선택, 별도 승인)

- KR 실시간 체결·호가를 토스로 이관하면 KIS approval_key 를 US 전용으로 비울 수 있다
- 계정당 동시 연결 2개 제한, 180초 내 PING 필수, 시세는 LOSSY 보장
- ⚠️ **토스 KR 실시간은 통합 시세(KRX+NXT)라 전 세션(프리·정규·애프터 ~20:00)에서 푸시되고 KRX 전용 채널이 없다.** 이를 청산 경로에 그대로 물리면 §6.1 의 "장외에는 통합가를 청산에 쓰지 않는다" 완화책이 무력화된다 — 세션 필터를 구독이 아니라 **소비 측**에 둬야 한다
- 인수: REST 폴백과의 이중화, 연결 끊김 시 자동 복구, 기존 WS 소비자 계약 불변

## 6. 위험과 완화

### 6.1 가격 기준 차이 (최대 위험)

토스 국내 시세는 KRX+NXT 통합이다. 정규장 종료 후에도 갱신되므로 **KIS 정규장 종가와 다르다**(실측 0.9% 차이).

- 청산 판정(`ExitManager.update_price`)에 통합 시세를 넣으면 손절·트레일링이 장외 가격으로 발동할 수 있다
- 완화: 폴백으로 받은 가격에는 **세션 태그**를 붙이고, 청산 경로는 정규장 시세만 신뢰한다. 장외 구간에서는 기존 동작(넥스트장 전용 조회 또는 스킵)을 유지한다
- 사이징·주문 가격은 **KIS 값만** 사용한다(폴백 금지)
- **이 금지는 호가에도 그대로 적용된다.** 호가 조회는 매도 지정가 산출로 직결되는데, 토스 호가는 요청 파라미터가 `symbol` 하나이고 응답(`timestamp`/`currency`/`asks`/`bids`)에 **거래소 식별 필드가 없어** 어느 거래소의 호가인지 알 수 없다. 통합 최우선 매수호가는 KRX 최우선 매수호가 이상이므로 그 값으로 지정가를 내면 KRX 에 미체결로 남아 **청산이 지연된다**. 호가는 어떤 단계에서도 폴백 대상이 아니며, KIS 호가 실패 시 기존 강등 동작(시그널 가격 지정가 → 시장가)을 그대로 유지한다

### 6.2 토큰 상호 무효화

§4.2 의 단일 캐시·파일 락·**최신 토큰 재시도**(재발급 금지)로 해결한다. 설계 검토 시 이 부분을 가장 먼저 본다.

### 6.3 세션 판정 자동 교체 금지

캘린더 API 가 정본이라도 세션 판정을 자동으로 바꾸지 않는다. 세션은 주문 허용·스케줄러 주기·동기화 케이던스에 걸려 있어 외부 응답 하나로 바뀌면 사고 범위가 크다. **불일치 경고 → 사람이 확인 → 코드 수정** 순서를 지킨다.

### 6.4 약관·계정 리스크

- 자동매매 봇의 시세 조회 용도가 이용약관상 허용되는지 **확인 필요**(§7)
- 허용 IP 목록에 서버 IP 가 등록돼 있어야 한다. IP 변경 시 전 경로가 403 이 된다 — 폴백이 아니라 **선행 조건**이므로 기동 시 1회 헬스체크를 넣는다

### 6.5 자격증명 관리

- `.env` 에 `TOSS_CLIENT_ID`·`TOSS_CLIENT_SECRET` 추가(2026-09-15 운영 반영 완료), 커밋 금지(기존 `.gitignore` 적용)
- **토스 OAuth 에는 스코프가 없다.** `/prices` 를 부르는 토큰과 `POST /api/v1/orders`·`/orders/{id}/cancel`·`/conditional-orders` 를 부르는 토큰이 **같은 토큰**이고, 주문에 추가로 필요한 `X-Tossinvest-Account` 는 같은 토큰의 `GET /api/v1/accounts` 로 얻는 정수라 비밀이 아니다. 즉 §8 의 "주문 API 를 쓰지 않는다" 는 **우리 코드의 관례일 뿐 권한 경계가 아니며**, 실효 경계는 **허용 IP 목록 하나뿐**이다.
- 설계 과정에서 시크릿이 평문 전달됐고 재발급을 권고했으나 **사용자 판단으로 현재 키를 유지**한다(2026-09-15). 위 스코프 부재를 전제로, 허용 IP 를 운영 서버 단일 IP 로만 유지하고 IP 변경 절차를 runbook 에 기재한다.
- 로그·원장에 토큰·시크릿이 남지 않도록 마스킹(`team_ledger._mask_secrets` 패턴 재사용)

### 6.6 폴백 실패 경로의 지연

청산 피드는 보유 종목을 순차 순회하는 루프라 **종목당 지연이 전 포지션의 청산 체크 주기로 누적된다**. KIS 단독으로도 이미 3회 재시도 + 지수 백오프가 있는데, 그 뒤에 토스 재시도를 더하면 KIS·토스 동시 장애 시 루프 주기가 크게 늘어난다.

- 폴백 호출에 **짧은 타임아웃**(KIS 대비 절반 이하)과 **재시도 1회 상한**을 둔다
- 연속 실패 N회면 **서킷 오픈**(일정 시간 폴백 시도 자체를 건너뜀). 서킷 상태를 계측에 남긴다
- 폴백은 "없으면 기존과 동일"이 기본값이다 — 폴백 때문에 원래 되던 것이 느려지면 안 된다

## 7. 보류·확인 필요

1. **이용약관** — 자동매매 시스템에서의 시세 조회 허용 범위. 확인 전에는 Phase 2 이상 진행하지 않는다
2. **업종·섹터 분류** — 토스에 필드가 없다. pykrx WICS 대체안을 별도로 찾아야 한다(현재 키워드 12개 폴백은 반쪽)
3. **200봉 상한** — MA200·52주 고가·MRS(252거래일)는 2콜 페이징이 필요하다. 페이징 비용이 KIS 대비 여전히 유리한지 Phase 1 에서 측정
4. **NXT 커버리지 세부** — ETF 등 `nxtSupported=false` 종목의 장외 갱신 부재를 소비자별로 확인
5. **US 확장** — 토스도 US 를 제공하나 이번 범위 밖

## 8. 이번 설계에서 하지 않는 것

- 토스 **주문·정정·취소·조건주문 API 사용** (제공되지만 쓰지 않는다)
- 토스 **계좌·잔고 조회** (KIS 원장이 정본)
- 세션 판정·주문 허용 시간의 자동 변경
- KIS 제거 (토스는 2차 소스이며, KIS 단독 실패 시의 보완재다)
- 수익성 개선 주장 — 이 작업은 **데이터 가용성** 개선이지 전략 개선이 아니다
