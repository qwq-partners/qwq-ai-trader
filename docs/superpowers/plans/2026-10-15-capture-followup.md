## 목적과 범위

종목 선정과 진입 시점의 비용 후 효과를 측정할 유효 표본을 확보한다. 사용자가 요청한 Claude 작업 확인과 기존 후속 개발을 Plan → Do → See로 진행한다. 기준 main은 `e90e3622f45d34e78297b98a4dfe915dc0cfe4f8`이다.

이번 범위는 읽기 전용 실행 증거 확인, 다음 날짜의 설치 코드·격리 시험·문서·PR이다. 운영 배포/재시작/새 예약 설치, 유료 AI 재실행, 텔레그램 재발송은 포함하지 않는다. 소비된 10월15일 자료와 설치기는 보존한다.

## PLAN

1. Claude 09:35 cron의 완료·모델·기록 비용·발송 결과·예약 제거를 대조한다. 보고서의 원장 범위와 전체 시간 주장을 구분하고, 반복 사용 전 필요한 실행기 보강을 기록한다.
2. 별도 고정 프로필 `20261016-llm-window-v1`을 준비한다. 10월16일 09:10~09:12 KST만 활성화하고, capture.start_at=09:15, admission_end_at=09:25, end_at=09:41로 고정한다. 계약상 수집 구간 [09:15,09:41)과 준비 시간을 구분한다. 이전 관측의 once/receipt/status/drop-in 소비 증거를 확인·백업한 뒤에만 미래 예약을 설치할 수 있도록 기존 배타 트랜잭션을 유지한다.
3. 활성화 실행기가 새 epoch·시간·호가/장 상태 몫·메모리·연결 상태를 정확히 확인하게 한다. 배포된 HEAD와 대상 HEAD가 같아야 하며 설치기가 배포를 대신하지 않는다. 과거 프로필 동작을 유지한다.
4. UTC/KST 관련 시험, 전체 verify·비밀정보 검사, 구현자와 다른 최종 리뷰를 거친 뒤 문서·커밋·푸시·PR로 통합한다.

## 고정 계약과 수용 조건

- 소스·설정·실행 PID는 설치 시 확보한 실제 근거로 고정한다. 합성 시험값을 운영 manifest로 사용하지 않는다.
- 새 경로/epoch/once/영수증을 사용하며 과거 입력을 덮어쓰지 않는다. 날짜를 임의 인자로 바꾸는 일반 설치기로 확대하지 않는다.
- 관측 상한은 기존과 동일: 4스캔, 최초5종목, 26분 계약, lease1560초, 호가50000/장 상태50000/기타8000/스캔 메타804, 큐·버퍼110000, 레코드65536바이트, 저장7434242048바이트, 관측 버퍼의 보유 메모리512MiB(프로세스 전체 RSS 상한 아님). 적용 전 가용 디스크 검사를 유지한다.
- 900초 markout·최대 호가 지연5초와 16분 후행 구간은 유한 LLM 응답 지연 전체를 보장하지 않는다. 늦은 응답은 unknown으로 남긴다.
- 실제 전략 enabled/추가 시간·휴장 근거·프로세스 KST·운영 구독 수요·미체결/복구 상태는 설치 직전 별도 확인한다. 약세장 차단 등 기존 조건을 완화해 LLM 표본을 만들지 않는다.
- 합성 원문을 사용해 새 프로필의 준비→시작 요청→실제 CapturePlan 투영→활성화 검증을 연결한다. 옛 시간/새 epoch 혼합, 다른 source/head, 미소비/실패 영수증, 재설치·부분 실패를 거부한다.
- 실측 완료·수익성·실행 비용 확정으로 승격하지 않는다. 새 관측·자동 AI 판독은 아직 예약되지 않았다.

## 역할과 검증

코디네이터는 실제 실행 증거·문서·통합을 맡는다. 별도 Astra/high 작업자는 새 고정 설치기와 활성화 연결·시험만 구현한다. 독립 Astra/high 작업자는 기존 cron 코드만 검토하고, 새 설치 코드의 최종 리뷰는 구현자가 아닌 Astra/xhigh가 맡는다. 실제 모델 metadata 미노출 시 검증되지 않았다고 기록한다. 작업자는 다른 작업자를 생성하지 않으며 운영 자격증명/원장/로그에 접근하지 않는다.
