# 66차 C 후속 — 실제 수량 정책·응답 지연을 반영하는 모델 비교 (2026-10-13)

설계·비용 산정·오프라인 검증 단계다. 운영 모델 교체나 새 유료 비교 호출을 시작하지 않는다. 트레이딩 엔진의 모델 선택(config `llm.*`)을 다루며, 개발 에이전트의 모델 라우팅 정책과는 무관하다. 이전 초안의 전량 거절 라벨·판단 후 수량의 기준수량 사용·모델과 추론 동시 변경은 아래 계약으로 대체한다.

## PLAN — 무엇을 비교하고 무엇을 비교하지 않나

- 현행: Bull = `openai_model_light`(gpt-5-mini, `reasoning_effort="minimal"`, max_tokens 400), Bear = `gemini_model_light`(gemini-3.1-flash-lite-preview, temperature 0, max_tokens 400), 둘 다 판정 불가면 단일 폴백(`STRATEGY_ANALYSIS` 작업 모델, max_tokens 100). 입력은 71차 공통 사실(`entry-llm-input-v1`)+역할 접미. 지원하지 않는 추론 수준을 몰래 바꾸지 않는다.
- **Bull/Bear 는 역할이 다르므로 서로의 응답 차이를 모델 성능 차이로 읽지 않는다.** 비교는 **같은 역할 안에서** 현행 모델 vs 후보 모델(또는 같은 모델의 추론 수준만 변경)로만 한다. 모델 변경과 추론 수준 변경은 별도 후보로 분리한다.
- 입력은 64차 판단 기록의 `common_context`(원문)와 `role_suffix`·역할 시스템 프롬프트 sha256 으로 고정한다. 오프라인 재생 응답은 당시 실제 응답·체결로 표시하지 않는다. 반대 역할의 응답과 최종 집계 규칙도 고정한다. 역할 응답을 최종 엔진 판정으로 바로 간주하지 않는다.

비교 순서와 고정 제어:

1. **R(추론)**: Bull gpt-5-mini minimal/400 ↔ 같은 모델 low/400. Bear·폴백·입력·나머지 제어 동일.
2. **M(모델)**: Bull gpt-5-mini low/400 ↔ gpt-5.6-sol low/400. 최소 추론 수준이 다른 모델을 minimal↔low로 비교하지 않는다. 공급자별 같은 이름의 effort가 동일 계산량을 뜻한다는 주장도 하지 않는다.
3. **O(출력 한도, 필요 시 별도)**: Bull gpt-5-mini low/400 ↔ 같은 모델 low/1200. 이를 추론 상향 효과와 합치지 않는다.

Bear 모델 교체는 위 비교와 별도의 사전 고정 실험이다. 실측 전 후보 수를 늘리지 않는다. `minimal`/`low` 지원 여부는 현재 저장소 `_validate_controls` 검증 기준이며 실제 공급자 호출·응답 품질 검증은 아직 없다.

## DO — 비용 항목과 상한 계산

`src/analytics/model_comparison_budget.py`(순수 함수)가 저장소 `llm_pricing` 단가표를 Decimal로 계산한다(1e-9 단위 올림, 청구 보증 아님). 역할별 호출 비용 → 판단 비용 → 비교 1쌍 비용 → 가용액×(1−예비 비율)에서의 비교 수를 낸다. **expected**는 역할별 1회×1.1이라는 시나리오 가정이다. 과거 6회 중 빈 응답 1회만으로 재시도율의 상한을 추정하지 않는다. **max**는 역할별 최대 2회+폴백 공급자 체인 전체(기본 gpt-5.6-sol 900/100 토큰 및 gemini-3.1-pro-preview 900/100 토큰) 합계다. 비용 입력의 bool·음수·NaN/Inf·비정수 횟수를 거부하고 가격 미확인은 None으로 보존한다.

각 행은 동일 가용액을 독립적으로 쓰는 가정이며 세 행의 허용량을 합산하지 않는다. 입력 900토큰, 출력 R/M 400토큰·O 후보 1200토큰 가정이다. 운영 `_daily_llm_max` 10은 엔진 내부 판단 한도이며 **오프라인 비교 호출에 자동 적용되지 않는다**. 관측 판단 수와 유료 비교의 공급자 시도 수는 별도로 센다.

**표는 실행 허용 상한이 아니다.** 입력 900은 강제 제한이 아니며, 표에는 월 원장의 공급자별 출력 예약 여유 2배가 없다. 비교 전 실측 토큰으로 갱신하고 원장 예약 기준으로 재산출한다. 작은 과거 표본만으로 예산 또는 표본 중 어느 것이 유일한 병목인지 확정하지 않는다.

호출 경계 `model_comparison_execution.py`는 명시 주입한 `MonthlyBudgetLedger`와 불변 `ComparisonExecutionPolicy`를 요구한다. KST 일별 `daily_attempt_cap`·허용 모델·출력 한도를 원장 내 별도 표에 보존한다. **단일 공급자 시도마다** 일 슬롯 확보 → 월 예산 예약 → 전송 → 측정 비용 정산이다. 재시도·폴백도 매번 통과해야 한다. 실패한 시도의 일 슬롯은 되돌리지 않으며, 전송 뒤 취소/불명 비용은 가능한 과금을 0으로 해제하지 않는다. 실험 ID 변경으로 한도를 초기화하지 못하고 기존 월 한도·활성화 기준선도 변경하지 않는다.

이 가드는 실제 공급자 어댑터나 재생 실행기가 아니다. 가짜 단일 전송 콜백과 임시 원장으로 검증한다. 향후 어댑터는 숨은 재시도 없이 요청 모델/출력 한도를 지켜야 하며, 내부 예약과 폴백이 있는 `LLMManager`를 그대로 중첩하면 이중 예약/미계측 시도가 생기므로 금지한다. 실험 정책·하루 시도 수는 아직 운영 설치하지 않았다.

## SEE — 실제 정책과 증분 손익 (`model-comparison-report-v2`)

엔진의 LLM reject는 전량 거절이 아니라 기존 `position_multiplier`에 설정 배율(현재 기본 0.5)을 곱한다. 따라서 비교는 다음을 요구한다.

1. **판단 전 동일 사이징/위험 스냅샷**: 사용 가능 현금·기존 배율·보유/예약·종목 및 전략 한도·가격/위험 입력·소스/설정 지문과 당시 사용 가능 시각. 현재 판단 후 `size_trace.quantity`를 0.5로 나누어 기준수량을 복원하지 않는다.
2. **각 판정의 정책 재생**: approve는 기존 배율, reject는 설정 배율 추가 적용, 예산/타임아웃/파싱 불가의 fail-open도 그 버전 실제 경로를 따라 기록한다. 정수 내림·현금·위험 한도가 있으므로 단순히 수량을 두 배로 만들지 않는다. 재생 근거가 없으면 증분 수량/손익은 null이다.
3. **응답 지연**: 현행과 후보 각각의 완료 시각 뒤 첫 호가를 검증한다. 공통 입력 시점+900초의 **동일 종료 시점**과 그 이후 첫 bid를 주 평가로 사전 고정한다. 기존 H1의 진입 시각+900초 방식과 별도 계약이다. 후보가 늦어졌는데 현행의 빠른 진입 가격을 재사용하지 않는다.
4. **비용**: 각 수량·진입/종료 가격에 같은 명시 `FeeCalculator`·슬리피지 정책을 적용한다. API 비용 USD는 사전 고정 환율/원천으로 KRW 변환할 때만 합산한다. 비용 또는 환율 미확인은 0이 아니다.

순손익 차이 = 후보의 거래비용 후 가격 손익 − 후보 API 비용(KRW) − 현행의 거래비용 후 가격 손익 + 현행 API 비용(KRW). 예컨대 50주와 100주가 같은 가격으로 들어간 비교에서 기회 차이는 추가 50주의 효과다. 이를 100주 전량의 '놓친 거래' 또는 '회피한 손실'로 보고하지 않는다.

`model_comparison_outcome.compare_policy_outcomes`는 별도 검증된 두 정책 재생의 최종 수량과 가격/원천 참조를 받는 순수 계산기다. `quantity_basis=policy_replay`, 같은 선행 스냅샷, 적용 배율, 개별 완료 시각, 첫 호가/장 상태 참조, 공통 종료 시각, 명시 수수료/환율을 검사한다. 입력 일관성을 검사할 뿐 참조 문자열의 진실성·실제 사이징 재생·원장 해시·정상 장 상태를 자체 인증하지 않는다. 정상 입력도 `conditional_price_proxy`, `actual_execution=false`이며 실체결/실현손익이 아니다. 누락 행은 ID·사유·null을 유지한다.

보고서에는 decision/signal ID·종목·stage·역할·요청/실제 모델(없으면 unverified)·추론·원래 판정·실제 정책 결과·수량·지연·토큰·비용·예약 토큰·개별 호가/장 상태/재생 근거를 보존한다. 승인/거절/파싱 불가/예산 차단/호가 미배정/자료 부족의 분모를 구분한다. 경제성 라벨은 '후보 정책의 증분 가격 손익'으로 제한한다.

오프라인 모델 재생의 응답 시간은 과거의 실제 완료 시각이 아니다. 과거 호가에 재생 지연을 더한 결과는 가정 실험으로 별도 보고하고 주 경제성 계산에 넣지 않는다. 실제 지연을 포함하는 비교에는 같은 입력 시점의 paired shadow 응답과 각 응답 이후 시세가 필요하다.

## 시작 조건(이 단계에서 하지 않은 것)

1. 64차 판단 기록이 운영에 배포돼 실제 `common_context`·토큰·응답이 쌓여 있다.
2. 65차 조인으로 평가 가능한 (판단, 첫 호가, 장 상태) 쌍이 최소 1개 확인된다.
3. LLM 대상 새 관측 계약의 배정·용량 검증과 판정 전 스냅샷/정책 재생·공통 종료 가격 증거가 있다. 현재 기록만으로 모든 경제성 입력이 확보됐다고 간주하지 않는다.
4. 실제 단일 요청 어댑터가 월 원장 예약/정산 가드와 모든 재시도·폴백의 일 시도 상한을 통과하는 통합 시험을 마쳤다.
5. 한 가지 비교·표본 선정·일 시도 상한·고정 종료/비용 기준을 정했다. 표의 계산상 쌍 수를 그대로 적용하지 않는다.

그 전에는 유료 비교 호출을 시작하지 않는다. 지금 완료 가능한 것은 관측/가드/조건부 계산의 오프라인 검증이며 실제 수익 비교는 후속 단계다.
