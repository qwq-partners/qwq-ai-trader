# 선정 원천 상태와 중복 입력 진단 — 30차

현재 상태: 로컬 구현·독립 재검토·전체 검증 완료. 운영 미배포이며 10월 2일 예약 대상5468208·설치 입력·매수 중지·운영 설정을 변경하지 않았다. [29차 점수 보존](current-engine-selection-basis-2026-10-02.md) 이후의 후속 작업이다.

## Plan — 좋은 종목을 고른 근거가 실제로 있었는가

목표는 정보원별 점수를 비용 후 이익과 연결할 때, 조회 실패를 정상적인 무후보 결과로 해석하거나 중복 입력을 독립 확인으로 세지 않도록 하는 것이다. 점수 가중치·가산점·필터·매수 조건은 이번에 바꾸지 않는다.

기존 원천 함수는 HTTP/API 오류·파싱 오류를 잡고 빈 목록 또는 부분 목록을 반환한다. 따라서 통합 함수에서 목록 길이만 봐서는 실패/빈 응답/필터 탈락을 구분할 수 없다. KIS 원천 캐시 외에 하위 시장자료 캐시가 있고, 기관/외인 후보는 두 시장 응답을 합친다. 네이버 신고가 후보는 상승률 후보의 파생 자료다.

현재 시도의 원천 상태는 **스캔 전체**에 한 번 기록한다. 후보별 선정 근거는 기존대로 별도 기록한다. 현재 시도가 실패해 과거 통합 캐시를 반환한 경우, 현재 실패를 과거 후보 점수의 획득 근거로 붙이지 않는다. 빈 후보 스캔도 11개 원천의 호출 상태를 남긴다.

## Do — 선택적으로 원천 반환 분기를 기록

기존 호출 안에서 허용된 상태·행수·로컬 시각만 복사한다. 새 조회·재시도·인증·주문은 추가하지 않는다. KIS 병렬 호출 순서, 부분 결과, 네이버 가중치 분기, theme 우선순위로 LLM을 건너뛰는 동작을 유지한다.

| 표시 | 뜻 | 해석하면 안 되는 것 |
|---|---|---|
| completed_empty / nonempty | 필요한 입력의 명시 응답이 확인됐고 기록된 실패 없이 반환 | 응답 내용의 정확성·최신성·투자 우위 |
| cached_empty / nonempty | 원천 자체 또는 하위 입력 캐시를 사용 | 원래 캐시 생성 시 모든 조회가 성공했다는 증명 |
| partial | 실패가 기록됐지만 현재 후보 일부가 반환됨 | 완전한 시장/자료 커버리지 |
| failed | 실패가 기록됐고 현재 반환 항목이 없음 | 해당 종목·시장에 부정적 정보가 있다는 뜻 |
| unknown_empty / nonempty | 하위 함수가 반환했으나 필요한 획득 근거를 확인하지 못함 | 정상0건 또는 정상 성공 |
| not_called | 이 스캔에서 해당 경로를 호출하지 않음 | 호출했으나 기여가0인 경우 |

기관/외인은 두 시장의 명시 응답 또는 입력 캐시 근거가 필요하다. 한 시장 실패와 다른 시장 후보 반환은 partial이다. `raw_count`가0이면 명시 입력이 비어 있었고, 양수인데 반환0이면 입력은 있었으나 최종 반환에 남지 않았음을 뜻한다. 이것만으로 개별 종목의 탈락 사유를 복원하지 않는다. HTML 행수는 표의 행수와 같다는 보장이 없으므로 네이버 raw_count는 불명으로 유지할 수 있다.

`started_at`, `completed_at`, `last_payload_at`은 **로컬 관측 시각**이다. 캐시 경과시간도 로컬 저장 시각 기준이며, provider의 거래소 시각은 항상 null이다. 캐시와 새 응답이 섞이면 cached로 표시하고 각 횟수를 함께 보존한다. theme의 로컬 snapshot은 원천 획득 근거가 없으면 unknown으로 둔다. 원 응답·헤더·토큰·오류문구는 기록하지 않는다.

호출별 ContextVar를 사용하여 병렬 원천과 동시 스캔의 상태가 섞이지 않게 한다. 원천은 고정11개, 호출별 이벤트 최대16개, 수치·필드·시각은 검증한다. 기록 오류·한도 초과는 원래 후보/예외를 보존하면서 원천 근거를 unavailable로 만든다. 저장된 원장의 형식 모순은 평가기가 거부한다.

### 명시 활성화와 호환성

후속 study는 기존 `runner-first-scan-v2` 안에서 다음을 명시해야 한다.

```json
"selection_basis": {
  "version": "selection-basis-v2",
  "max_candidates": 100,
  "max_source_terms": 16
}
```

`selection-basis-v1`은 29차의 후보 계산 근거만 유지한다. 새로운 원천 기록은 v2에서만 켜며 기본은 꺼져 있다. 스캔 레코드에 원천 상태를 함께 넣으므로 행 수는 늘리지 않는다. 최소 레코드 예산은64KiB, 버퍼/큐는 `1+max_candidates`개, 파일 최소 예산은 `(1+max_candidates)×(max_record_bytes+2048)+2048`바이트다. 이는 즉시 발생하는 스캔/선정 근거의 최소치이고 전체 호가 유량/운영 성능의 보장은 아니다. 실제 수집의 자원 근거는 따로 고정해야 한다.

현재 예약의 study/manifest/실행기를 v2로 바꾸지 않는다. 5468208에는 29·30차 기능이 없으며, 새 코드의 관측은 새 평가 세대로 구분한다. 기존 원장을 소급 보완하지 않는다. 새 레코드는 갱신된 reader로 읽는다.

### 평가 연결과 중복 입력 진단

기존 평가 도구의 `selection_basis.source_scans`에 전체 원천 상태가 나온다. 현재 후보의 점수 항은 해당 원천이 실제 반환한 수와 입력 순위에 맞아야 하며, 원천 완료 뒤에 생성돼야 한다. 캐시 후보의 과거 점수 항은 현재 시도의 원천과 교차 연결하지 않고 폴백 표시와 과거 생성 시각만 확인한다. 이 검증은 기록의 내부 일관성이며 외부 사실의 인증이 아니다.

후보별 `lineage`는 알려진 동일 입력 계열만 묶는다. 프리마켓 갭과 KIS 등락률은 같은 등락률 자료 계열이고, 네이버 신고가 후보는 네이버 상승률 계열이다. 서로 다른 계열의 통계적 독립성은 증명하지 않는다. 실제 가산점·가중치와 가격 비교 결과는 그대로 유지한다.

## See — 검증과 남은 일

- 상태/동시성/취소/한도/오류 격리의 실패 테스트를 먼저 작성했다.
- 독립 검토에서 후보 기여 원천의 호출·순위·완료시각 연결과 누적 수치 한도 오류 격리를 지적했고, 반례를 실패 테스트로 고정해 수정했다.
- 관련 통합 검증은 **265개 통과(7.33초)**다. 직접 KIS 두 원천의 성공/빈 응답/전량 미반환/HTTP/API/누락/부분 결과와 LLM·네이버 파싱·캐시·기록 장애에서 기존 반환을 보존했다. 실제 스케줄러의 기본 OFF/v1/v2 전달도 검증했다.
- 원장·분석 재검토177개 통과(5.66초), 최종 중요 경로 독립 검토177개 통과(3.82초)와 실제 원천 경계22개 통과(1.14초), 실제 함수→스캔→원장→reader의 신규 응답/캐시 양쪽을 확인했다. 신규 조회 총1회·캐시 추가 조회0회였으며 남은 P0/P1/P2 지적은 없다.
- 프로젝트 공식 전체 검증은 **3,200개 통과·기존 예상 실패2개(89.23초)**다. 문법·비밀정보 검사 통과, 운영 상태·외부 네트워크 접근 시도0건이다. 기존 pykrx 리소스 접근 방식 폐기 예정 경고1개는 남는다.
- 작업자의 별도 전체 디렉터리 탐색 `pytest -q`에서는 수동 API 스크립트 `scripts/test_new_tr.py`의 `kis_md` fixture 부재2건이 발생했다. 공식 검증 대상 `tests/`와 구분하며 해당 스크립트를 변경하거나 실 API로 실행하지 않았다.
- 합성100후보·11원천 활성 스캔은21,560바이트로64KiB 이내였다. 파일 왕복에서도100후보를 보존했다. 이는 합성 저장 크기 증거이며 운영 CPU·장중 호가 처리량 검증은 아니다.
- 요청 구현 모델은 Terra/high, 원장·분석 리뷰는 Sol/high, 최종 중요 경로 리뷰는 Astra/xhigh다. 실제 모델/실효 effort 메타데이터는 모두 미노출로 미검증이며 다른 제공자 교차 검토로 주장하지 않는다.

추가 인사이트: 현재 `kis_success`는 통신 성공이 아니라 **후보가 하나라도 있는지**로 정해진다. 네이버를 켰다면 정상 무후보도 네이버 가중치 상승 분기에 들어간다. 현재 기본 네이버는 OFF이고 이번에는 그 정책을 변경하지 않는다. 후속 분석은 이런 원천 가용성 분기를 선정 품질과 분리해야 한다.

다음 우선순위는10월2일 기존 수집의 무결성·장 상태 근거 확인과 **동일 진입의 청산 대조 및 현금·슬롯을 반영한 시간순 재생**이다. 보정 단계별 평가/미평가와 후보 처분 기록도 남아 있지만 기록 확장 자체를 수익 검증의 목표로 삼지 않는다. 독립 체결29건·실제 비용·현금흐름을 확보한 계좌 순수익 평가와 전체 KODEX200 비교는 계속 남는다. 반도체 제외·버전·국면 진단은 병기하며, 이번 합성 검증을 실수익 개선으로 판정하지 않는다.
