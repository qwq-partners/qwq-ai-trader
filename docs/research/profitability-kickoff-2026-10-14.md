## 첫 공백과 최소 보완

기존 `report_decision_quotes.py`는 주어진 판단 JSONL의 모든 행을 읽고 종목/시각으로 호가를 연결한다. 하나의 관측 원장에 월 전체 판단을 넣으면 다른 날짜 또는 같은 종목의 다른 신호가 분모에 섞인다. strict 원장 해시 검증만으로 이 문제가 해결되지 않는다.

따라서 별도 오프라인 도구에서 다음을 먼저 수행한다.

1. 명시한 study와 원장의 해시·완전성·관측 계약을 검사한다.
2. 이번 원장의 `llm_check_started` 신호와 배정/재사용 근거로 모집단을 만든다.
3. 판단 입력을 제한 크기의 안정된 바이트로 읽고, 신호 ID·종목·전략·시각을 대조한다. 제외된 다른 판단과 미대응 신호를 모두 집계한다.
4. 이 모집단만 기존 판단/호가 조인기에 전달한다. 장 상태 결측·연결 세대·응답 지연의 기존 판정은 유지한다.
5. 순수익/계좌 수익/운영 적용 가능으로 승격하지 않는다.

관측 원장이 봉인됐고 판단 파일을 안정되게 읽었더라도 별도 비동기 판단 기록기의 큐가 모두 저장됐다는 증거는 없다. 따라서 `decision_recording_finality=unverified`를 유지한다. 시작 신호에 대응 판단이 없으면 `decision_snapshot_unsettled`로 표시하며, 미대응 건수는 해당 스냅샷 시점의 잠정 결측이다. 최종 유실이나 판단0건으로 확정하지 않고 다음 스냅샷과 대조한다. 시작 신호0은 완전하고 유효한 관측 원장으로만 확정할 수 있다.

입력은 읽기 전용이고 결과만 stdout으로 보낸다. 원본 파일 수정, 라이브 봇 flush/종료, 새 API 호출, 판단/주문 정책 변경은 없다. 구현과 시험은 별도 작업자, 최종 리뷰와 통합은 조정자/독립 리뷰어로 분리한다.

### 판독 CLI

격리된 개발 작업 트리에서 실행한다. `--analysis-as-of`는 **실제 판독 시각**을 시간대 포함 ISO 형식으로 넣는다. 아래 09:35는 예정 판독의 예시이며, 봉인보다 이른 시각이면 거부된다.

```bash
/home/ubuntu/projects/qwq-ai-trader/venv/bin/python scripts/report_capture_readiness.py \
  --study /home/ubuntu/.local/share/qwq-entry-observation/20261015-llm-window-v1/study.json \
  --ledger /home/ubuntu/.local/state/qwq-entry-observation/20261015-llm-window-v1/engine.jsonl \
  --decisions /home/ubuntu/.cache/ai_trader/llm_decisions/decisions-2026-10.jsonl \
  --analysis-as-of '2026-10-15T09:35:00+09:00'
```

- stdout JSON/rc0는 판독 수행 성공이며 자료 충족·순수익 통과가 아니다. 잘못된 입력은 stderr 오류/rc2다.
- study는4MiB, 원장/판단은 각각256MiB 이하의 명시 일반 파일만 읽는다. 한도 초과면 중단하고 메모리 사용을 검토한다. study에 선언된 최대 저장 용량으로 분석 한도를 자동 확대하지 않는다.
- 응답 뒤 첫 호가 지연은 study의 `policy.max_decision_delay_seconds`를 따른다(고정 관측5초). `--max-state-age-seconds` 기본5초는 별도 장 상태 신선도 진단 설정이며 study에서 읽은 값으로 위장하지 않는다.
- 결과의 입력 해시·크기와 판독 시각을 함께 보존한다. 상세 JSON은 Git 밖 비공개 위치에만 저장하며, 문서에는 결측·건수·판정 상태만 기록한다.
- `no_llm_checks`는 완전한 해당 저널에 기록된 시작0이라는 뜻이다. 조기 종료 가능성까지 제거한 전체 예정 시간의 무신호 증명이 아니며 `full_coverage=false`를 유지한다. 활성화/실제 종료 시간은 별도로 확인한다.

## 10월15일 — 가격 평가기 연결 보완

### PLAN

사용자가 가격 평가기 연결 보완과 검증을 승인했다. P2의 선행 구현만 수행하며, 09:26 이후 실제 관측 판독과 경제성 분석을 완료한 것으로 표시하지 않는다. 기준은 PR #196 병합 `1e4362e0`이고 격리된 `feature/llm-price-evaluator-20261015`에서 작업한다.

실제 수집기를 사용한 합성 봉인 원장에서 기존 가격 입력 조립기가 `llm_check_started`를 만나 `지원하지 않는 관측 kind`로 종료하는 것을 재현했다. 별도로 실제 3채널 구독 흐름의 `H0STMKO0`가 기존 허용 목록에 없어 완전성 판정을 막는 공백도 확인했다. 이는 전략 성과가 나쁘다는 근거가 아니라 분석 연결 결함이다.

### DO

- `received_entry_input.py`는 기존 `validate_window_contract`의 LLM 신호/배정/재사용·시간창 검사를 먼저 거친다. 이후 시작·배정과 장 상태 원문을 보존한 채 가격 계산에 직접 쓰지 않는 기록으로 처리한다.
- 명시 `capture.channels.market_state_evidence=true`일 때만 `H0STMKO0`의 실제 구독 수명을 허용한다. 기존 ACK 순서·동일 연결/세대·재연결/불명 차단을 유지한다.
- 시작/배정은 `order_ready`가 아니며, 원문 장 상태는 정상 연속매매의 검토 증거가 아니다. 기존 실제 수량·자본·초기 손절·신호 전 REST 목표와 명시 호가별 장 상태 검토를 요구한다.
- 같은 종목에 호가 배정을 재사용해도 원래 스캔의 후보 ID와 순위를 모두 남긴다. 시작하지 않은 후보나 주문 준비에 도달하지 못한 후보도 분모에 보존한다.
- 원본 study 바이트/해시, 봉인 원장의 해시·순서·레코드를 변경하지 않는다. 기존 첫 호가 선택과 0/10/30bps 진입·청산 각각의 슬리피지 진단을 재사용한다.
