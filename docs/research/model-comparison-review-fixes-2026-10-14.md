# PR #190 후속 결함 6건 — 2026-10-14

목적은 같은 후보의 모델 판단을 비교할 때 **실제 응답 이후 가격과 비용을 반영한 순성과**를 신뢰할 수 있게 만드는 것이다. 이번 범위는 기준 `491f613`에서 재현한 P1 1건·P2 5건의 수정이다. 구현 완료와 수익성 입증을 구분한다.

| P2 | 같은 프로세스의 새 작업자가 저널 ID·번호 재사용 | 작업자별 ID, 중복/결손 감지, 새 실행의 열린 상태 유지 |
| P2 | 손상된 incomplete 파일이 빈 기록으로 바뀌어 0원 확정 | CLI부터 보고서까지 결손 상태 전달, 총지출 null |

동일 기준 SHA의 분리 작업공간에서 종료/기록·비용 복구·보고서를 나누고, 조정자가 문서와 통합을 맡는다. 운영 주문·배포·재시작·설정·예약 및 유료 비교 실행은 이번 범위에 없다.

## DO — 코드와 처리 흐름

- 작업자: 새 접수 차단 → 남은 작업 처리/취소 → 늦은 복구 행·상태 전이 기록 → 생산자 종료 확인 → 저널 배출·봉인. 제한 시간에 생산자가 남으면 `alive=true`, `journal_drained=false`로 반환한다. 강제 프로세스 종료나 디스크 고장을 견디는 무손실 보장은 아니다.
- 저널: 인스턴스별 `run_id`와 파일별 번호를 사용한다. 봉투 attestation의 프로세스 ID는 별도다. 중복 번호는 손상으로 세고, 종료 후 거절된 offer로 이미 봉인한 스트림을 다시 열지 않는다.
- 비용: 예약과 시도 연결은 같은 트랜잭션에 저장한다. COMMIT 성공 여부가 불명확하면 이미 저장된 연결을 보존하고 자동 정산/재전송 없이 증빙 대사를 기다린다. 대사 후 응답이 없는 시도는 비용만 복구하며 다시 호출하지 않는다.
- 보고: 실제 입장한 실행을 표본으로 집계하고, incomplete 저널의 결손을 `incomplete_journal`에 노출한다. 총지출이 불명이어도 집계 가능한 비용은 `known_subtotal_usd`로 남긴다. 이 부분합에는 원래 API 추정액도 포함될 수 있으며 청구서 확정액을 뜻하지 않는다. `subtotal_uses_original_estimate`와 기존 추정/대사 근거를 함께 본다. 저널 중복·충돌 건수도 진단 필드로 전달한다.
