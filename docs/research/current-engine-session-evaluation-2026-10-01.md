# 실제 호가 근거 연결과 평가 기준 — 28차

현재 상태: **오프라인 근거 연결 도구 구현, 실제 장 상태 근거는 미확보**.10월2일 수집 예약은 유지한다. 수집 준비, 명시 입력 계산, 원천 확인, 실제 계좌 순수익은 각각 다른 완료 조건이다. 이 단계에서 매수 재개나 추가 수집을 승인·예약하지 않는다.

목표는 종목 선정과 진입 시점의 강점을 실제 비용 차감 이익으로 연결하는 것이다. 당장의 우선순위는 기존 원장에서 평가가 막히는 이유를 명시하고, 결과를 보기 전에 연구 기준을 고정하는 일이다. [구현 계획](../superpowers/plans/2026-10-01-session-evaluation-readiness.md)에 이번 범위를 기록했다. [27차 PDS](current-engine-remaining-pds-2026-10-01.md)의 계좌/벤치마크 원천 미확보 항목은 계속 남는다.

## Plan — 확인된 공백과 선택한 범위

현재 비교기는 진입 호가의 `quote_session`과900초 평가 호가의 `markout_session`을 요구한다. 장 상태 근거가 없으면 정상 저장된 가격만으로는 계산을 완료하지 못한다. 합성 리허설에서 진입 근거만 제거하면4후보 모두unknown·비교0쌍, 평가 근거만 제거하면 가격 게이트 통과1/미진입2를 유지하면서 손익 비교0쌍이 됐다.

공식 자료를 조사했지만 기존 필드로 정상 연속매매를 자동 확인하는 규칙은 만들 수 없었다. 이에 **명시 검토 근거의 연결과 부족한 입력 보고를 구현**했다. 원천의 사실을 만들어 채우는 코드나 검증 조건을 완화하는 코드는 넣지 않는다. 자동 장 상태 수집은 별도 공식 코드표·초기 상태·유실 검사 계약을 확보한 뒤 후속 수집에서 다룬다.

## Do — 명시 근거를 연결하는 오프라인 도구

[준비 CLI](../../scripts/prepare_entry_evaluation.py)는 수집 당시 study의 **원문 SHA**로 원장을 먼저 읽는다. 이후 [조립기](../../src/analytics/entry_evaluation_bundle.py)가 study 원문을 직접 검증·해석하여 변형된 정책을 원본으로 표시하지 못하게 한다. 전체 후보와 원래 순서를 유지하고, 각 후보의 첫 진입 호가·900초 첫 평가 호가·기록 지문·부족한 근거를 출력한다. 잘못된 첫 호가를 뒤의 좋은 호가로 바꾸지 않는다.

명령은 새 분석기가 있는 별도 연구 checkout에서 실행한다. 예약된 제품 커밋5468208이나 설치 파일을 바꾸지 않는다. 아래 꺾쇠 부분은 검토한 파일 경로로 바꾸는 설명 자리다. 도구는 지정한 파일만 읽고 stdout으로 출력하며 네트워크/원본 변경은 없다.

```bash
python scripts/prepare_entry_evaluation.py \
  --journal <수집된-engine.jsonl> \
  --study <수집당시-study.json> \
  --max-journal-bytes 67108864
```

처음에는 근거 파일을 주지 않는다. 결과의 `binding`과 `review_tasks`를 읽어 실제로 필요한 호가를 확인한다. `UNREVIEWED`는 정상 세션이 아니다. 검토 결과가 있으면 같은 명령에 `--session-review <검토파일.json>`을 추가한다.

검토 문서는 `version=entry-session-review-v1`, 원래 `dataset_kind`, 출력된 `binding`, `quotes` 배열을 가진다. binding에는 study/decoded observation 지문·capture ID·epoch가 들어간다. quote별 필드는 다음과 같다.

| 필드 | 요구사항 |
|---|---|
| `quote_id`, `symbol`, `record_sha256` | 출력된 해당 원본 호가와 정확히 일치 |
| `session` | `KRX_REGULAR_CONTINUOUS`, `AUCTION`, `VI`, `HALT`, `UNKNOWN` 중 실제로 확인한 상태 |
| `basis` | `external_event_history_review` 또는 `official_per_quote_status_review`. 시계/시간 코드만의 추정은 지원하지 않음 |
| `source_ref`, `source_sha256` | 검토한 외부 근거의 식별자와 원문 지문 |
| `reviewer_ref`, `reviewed_at` | 근거를 검토한 주체와 시각. 호가 관측 이후이며 정책 고정시각과 별개 |
| `valid_from`, `valid_until` | 같은 KST 날짜에서 해당 호가의 수신~관측 구간을 포함하는 상태 유효 범위. 종료는 제외 |

도구는 식별자·지문·시간·형식의 일치를 확인한다. **검토자의 진술이나 외부 자료의 진실성을 인증하지 않는다.** 출력의 `source_authenticity_verified=false`를 유지한다. 근거가 없거나 의미가 불분명하면 검토자가 `KRX_REGULAR_CONTINUOUS`라고 작성해서는 안 된다. 원장 지문은 외부 자료의 신뢰성 검증을 대신하지 않는다.

근거가 연결되면 기존 계산기에 넣을 `evaluation_inputs`, 원래 정책 결과, 양방향0/10/30bp 파생 결과와 별도 지문을 한 번에 출력한다. `evaluation_inputs`만 저장해 기존 [비교 CLI](../../scripts/compare_entry_price_shadow.py)에 넣어도 같은 원래 정책 손익이 나온다. 근거가 하나도 없는 후보는 입력 목록에서 제외하되 전체 후보/검토 목록에는 남는다. 한쪽 근거만 있는 부분 입력도 계산 완료를 뜻하지 않으며, `missing_required_session_evidence_candidates`에 양쪽 근거를 갖추지 못한 후보 수를 별도로 표시한다. 민감도3개는 같은 표본을3번 계산한 것이며 표본 수를3배로 세지 않는다.

`no_comparable_pairs`, `partial_price_diagnostic`, `complete_price_diagnostic`은 **주어진 검토 입력 아래의 계산 가능 범위**다. 외부 근거 인증·수익성 통과·실제 체결 여부가 아니다. 계좌 수익은null, 자동 투자 적격은false로 유지한다.

## 결과를 보기 전에 고정하는 연구 기준

아래 숫자는 현재 과거 성과에 맞춰 최적화한 값이 아니라 **보수적인 연구 기본값**이다.30쌍·10일이 통계적 검정력을 보장하지 않는다.10월2일에는 투자 우위를 판정하지 않고, 새 기준을 기존에 본 기간에 소급 적용하지 않는다.

### 1.10월2일: 품질 pilot

- 원래 후보 수/순서·study/epoch 연결 일치, 알려진 저장/연결 유실0, 봉인과 별도 종료 증거를 확인한다. 원장 reader의 구조상 봉인과 실제 fsync 확인을 구분한다.
- 원래 상위 `min(3,N)` 관측 대상과 실제 대상이 일치해야 한다. 각0/10/30bp에서 완전한 가격 비교가1쌍 이상이면 해당 부분집합의 가격 진단이 가능하다.0쌍이면 원인을 보고하며 전략 실패/현금 수익0으로 간주하지 않는다.
- 전체 후보 중 관측하지 않은 후보는 계속unknown이다. 예를 들어100개 중3개만 관측하면 나머지97개가 남아 전체 개선손익은null이다. 부분집합에 대한 계산 가능성과 전체 후보의 완전성을 따로 보고한다.
- 이 날은 장 상태 근거를 확보하지 못할 수 있으므로 **가격 비교 완료를 보장하지 않는다**. 후보/호가 수집과 결측 원인 점검 결과도 다음 수집을 설계하는 자료로 남긴다.

### 2. 후속 가격 진단: 제한된 개선 가설의 추가 연구 여부

연구 기간은 **2026-10-06~2026-11-03 KST**, 첫3개 반환 순서에 속한 후보만 진단 대상으로 고정한다. 이 날짜 고정은 수집 실행 승인이 아니다. 기동/장 상태 근거/연속 관측 계약이 준비되지 않아 필요한 자료를 얻지 못하면 결과는자료불충분이다. 결과를 보고 종료일을 늘리지 않는다.

- 동일 코드·실효 설정·선정/프롬프트·비용/가격 조건의 평가 세대에서 **완전 비교30쌍 이상, 서로 다른 KRX 거래일10일 이상**. 준비 실패·빈 scan·무신호·미관측일도 원래 예정일/후보 집계에 남긴다. 다른 버전의 표본을 이어 붙이지 않는다.
- 선정된 진단 부분집합의 모든 후보에는 명시 처분 상태가 필요하다. 실제 미진입 근거가 있으면0 현금 결과가 가능하지만, 신호/주문 기록 부재만으로 이를 추정하지 않는다. **해결되지 않은 결과 누락은0건**이어야 긍정적인 경제적 결론을 낸다. 현재 원장이 이 요건을 충족하지 못하면 후속 처분 기록 설계가 필요하다.
- 원래 후보 수/부분집합 수/알려진 미진입/unknown/비교 쌍 수를 모두 보고한다. 전체 후보unknown은 별도 분모에 남기며 이 기준이 전체 종목 선정 능력을 통과시키지 않는다.
- 주 지표는 A의 동일 요청수량 진입비용을 분모로 한 후보별 `x=(B순손익−A순손익)/A진입비용`이다. A진입비용이 양수인 완전 가격 쌍에서 계산한다. 공통 선행 조건 때문에 A/B 모두 미진입했다는 명시 근거가 있으면 그 후보의 차이와 B단독 지표는0으로 정의하되 가격 비교30쌍에 세지 않는다. 한쪽만 진입 가능한지 불명확하면 누락이다. B단독 지표도 같은 A진입비용으로 정규화하여 규모가 다른 후보의 원화 손익을 바로 평균하지 않는다.
- 예정일은 위 기간의 공식 KRX 정규 거래일 전체다. 첫 관측 전에 해당 달력과 날짜별 상태표를 고정한다. 후보가 있는 날은 원래 상위 `min(3,N)` 전체 후보의 지표 평균을 `y_d`로 삼는다. 정상 실행되어 실제 빈 scan임을 확인한 날은 `y_d=0`; 후보가 있지만 모두 공통 선행 조건에서 명시 미진입한 날도0이다. 수집 미실행·자료 유실·미확인 무신호·해결되지 않은 후보는0이 아니라 누락이며, **예정일 중 누락일이 하나라도 있으면 긍정 결론/CI 판정을 중단**한다. 가격 쌍이 존재하는 날짜도 별도로10일 이상이어야 한다.
- 정해진 종료일에 한 번 평가한다. 주 평균은 예정 KRX 날짜 수 `D`에 대해 `sum(y_d)/D`다.95% 구간은 빈 날의0을 포함한 날짜 순서를 압축하지 않고5거래일 길이의 순환 이동 블록으로10,000번 복원추출한다. 분석 시작 시 NumPy `rng = Generator(PCG64(20261001))`를 한 번만 생성한다. 동일 rng에서 반복마다 새로 `ceil(D/5)`개의 시작 인덱스를 `[0,D)`에서 균등 추출하고, 각 시작점의 연속5개를 modulo D로 연결한 뒤 앞D개를 택해 평균한다.10,000회 동안 rng를 재초기화하지 않는다. 날짜 벡터는 각 비용 시나리오의 B−A와 B단독 지표별로 따로 만들고, 같은10,000개 날짜 인덱스 표본을 공통 적용한다. 원래 D개 분모를 유지하고 분위수 방식linear로2.5/97.5%를 구한다. 날짜 간 의존성을 모두 해결한다는 보장은 없으며 보조 날짜별 결과도 제시한다. 중간 결과는 품질 점검만 한다.
-0/10/30bp 모두에서 B−A 평균과 B 단독 비용 후 가격손익 평균이 양수이고, B−A의95% 구간 하한이0보다 커야 다음 계좌 재생 연구의 근거로 삼는다. 각 비용 시나리오의 가장 큰 양의 후보별x 3개를 제거한 민감도에서도 B−A가 양수여야 한다(양의 후보가3개 미만이면 있는 만큼 제거, 동률은 날짜/반환 순위/candidate ID 오름차순). 해당 날짜의 남은 후보로 일평균을 다시 계산하며, 제거로 빈 날짜는0을 사용해 예정일 D를 유지한다. 제거 후 **가격 쌍27개·가격 쌍이 존재하는 날짜10일 이상**을 별도 연구 하한으로 고정한다. 미달은 민감도자료불충분이며 다음 단계의 긍정 근거가 아니다. 이 민감도는 주 결과의 분모를 바꾸지 않는 별도 표다.
- 완전 자료에서 B−A 평균 또는 B 단독 순손익이0 이하이면 해당 기준의 개선 근거 미달이다. 구간이0을 걸치거나 민감도만 불안정하면 우위 미확정이다. 자료가 부족하면 기각이 아니라자료불충분이다. 어떤 경우에도 결과를 보고 가격 조건/기간을 고쳐 같은 표본에서 재합격시키지 않는다.

30쌍은 상위3개/일이 모두 유효해도 최소10일이 필요하다. 이번 하루 pilot으로 충족할 수 없다. 이 단계의 결과는15분 가격 진단이며 실제 청산 수익으로 승격하지 않는다. 위 통계 집계는 이번 CLI에 구현하지 않았으며, 준비 계약과 실제 자료를 확인한 뒤 별도 검증한다.

### 3. 미관측 확인과 실제 투자 판단

확인 기간은 **2026-11-04~2026-12-01 KST**로 분리한다. 최소30쌍·10거래일을 다시 요구하며10월2일/앞선 진단 자료를 합치지 않는다. 같은 통계·비용·누락 기준을 유지한다. 진단 이후 정책/버전이 바뀌면 이 확인 실험은동일 가설 확인으로 부르지 않고 미시작/중단으로 기록한다. 새 규약은 아직 보지 않은 별도 기간에만 적용한다.

실제 투자 판단에는 추가로 다음이 **전부** 필요하다. 하나라도 없으면 `promotion_ready=false`다.

1. **정책 결과와 독립적으로 고정한 전체 기간의 모든 대상 후보 시간순 스트림**을 모집단으로 하는 A/B 계좌 원장. A에서 자본/슬롯으로 막힌 후보도 B에서 나중에 진입할 수 있으므로 제거하지 않는다. 모든 후보에 A/B별 처분·현금·예약·슬롯 상태를 기록한다. 전 후보에게 `order_ready`를 요구하지 않되, 어느 정책에서든 후속 상태를 바꿀 수 있는 미해결 행이 하나라도 있으면 승격 불가다. 같은 진입의 실제 청산 상태/부분체결/취소/갭 체결과 자본 재사용을 재현한다.
2. 독립 실제 체결·수수료/세금·입출금/분배금/평가액과 운영비.29건의 독립 대사 및 수동 보유 귀속도 포함한다.
3. 같은 기간·자본·현금흐름의 전체 KODEX200 총수익 비교. 반도체 제외는 원인 진단으로 함께 보고하며 전체 투자 기회비용을 대체하지 않는다.
4. 실제 비용/운영비 후 B순이익·B−A·전체 KODEX200 대비 초과수익이 양수. 확인일을 시간순3블록으로 나눠 마지막 블록에 나머지 날짜를 배정하고, 블록별 B−A는3개 중2개 이상 양수. 전체 B−A의 사전 고정95% 구간 하한>0. 계좌 최대낙폭의 A 대비 악화는1%p 이내라는 보조 연구 기준을 적용한다.
5. **계좌 전체의 절대 허용 최대낙폭과 운영 투입 한도는 사용자 확정 필요**. 현재0.7%는 선언된 건당 위험,18%는 종목 비중이며 계좌 최대손실 한도로 바꾸지 않는다. 이 값은 미확정으로 남고 실제 투자 승격은 계속 불가다. 상대 낙폭1%p 기준은 큰 절대 손실을 허용하는 근거가 아니다.

날짜·표본·상대 낙폭 기준은 연구의 선택이며 수익 보장이나 실거래 위험 허가가 아니다. 계좌 재생과 승격 검사는 아직 구현하지 않았다. **계좌 단계 규약은 아직 완결된 사전등록이 아니다.** 계좌 자료를 보기 전에 외부 현금흐름 처리·분배금 재투자/현금 처리·평가 기준시각과 계좌 수익 CI의 추정량을 별도로 고정해야 하며, 위 가격 진단의 후보 지표를 계좌 수익 CI로 재사용하지 않는다. 위 확인 기간의 수집도 이번 작업에서 예약하지 않는다.

## 다음 구현에 사용할 설계 경계
