# 현재 엔진 31차 — 같은 진입의 초기 손절 효과

## Plan: 목적과 설계

좋은 종목과 진입을 실제 순수익으로 연결하려면 청산이 보탠 효과를 분리해야 한다. 같은 후보·첫 진입 호가·수량을 고정하고 **관측된 초기 손절 vs 사전 고정 시점까지 보유**의 비용 후 차이를 계산한다. 종목 선정/가격 조건 통과 여부로 유리한 후보만 다시 고르지 않는다. 기존 가격 조건이 `cash`인 후보도 원래 엔진 진입이 유효하면 비교한다.

이것은 **bid 경로의 초기 손절 진단**이다. 실제 엔진 전체 청산 재생, 계좌 수익률, 최적 손절값 탐색이 아니다. 현재가 PRICE 트리거, 체결 뒤 손절 조정, ATR/추적 손절, 부분 익절, LLM, 미체결·동기화·마감 청산과 자본 재사용은 재현하지 않는다. 일봉 경로를 만들어 실시간 근거를 대신하지 않는다.

### 고정 계약

- 입력: 기존 원본 study bytes·원장·`entry-session-review-v1`, 별도 명시 비교 정책. 기존 입력과 예약은 수정하지 않는다.
- 정책: `version=same-entry-initial-stop-bid-v1`, `policy_ref`, `study_sha256`, `fixed_at`, `max_quote_gap_seconds`만 허용한다. 최대 간격은 양수이며 원래 horizon 이하. 지문은 원본 study와 일치해야 한다. 고정 시점이 해당 진입 판단 뒤면 그 후보는 unknown이다. 시각 주장은 사전등록의 독립 인증을 뜻하지 않는다.
- 원래 study의 horizon·수수료·슬리피지·자본 한도와 `order_ready.effective_stop_pct`를 재사용한다. 초기 손절은 순손익률 기준이며 진입시점 예상값이다. 수수료를 손절률에 다시 가산하지 않는다.
- 첫 진입 호가부터 고정 horizon의 첫 KRX 호가까지 수신 순서대로 평가한다. NXT 호가는 KRX 경로에 섞지 않는다. 각 호가의 외부 세션 근거, 같은 거래일, 수신/관측 시각 단조성, 전달 지연, 양수 bid/ask·비교차, 정수 bid 잔량≥공통 수량을 확인한다. 진입 직후 스프레드/비용만으로 손절에 도달하는 경우도 포함한다.
- 손절 트리거는 표시 bid에서 계산한 순손익률 `<= -effective_stop_pct`. 가상 매도가는 최초 도달 bid에 매도 슬리피지를 적용한 값이며, 손절 기준 가격에 체결된 것으로 보정하지 않는다. 상대안은 원래 horizon의 첫 호가에서 같은 비용으로 계산한다.
- 첫 불량/불명 호가를 건너뛰지 않는다. entry→horizon 사이 하나라도 검증되지 않거나 사전 최대 간격을 수신 시각 또는 관측 시각에서 초과하면 pair 전체를 unknown으로 보존한다. 한쪽의 빠른 종료를 근거로 나머지 경로 결측을 숨기지 않는다. 제한 이내 간격도 시장 이벤트 무유실을 증명하지 않는다.
- 모든 후보가 분모에 남는다. `stop_minus_hold_net_pnl` 양수=손절의 손실 방어 효과, 음수=보유 대비 기회손실. 알려진 pair 합계와 전체 후보 합계를 분리한다. 비교 가능 pair가0이면 두 합계 모두 null이고, unknown이 있으면 전체 합계는 null. 동시에 발생한 후보 손익의 단순 합계는 실제 투자 가능한 포트폴리오 성과가 아니다.
- 원래 비용 및 기존 0/10/30bp 양방향 민감도를 동일 계약으로 계산한다. 각 시나리오의 매수 슬리피지 적용 진입가로 trigger를 다시 계산하고, 표시 bid에는 매도 슬리피지를 넣지 않는다. trigger 뒤 평가 매도가에만 매도 슬리피지를 적용한다. 비용별 기존 진입/자본/종단 유효성을 각각 재사용한다. `production_eligible=false`, `profitability_established=false`, `account_return=null`을 유지한다. 토스 통합/LOSSY 호가를 KIS KRX 경로로 바꾸어 넣지 않는다.

### 코드에서 확인한 평가 한계

현행 `ExitManager.update_price`는 최고가 갱신 후 보유기간·stale·초기 손절·부분 익절·본전/추적·복합 조건을 순서대로 처리한다. WS 현재가, REST fallback, batch, EOD LLM은 입력과 추가 청산 조건이 다르다. 따라서 일봉의 high/low 도달 순서나 BOOK bid만으로 전체 엔진과 같다고 판정할 수 없다.

- `src/strategies/exit_manager.py:529`: `price_history`가 있으면 동적 ATR 손절을 산출하지만 `atr_pct_hint`만으로는 초기 동적 손절을 만들지 않는다. 후자는 추적 손절에 사용한다.
- `src/schedulers/kr_scheduler.py:3143`: 신규 체결 등록은 hint 경로다. `scripts/run_trader.py:714`의 기동 시 기존 포지션 등록은 history를 전달한다. 재시작 전후 같은 손절 정책이라고 가정하지 않는다. 이 차이는 기존 특성화 테스트에도 기록돼 있으며 이번에 변경하지 않는다.
- `src/core/engine.py:654`: 포지션 성과 원장의 SELL 기록에 `reason`을 넘기지 않는다. 이 원장의 사유 공백을 실제 청산 사유로 추정하지 않는다. 다른 journal과 실제 체결 대사는 별도다.

직접 실행한 기존 청산 특성화·live/backtest parity 검증은 **54 passed / 2 xfailed(2.27초)**다. 기존 예상 실패는 비용 후 손절과 가격하락률 손절의 차이, 일봉 high-touch와 live tick의 차이를 드러낸다. 별도 분석자의 관련 확대 검증은70 passed/2 xfailed이며 coordinator 결과와 합산하지 않는다. 운영/외부 네트워크 접근 시도0건이었다.

### 사용 범위

CLI는 원본 `--study`, `--journal`, `--max-journal-bytes`, 선택적 `--session-review`에 `--exit-policy`를 더한다. 경로를 자동 탐색하지 않는다. 비교정책 파일은 원본 study SHA와 이미 고정한 최대 호가 간격을 명시해야 한다. 검토 파일에는 진입/종단뿐 아니라 **중간 KRX 경로의 모든 호가**가 필요하다. 당시 기록하지 않은 호가나 장 상태를 나중에 생성하지 않는다.

현재 비교는 기존 진입 평가기의 `live_screening/gap_and_go`·자본·목표 스냅샷 검증 범위 안에 있다. 다른 경로 또는 진입 필수 자료가 부족한 후보는 분모에 남지만 비교 불명이다. 토스 KRX+NXT LOSSY 자료나 10월2일 pilot의 성공 상태만으로 이 요구가 충족되지는 않는다. 이 구현은 수집 실행이나 후속 실험의 완결된 사전등록을 추가하지 않는다.

## 다음 투자 판단

실제 원본 경로가 확보되면 손절이 방어한 손실·반등에서 잃은 이익을 같은 진입별로 확인한다. 그 뒤에만 변동성 대응 손절과 포지션 크기를 한 세트의 새 가설로 사전 고정한다. 손절 폭만 넓혀 동일 수량의 위험을 늘리지 않는다. 전체 KODEX200 기회비용, 반도체 제외 보조 비교, 엔진 버전/시장 국면을 함께 보고 종목 선정·진입·청산·비용의 기여를 분리한다.
