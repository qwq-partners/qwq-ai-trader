## PLAN — 중단 범위를 비용 불확실성과 구분한다

기존 task에는 Gemini light → OpenAI light 경로가 있었지만, 전송 후 시간 초과는 일별 `cost_missing`과 월별 `unknown`을 동시에 만들었다. 이 때문에 한도가 남아도 대체 호출까지 중단됐다. 사용자 요청에 따라, 비용을 만들어 정산하는 대신 검증된 상한을 별도로 점유하는 경로를 추가한다.

범위는 native Gemini의 정식 `gemini-3.1-flash-lite`, Standard 단일 후보·텍스트 `generateContent`, 도구/명시 캐시/연속 호출 없음이다. `maxOutputTokens`는 추론 포함 출력 제한이다. 입력 전체 허용량1,048,576토큰을 사용해 느슨하지만 사전에 계산 가능한 공개 단가 상한을 만든다. 입력USD0.25/M·출력USD1.50/M이므로 출력100이면USD0.262294, 기본출력16,000이면USD0.286144다. 정상 응답에서는 실제 보고 토큰 기반 추정액만 남는다. 상한은 공급자 청구서·세금·환율을 포함한 보장이 아니다.

Google은 기존 `gemini-3.1-flash-lite-preview`가2026-05-25 종료됐다고 명시한다. 일반 기본 슬롯/YAML은 stable로 옮기고 새 월 예산 입장은 preview를 거절한다. 이 공용 light 슬롯을 쓰는 테마/뉴스뿐 아니라 Bull/Bear 등도 새 기본 모델의 영향을 받는다. 고정 역할과 이미 등록된 비교 명세는 자동 치환하지 않으며, preview로 고정한 비교는 새 명세 없이는 입장할 수 없다. 모델의 실전 예측력 동등성은 검증하지 않았다. 과거 원장/보고용 계열 요금 추정은 삭제하거나 확정 요금으로 승격하지 않는다. 이 공개 문서만으로10월16일 시간 초과 원인을 모델 종료라고 확정하지 않는다.

## DO — 코드와 처리 흐름

1. `MonthlyBudgetLedger.reserve(..., timeout_hold_contract=...)`가 검증된 모델·상한·요금·시각을 보조 표에 같은 트랜잭션으로 저장한다. 기존8열 원장과 미확정 이력은 유지한다.
2. Gemini가 명시적으로 분류한 전송 시간 초과이고 알려진 인증/권한 오류가 아니면 `settle(outcome='timeout')`로 전환한다. 원래 행은`unknown`, 실제비용은null, 별도상한만 보류한다. 취소·프로세스 상실·불완전 사용량·미검증 모델은 기존 차단을 유지한다.
3. 가용액은 월 정산 추정액+진행 중 예약+미확정 보류액을 차감한다. 보류액은 재시작/월 경계에서 지워지지 않고80/95/100 정책에도 포함된다. 아직 응답을 기다리는 인증 예약도 전월부터 이월해, timeout 전환 순간 새달 예산을 뒤늦게 초과하지 않게 한다. 별도 대체 호출은 이 가용액 안에서 새 예약을 얻어야 한다.
4. 일별 요약·시도 기록·감사·정책 알림은 미확정 비용과 보류액을 구분한다. 대체 응답은 OpenAI의 실제 응답으로 남고 Gemini 성공으로 표시하지 않는다.
5. task의 기존 fallback은한 번만 사용한다. 시간 초과를 포함한 JSON 호출에서는 추가 복구/섀도우 호출을 늘리지 않는다. `complete_with`와 고정 역할은 자동 공급자 변경 없이 원래 모델 정체성을 유지한다.
6. 후일 귀속 가능한 증빙이 오면 기존 대사 경로로 보류를 실제 보고 비용 추정/확정 금액으로 바꾼다. 상한 초과는 별도 지속 차단이며 자동해제하지 않는다. 이전 버전으로 되돌아가면unknown을 다시전역차단하는 방향으로 동작한다.

상한 인증은 현재 코드의 좁은 요청 형태에 의존한다. 도구·유료 캐시·후보 수·서비스 등급·모달리티를 바꿀 때 인증을 재검토해야 한다. 반복 장애용 별도 공급자 circuit breaker는 이번 범위에 없으며, 각 논리 요청의 한 번 fallback과 기존 일/월 예산이 추가 지출을 제한한다. 일별 한도는 기존처럼 프로세스 로컬 사후 검사이며 엄격한 전역 한도가 아니다.
