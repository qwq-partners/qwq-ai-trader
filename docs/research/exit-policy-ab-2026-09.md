## 0. 한 줄 판정

- 본 그리드(2×2×2)에서 baseline(`ladder/current/nominal`)을 **두 윈도우(6·12개월) 모두** 이긴 셀은
  sepa 단독 그리드의 **`ladder/current/risk` 하나** — 청산·보유는 그대로 두고 **사이징만 위험 기반**으로
  바꾼 셀. 기대값 +0.71→+1.09%(6m)·+0.79→+0.97%(12m), PF 1.06→1.29·1.17→1.39, MDD -21.6→-5.9%·-28.7→-11.2%,
  연회전 78→34~43배, 수수료 드래그 절반, WF 2/3·2/3. 상위 3건을 빼도 12m 순손익이 양수인 유일한 셀.
- **채널 청산(권고 1)은 현행 보유 규칙(stale 5d·stale_high 3d·max 10)과 결합하면 개선 없음** — 채널이
  자리 잡기 전에 stale 규칙이 먼저 자른다. 보유 규칙을 전부 떼면(보충 `none`) 기대값 +5~6%/건·PF 1.7~2.1로
  게이트를 통과하지만 n=36/77, 상위 3건이 이익의 58~72%, 순손익이 top3 제외 시 음수, nominal 사이징 쌍둥이 셀은
  -22~-33% → **아웃라이어·베타 의존, 채택 불가** (harvest shadow 관측 지속).
- **회전 억제(권고 2, extended)는 기각** — ladder와 결합 시 전 윈도우·전 그리드에서 악화(sepa 6m -28%, 12m -22%).
- 권고: **위험 기반 사이징(equity×0.7%/stop, 상한 18%, 동시 7)만 게이트·canary 경유 적용.**
  `ExitConfig`·`REGIME_EXIT_PARAMS`·보유 규칙은 **변경 없음**.

## 1. 방법

### 1-1. 백테스터 3축 (기본값 전부 기존 동작 — 진화 게이트 `backtest_gate.py` 호환)

| 축 | 값 | 의미 (`BacktestConfig`) |
|---|---|---|
| `exit_policy` | **ladder** (현행) | 분할익절 10%/10%·15%/40%·25%/35% + 본전보호 + ATR 연동 트레일링(4.5%) + 레짐 보정. A/B에선 실엔진 미러로 **복합 청산**(1차 익절 후 MA5-0.5%/전일저가 이탈 전량, `enable_composite_exit`)과 **익절 후 저효율**(5일·0<수익<3%·신고가 3일 실패, `post_exit_stale_days`)을 켬 |
|  | **channel** | 진입 시 하드스톱 = ATR×2 클램프 4~8% 고정 → 이후 스탑 = max(하드스톱, 선행 10일 저가); 고가가 진입가×1.30 이상이면 20일 저가로 승격; 종가 < 채널이면 종가 청산(갭 관통은 시가, 저가 관통은 스탑가). 분할익절·본전·복합·고정 트레일링 없음. `src/strategies/harvest_shadow.exit_step` / `scripts/backtest_t1_gate.simulate_exit`와 동일 의미(EOD 근사) — `channel_exit()` 순수 함수, 단위 테스트 8건 |
| `holding_policy` | **current** | stale 5일 ±2% · stale_high 3일 <3%(실엔진 SEPA 오버라이드 `run_trader.py:552`) · max_holding 10 |
|  | **extended** | stale 10일 ±3% · stale_high 10일 · max_holding 20 · 손절(채널 이탈 포함) 외 2일 전 청산 금지 (`min_holding_days=2`) |
|  | *none* (보충) | 보유 규칙 전부 해제(999) — 청산 정책 자체의 효과 격리, G2 비교와 같은 조건 |
| `sizing` | **nominal** (현행) | equity×25%, 상한 28%, 동시 5(=max_positions 8 − core 3) |
|  | **risk** | position = equity×0.7% / stop_pct(진입 ATR×2, 4~8% 클램프) → 8.75~17.5%, 상한 18%, 동시 7 |

- 지표는 **포지션(왕복) 단위** (`ResultAnalyzer.positions()` — BUY를 구분자로 부분 매도 합산, R = 순손익% / 진입 손절폭%).
  리뷰 §6 "이벤트 승률 지표 금지" 대응. 회전 = (매수+매도 명목)/평균자산 연환산, 수수료 드래그 = 총수수료/평균자산.
- WF = 자산곡선 3등분 구간수익률에서 baseline을 이긴 구간 수 (`BacktestGate._segment_returns` 재사용, 게이트와 동일 정의).
- **판정 규칙**: 기대값% > baseline AND PF > baseline AND WF ≥ 2/3 AND MDD 악화 ≤ 3pp — **모든 윈도우에서**.

## 3. 해석

1. **사이징 축이 지배한다.** `nominal→risk`는 sepa 단독 4/4 윈도우·혼합 4/4 윈도우에서 MDD를 절반 이하로 줄이고
   (예: -21.6→-5.9, -28.7→-11.2) 연회전과 수수료 드래그를 절반으로 만든다. 기대값·PF도 sepa 단독에선 개선(+0.38pp / +0.23,
   +0.18pp / +0.22). 리뷰 §2-3의 진단("25~28%×손절 4~8% = 건당 1.0~2.24% 위험, 3~4종목 집중")이 백테스트에서 그대로 재현됐다 —
   위험을 0.7%로 고정하면 7종목이 실제로 채워지고(101 vs 87건) 한 종목의 급락이 자산곡선을 흔들지 않는다.
2. **채널 청산은 보유 규칙과 상호작용한다.** 채널(10일 저가)은 최소 수 일이 지나야 진입가 위로 올라오는데, stale_high 3일·stale 5일이
   그 전에 발동해 채널 셀의 보유 중앙값이 ladder와 같은 3일이다 → 손익비만 커지고(2.2~2.6) 승률이 27~34%로 떨어져 기대값은
   그대로. `extended`(stale_high 10일)에서 손익비 2.5~3.1로 더 커지지만 거래 수가 30~40% 줄어 WF·PF가 미달. 보유 규칙을 전부
   떼야(`none`) G2 문서의 "+0.8R"급 기대값(+0.78·+0.85R)이 재현된다 — 즉 **리뷰 권고 1은 권고 2(회전 억제)를 '완화'가 아니라
   '해제'까지 밀어야 성립**하는데, 그 상태의 성과는 §2-4처럼 소수 종목의 장기 보유(60~134일, +113~221%)가 만든 것이다.
   같은 셀의 nominal 쌍둥이(-22~-33%)와 혼합 그리드 6m(SEPA PF 0.08)이 뒤집히는 것은 어떤 종목이 현금을 먼저 잡느냐에 결과가
   좌우된다는 뜻 → 표본 30~77건으로는 엣지와 베타(KODEX200 +132%)를 분리할 수 없다.
3. **extended는 ladder를 망친다.** 사다리는 TP1 이후 복합 MA5·익절후 stale로 "빨리 나가는" 구조인데, 손실 쪽만 10~20일까지 붙들게 되므로
   평균손 -5.7→-6.5%, 승률 41→31%(6m). 회전 억제는 청산 구조를 함께 바꾸지 않으면 역효과 — 리뷰가 "따로 검증하면 상쇄"라고 한 그 사례.
4. **혼합 그리드는 결론을 오염시킨다.** rsi2(폐지)가 7개 슬롯을 나눠 가지면 sepa 성분까지 흔들린다(ladder/current/risk 12m sepa 기대값
   +0.97→+0.56%). 실운용은 rsi2 0%이므로 판정은 sepa 단독 그리드를 정본으로 한다.
5. **모든 셀이 KODEX200에 크게 뒤진다** (-20~-165pp). 12개월 +132% 지수 구간에서 스윙 전략의 노출은 구조적으로 낮다 — 이 A/B는
   "구조 간 상대 비교"이지 엣지 증명이 아니다(리뷰 §0 "엣지 미입증"은 유지).

## 4. 승자 셀과 권고 파라미터

**승자 셀: `ladder/current/risk` (sepa 단독, 6m·12m 모두 게이트 통과).** 변경 대상은 **사이징뿐**이다.

| 항목 | 현행 | 권고 | 근거 |
|---|---|---|---|
| 사이징 방식 | 명목 `base_position_pct 25%` | **위험 기반**: `position_value = total_equity × 0.7% / stop_pct` (`risk.sizing_mode: risk`, `risk.risk_per_trade_pct: 0.7` 신규 키) | 6m·12m 통과, top3 제외 순손익 양수 유일 |
| `risk.max_position_pct` | 28% | **18%** | stop 4%일 때 17.5%가 상한에 닿음 |
| `risk.max_positions` (단기 전략) | 8 − core 3 = 5 | **7** | 코어 배분 0 상태, 7×0.7% = 4.9% < 일일 -5% 한도 → 손절 몰림 잠금(6/22형) 구조적 완화 |
| stop_pct 원천 | — | 진입 시 ATR×2, `ExitConfig.min_stop_pct 4 ~ max_stop_pct 8` 클램프 **그대로** | 백테스트와 동일 정의 |
| `ExitConfig` (first_exit 10%/10%, composite, stale 5d ±2%, post_exit_stale 5d, SEPA stale_high 3d, max_holding 10) | 유지 | **변경 없음** | channel·extended 모두 미달 |
| `REGIME_EXIT_PARAMS` | 유지 | **변경 없음** | 동일 |
| 채널 청산 (`harvest_shadow`) | shadow | **shadow 유지**, 승격 금지 | §2-4 아웃라이어 의존 |
| 최소 포지션 20만원·현금 5%·캘린더/변동성 타게팅 배율 | 유지 | 유지 — 배율은 risk_val 위에 곱하고 18% 상한 재적용 | 백테스트 미포함 오버레이 |

적용 경로: 실엔진에 위험 기반 사이징 모드가 없으므로 `src/risk`(포지션 사이징) 구현이 필요하며, 이 브랜치는 `src/` 무변경.
`BacktestGate`는 파라미터 단위 A/B라 `PARAM_MAP`에 `risk.sizing_mode → sizing` 매핑을 추가하면 같은 게이트로 재검증 가능.
실거래는 **canary(매수 재개 후 첫 30건)** 를 포지션 원장 R·KODEX200 초과 기준으로 판정(리뷰 §7 마지막 항).

## 5. 주의 (독자가 알아야 할 것)

- **EOD 근사**: 청산은 일봉 종가/시가/스탑가 체결. 분할 익절은 고가가 목표에 닿으면 **종가**에 체결(실엔진은 목표가 지정가) → ladder에 불리.
  채널·복합 청산도 종가 판정(실엔진은 틱 단위) → 장중 이탈 후 회복한 봉은 청산되지 않음. ladder의 ATR 손절폭은 백테스터 기존 동작대로
  **매일 재계산**(실엔진은 진입 시 고정) — 기존 게이트와의 일관성을 위해 그대로 둠.
- **생존 편향**: 유니버스가 2024~25 시총 상위 하드코딩(pykrx 시총 API는 KRX 인증 필요) → 상장폐지·급락 후 탈락 종목 부재. 채널/none의
  장기 보유 수익은 이 편향에 가장 민감하다.
- **체결 가정**: T+1 시가, 슬리피지 0, 갭 -3.5% 초과 시 미체결, 손절은 스탑가 체결(ladder는 갭 관통 미모델, channel은 시가 체결).
  같은 날 여러 신호는 점수순, 현금·`min_cash_reserve 5%` 소진 시 미체결 → 체결 순서가 결과를 좌우(§2-4 nominal/risk 쌍둥이 괴리).
- **점수 대리**: 백테스터 SEPA 점수는 수급·펀더·섹터를 중립 점수로 채운 근사. 배치 스캐너·크로스검증 게이트·팀 심의는 미포함.
- **기존 백테스터 규칙**: 손실 매도가 있는 날은 신규 신호 정지(`daily_loss_locked`) — 전 셀 공통.
- **표본**: 6m 윈도우는 2026-03~09 단일 국면(3·6월 급락, 4·5월 급등). WF 3구간은 41·80일 단위라 구간승 2/3의 검정력은 낮다.
  channel/none 셀은 n=34~77.
- **백테스터 기본값 ≠ 실엔진**: 게이트 기본 설정(복합 청산 off, stale_high 7일 <1%)으로 돌리면 혼합 6m이 -3.3%인데 실엔진 미러
  (`apply_holding_policy("current")` + composite + post_exit_stale)로는 -14.7% — 게이트가 실엔진보다 관대한 청산을 검증해 왔다는 뜻.
  후속: 게이트 `_build_config`에 미러 옵션을 켤지 별도 판단.
