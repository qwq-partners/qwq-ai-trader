# 비대칭 수확 전략 (Asymmetric Harvest) — 세부 상세 계획 v2

> v1: 2026-08-12 (독립 연구) → **v2: 2026-08-13** (딥 다이브 — 전략 전문가·리스크 감사

> 상태: **계획 확정 — T1 선행 게이트 백테스트 착수 대기**

## 0. 핵심 사상 (v1 유지)

한국 시장의 두꺼운 우측 꼬리(상한가 제도·개인 쏠림·테마 응집)를
**낮은 승률(30~40%)·손절 상수화(-4%)·무제한 러너·피라미딩**으로 수확한다.
근거: KR 전통 모멘텀 약함(장기반전), 단기 rank/sign 모멘텀+수급 duration factor
유효, KOSPI 모멘텀은 낙관 국면 한정, salient(복권성) 종목 제외 시 개선.

## 1. Phase 0 실측 결과 (2026-08-13) — 방향을 바꾼 데이터

최근 3주 매도 후속 복기 56건: **놓침 23% / 회피 54% / 타당 23%, 최대 놓침 +5.92%**.
매도 후 +8%(첫 피라미딩 기준) 이상 간 "조기 절단" 사례는 사실상 0건.

**함의**: 현행 청산의 이익 절단은 약하게만 지지 → 이 전략의 edge는 exit 교체가
아니라 **T1 진입 트리거(신고가 돌파 선별) 자체**에서 입증돼야 한다. 사용자 직관
("가장 중요한 건 종목 선택과 매수 타이밍")과 데이터가 합치.
단 Codex 유보: 56건·3주(단일 국면)로 exit 가설을 폐기할 수는 없음 —
Phase 0 지표는 6개월·200건까지 계속 누적 (기존 주간 잡이 자동 수행).

## 2. 종목 선택 — 3단 깔때기 (확정)

### 깔때기 1: 자격 (hard filter)
- 거래대금 20일 평균 ≥100억 (현행 스크리너 10억 → 임계 상향)
- 시총 1천억~5조 (상한 필터 신규 — 현행은 하한만)
- 주가 ≥3,000원 / 우선주·스팩·리츠 제외 (VCP 라인 혼입 실사례 있음)
- 상장 6개월 미만 제외 (120일 신고가 정의 불가)
- 복권 필터: 최근 20일 +60% 초과 기폭등 제외
- **유상증자·CB 공시 차단 (최우선 신규)**: `_apply_dart_catalyst` 커넥터를
  가점→차단으로 재활용. 돌파 직후 유증은 러너의 1순위 킬러
- 실적발표 D-3 이내 회피 (-4% 고정 손절에 실적 갭은 설계 파괴급)
- 회전율(대금÷시총) 하한 — 유통주식 데이터 부재의 실질 프록시
  (신용잔고·공매도 잔고는 데이터 소스 부재로 T1에서 생략 — 감사 확인)

### 깔때기 2: 셋업
- 120일 신고가 돌파 (신규 지표 — 현행 20일/52주만 있음)
- 베이스 4주+ / 최근 20일 고저폭 ≤25% / 돌파 전 5일 ATR 수축
- MA 정배열: 종가 > MA20 > MA60

### 깔때기 3: 랭킹 100점 (Codex 재조정 반영 — D0 마감 시 동결)

| 베이스·ATR 수축 | 10 | **15** | |

## 3. 매수 타이밍 (확정) — "돌파를 사는 게 아니라 소화된 돌파를 산다"

기존 `entry_mode="breakout"` 메커니즘 재사용 (VCP 라인 기구현 — 신규 스케줄러 불필요):
1. D0 (배치 감지): 120일 신고가 돌파 마감 + 대금 조건 → **관찰 등록만**
2. D1 체결 gate: 트리거 = `max(D0 고가, 20일 고점) × 1.003` **AND** 동시각 누적
   거래대금 ≥ 20일 중앙값 2배 (가격만의 돌파는 함정)
3. 시가 갭 **+3% 초과 시 당일 진입 금지** — 제거가 아니라 pending 유지 (눌리면 재진입)
4. 진입 시각 상한 **14:00** (돌파 마감 확인 불가 시간대 배제, sepa_late 선례)
5. 재확인 주기: 현행 3회/일 → **breakout_wait 대상만 5분 주기** 재검사
   (10:20 돌파를 13:50 고점에 잡는 현행 문제 해소 — execute_pending_signals 필터 인자)
6. 동시호가(15:20+) 진입 금지 (미체결·슬리피지가 4% 손절폭 잠식)

## 4. 청산·피라미딩 (v1 유지 + 구현 사실 반영)

- 손절 -4% 고정 (ATR×1.5 중 좁은 쪽) / 분할익절 없음 / 10일→(+30% 후) 20일 채널 트레일링
- 피라미딩 +8%/+16% 각 50% — **register_position 추가매수 경로가 평단 재계산 기구현 (신규 코드 0줄)**
- ⚠️ 구현 함정 (전략 전문가 실코드 확인):
  - `is_core=True` 필수 — 없으면 레짐 전환마다 REGIME 값이 -4% 고정 손절을 덮어씀.
    is_core는 청산 전용 플래그로 코어 예산 로직("core_holding" 문자열 판정)과 격리 확인됨
  - is_core 부수효과: 장중 급락 SL 캡 면제 (설계 "협상 없음"과 일치 — 의도된 선택으로 명시)
  - 숨은 breakeven 경로: +트레일링 활성 후 -2% 복귀 시 전량 청산 존재 → 채널 트레일링을
    breakeven과 독립 경로로 구현해 공백 해소
- 자금관리 산술 수정 (전문가 지적): 25%×4=100%는 피라미딩 여력과 모순 →
  **실질 동시 3개(75%) + 피라미딩 여력 25%**, 전략 전체 allocation 상한 별도 (초기 5~10%)

## 5. 병합 방식 결정 (전문가 합의)

**옵션 C (전략별 exit policy) 채택** — 근거: `_strategy_exit_params` 딕셔너리가 이미
전략별 분기 구조이고 core_holding이 "분할익절 OFF+느슨한 트레일링+무제한 보유"의
실동작 선례. 신규 코드는 채널 트레일링 ~20줄 + 월간 -6% 게이트 ~15줄뿐.
- A(shadow only) 기각: 월 4~8회 × 3개월 = N 15~25로 표본 수학 불성립
- B(전면 개편) 기각: 검증 전 비용 지불 — 순서 오류. 단 "기존 엔진이 정답 아닐 가능성"은
  2×2 백테스트의 exit축 A/B가 데이터로 판정 (§6)
- D(two-bucket) 기각: ExitManager 심볼당 1정책 구조 + 거래세 이중 부담

**리스크 감사 필수 요건** (승격 전):
- `_consecutive_losses` 카운터 전략별 분리 (공용이면 타 전략 손실이 이 전략 사이징을
  왜곡 — 러너 직전 반토막 = 기대값 붕괴). execution shadow 진입 전 필수
- strategy_allocation 신규 키 (5~10% 시작) + **별도 팩터 버킷** (trend 합산 초과 위험)
- 섹터당 2종목 제한 예외 설계 / 월간 -6% 서킷 신설 (position_ledger 월 합산 재사용)
- 진화 시스템 잠금: "승률<40%→진입기준+5" 내장 규칙이 저승률 설계 전략을 질식시킴
  → evolved_overrides `_meta`에 manual_review_locked 등록

## 6.5 G1 실행 결과 (2026-08-13 — scripts/backtest_t1_gate.py)

2019~2026.8, 유니버스 400 (시총 1천억~5조), 완화 필터 (베이스·ATR 수축 제거,
대금 30억+ — 원안 필터는 신호 20건으로 과협착 판명). 신호 1,761건. 비용 0.6% 차감.

| 정책 (전부 실행 가능) | n | 기대값/거래 | 승률 | 상위10% 기여 |
|---|---:|---:|---:|---:|
| A. D0 종가 무조건 진입 | 1,761 | +0.02R | 15.6% | 4481% |
| **B. D1~D3 트리거+대금 확인 진입** | **891 (체결률 51%)** | **+0.375R** | 19.0% | 380% |
| C. D1 시가 진입 (과갭만 회피) | 1,326 (75%) | +0.21R | 17.4% | 585% |

- **판정: 진입 정책은 B 채택.** paired(B−A, 동일 신호) 기준으론 -0.153R로 형식상
  G1 기준(+0.10R) 미달 — B는 진입가 프리미엄을 지불한다. 그러나 B의 트리거+대금
  게이트는 **신호 필터**로서 A 전체(+0.02R)를 +0.375R 부분집합으로 정제한다.
  실행 가능 정책 비교에서 B가 명확한 승자.
- 극단 skew 구조는 설계대로 실증: 승률 15~21%에 median -1.15R (손절 다수),
  수익은 상위 꼬리가 전담. "승률 낮아도 수익 최대화" 골격 확인.
- 주의: 전 기간 in-sample. paired 연도별 7/8 음수 (2024만 +0.80) — B의 상대
  우위는 홀드아웃·walk-forward(G2)에서 재검증 필수. 생존편향 미보정 (canary 5% 근거).

### 6.7.3 드라이버 봉 커서·장중 봉 배제·유니버스 이탈 보정 (2026-09-03)

**문제** (적대 검증 확정 P1): `_run`이 종목당 **최신 봉 1개**만 판정했다. FDR 장애로
08:40 실행이 하루 빠지거나, 봇이 다운되거나, 보유 종목이 시총 상위 400 유니버스에서
빠지면(+30% 러너가 5조 상한을 넘는 바로 그 경우) 그 봉의 손절·체결·D0가 **영구 누락**됐다.
백테스트 `simulate_exit`는 전 봉을 순회하므로 "shadow == backtest 정의"(Codex 조건 4)가
깨진 상태였다. 장중 재시도 시 네이버 실시간 행이 완성봉으로 섞이는 문제도 같이 있었다.

**수정**:
- `_process(bt, data, ok_dates, universe, pending, positions, cursor)` 순수 함수 분리 —
  `cursor.json`의 `last_bar` 이후 봉을 **전부 순서대로** 판정 (pending → positions → D0 순;
  체결된 봉 이후의 봉도 같은 실행에서 청산 판정). 커서가 없는 첫 실행은 구 동작(최신 봉만)
  으로 시작해 승급된 stop을 과거 봉에 재적용하지 않는다.
- `_drop_incomplete_bar`: 당일(진행 중) 봉 제거. 보유·대기 종목은 유니버스 이탈 시에도 로드.
- 10봉 내 D0 재신호 억제 (`cursor.last_d0`, 백테스트 `find_d0_signals` 동일).
- 원장 레코드에 `exit_date` 추가. 테스트 `tests/test_harvest_driver.py` 6건 (놓친 봉 손절 /
  건너뛴 봉 체결 후 전진 / 3세션 만료 / 커서 없는 첫 실행 / D0·재신호 억제·유니버스 / 당일 봉 제거).

**한계**: 커서 도입 전 표본(원장 2건, 보유 000370)은 구 정의로 판정된 것 — G4 심사 시 주석 처리.
